G1 前哨量化实测与判据修订

真实 Sana 1.6B 上的 4 路 NVFP4 对照 · 误差归因 · G1 判据修订 · E5b 可训性定案

2026-10-03实测（非推演）靶子：Sana 1.6B · 15 例信号级 + 12 张端到端含一条 G1 判据修订 + G1 初步通过
七条结论

① 误差几乎全部来自「激活」量化——权重降到 4-bit 只花 7.74%；激活也降到 4-bit，误差暴涨到 29.72%（3.84×）。

② 设计档 W4A8（FP4 权重 + FP8 激活）落在两者之间——比 W4A4 好 2.98×，离 W4A16 只差 1.29×。设计选择被实测支持。

③ ⚠️ 逐像素 PSNR/SSIM 测的是「轨迹稳定性」，不是画质 → G1 判据必须换成分布级指标（§5）。

④ ⚠️ PTQ 是「模拟量化」，权重仍以 bf16 驻留 → 本轮显存数字（全 5.29 GB）不能用来论证 NVFP4 的显存收益（§6.4）。

⑤ 🔍 ModelOpt 的 NVFP4 fake-quant 忽略配置里的 block_sizes → 官方 "block 32" 不会带来额外损失（§6.1）。

⑥ ✅ E5b 可训性定案——ModelOpt 训练路径的 blocker 是 FP8SDPA 无 backward（非环境问题，已 patch）；且 8GB 卡全参 QAT 不可行（优化器状态 12.8GB）→ 必须 adapter 式 QAD（§8）。

⑦ ✅ G1 快速判据初步通过——W4A8 的分布级偏移仅为自然离散度的 53.5%（W4A16 52.7% / W4A4 88.9%，三臂全 < 1）（§8.4）。

4.1 误差随 timestep 呈「倒 U 形」

中间步（定结构的那几步）最脆弱。早期步的微小偏差会被后续采样放大 —— 这解释了为什么端到端会出现"构图漂移"而不是"画质下降"。

  • 代价：校准耗时 5.5 s → 260.7 s（47×）

→ 这条可以省掉。官方 NVFP4_FOUR_OVER_SIX_CFG 的价值在训练（QAD）阶段，不在 PTQ 校准阶段。

05⚠️ G1 判据修订（本文件的核心动作）

5.1 问题

原 G1 判据隐含地依赖「固定种子 → 逐像素对照」。E5 实测证明这条路会给出错误判决：

20 步扩散采样中，早期步的轻微扰动会被放大成「另一个同样合理的样本」

逐像素指标衡量的是「同一轨迹走不走得稳」，不是「画得好不好」。W4A4 的 9.67 dB 就是这么来的 —— 它被判"崩了"，但实际画质正常。如果直接拿逐像素指标当 G1 的门，会把一个可用的配置误判为不可用。

5.2 修订后的判据

原判据（作废）新判据（v1.0）
主判据FP4 vs BF16 逐像素差距 < 2%分布级指标：FID（或同等的多样本质量评估）上 FP4 与 BF16 差距 < 2%，且 QAT 优于 PTQ
辅助判据—① 逐像素 PSNR/SSIM —— 仅作「轨迹稳定性」参考，不作门；② 信号级 noise_pred 相对误差与余弦 —— 作趋势指示
样本量单张≥ 50 张（同 prompt 集，多 seed）—— 单张无统计意义

5.3 为什么这条修订重要

它把 G1 从「会不会崩」变成了「分布偏不偏」。前者对量化过敏（任何微小数值差都会触发），后者才是生成模型的真实质量轴。

一条可复用的方法论规范（已写进主文档 §9.2 的 G1 行）

评估生成模型时，逐像素指标只用于「同轨迹复现性」检查，不可用于「质量」判决。

06附带的工程知识（边界条件）

6.1 ModelOpt 的 NVFP4 fake-quant 忽略 block_sizes 配置

实测：把 W4A8_NVFP4_FP8_CFG 的权重 block 从 32 改成 16、再改成 64，输出完全相同（8376.7334，差异 0.000000%）。

→ ModelOpt 内部用固定块长，配置里的 block_sizes 只写进 quantizer 属性、不影响数值。
→ 推论：官方 W4A8_NVFP4_FP8_CFG 里那个 "block 32" 不会带来额外精度损失，可放心用；不需要自己改回 16。

但手写 NVFP4 量化器时 block 是真实生效的

合成权重上 block 16 优于 32（10.07% vs 11.39%），真实权重上亦然（低 9–25%）。区别在于：ModelOpt 的 fake-quant 路径不用这个参数，手写路径用。两者不要混为一谈。

另：真实权重上 proj_out 层误差最高（12.56%）且对 block 最敏感（1.25×）—— 这解释了 ModelOpt 默认配置为何单独关掉 *proj_out.* 的量化。

6.2 FP8 模拟量化确实生效

ModelOpt 会打印 "FP8 not available" 警告（CUDA 加速扩展未编译），但实际走 _fp8_eager 纯 PyTorch 回退路径，量化真实发生（两种配置输出哈希不同、误差不同，已实测）。

08E5b：可训性定案与 G1 实测结论（v1.1 新增）

§2–§6 全是 PTQ（推理）结论。G1 的真问是 QAD/QAT（训练）：量化后还能不能训、训了掉不掉点。§8 是这一问的实测回答。

8.1 blocker：ModelOpt 量化后的模型只能推理、不能训

对 Sana 做 mtq.quantize 之后，第一步 backward 就崩：

NotImplementedError: You must implement either the backward or vjp method
for your custom autograd.Function to use it with backward mode AD.

六种配方全灭（W4A4 / W4A8 / W4A16 / FP8 / 4-6 / 默认）；1024² 与 512²、开/关梯度检查点，全部同样报错。

⚠️ 根因我第一版说错过，必须记下

我起初判定「本机缺 MSVC」——错。vswhere 实测本机有 4 处 VS 安装（D:\vc2022 / ...\2022\BuildTools / D:\vsc / D:\vs），cl.exe 在 ...\BuildTools\VC\Tools\MSVC\14.44.35207\bin\Hostx64\x64\，只是不在 PATH。正确表述是环境/路径问题，不是能力缺失。

✅ 真根因（抓到真实调用栈后定案）：ModelOpt 的 diffusers 插件把 F.scaled_dot_product_attention 替换为内部走 FP8SDPA.apply(...)，而 FP8SDPA（modelopt/torch/quantization/plugins/diffusion/diffusers.py:214）只实现 forward、没有 backward。⇒ 与量化器开关、与 CUDA 扩展均无关（这解释了为什么「把量化器全部 disable 也照样断」）。

修复（tools/e5b_patch_probe.py）：把插件的 FP8SDPA patch 回原版 SDPA（前向严格等价）。补丁后 W4A8 / W4A4 全参 backward 通过（loss 1.667 / 0.889，峰值 3.46 GB）。

8.2 容量结论：8 GB 卡必须 adapter 式 QAD

路线可训参数优化器状态可行？
全参 QAT1.604e9AdamW 2×1.604e9×4B ≈ 12.8 GB不可行 8 GB 绝无可能
adapter 式 QAD5.99 M（0.37%）极小可行 峰值 3.41 GB、0.57–0.75 s/step
✅ 不是妥协，是把架构决策提前实证了

之前「能跑通」的全是 SGD 无动量（零状态）——一旦上 AdamW，全参路线立刻不可行。

⇒ 冻结主干 + 只训低秩旁路，与设计稿的 Δ-Pack / 能力包结构完全同构。

8.3 独立路径：自研可微 NVFP4 fake-quant

训练期只需模拟量化，不需要 packed / swizzled 布局 → 手写「E2M1 + block16 + E4M3 scale」+ STE 直通梯度（tools/e5b_qad.py）：

def quant_fp4_ste(x, blk=16):
    # E2M1（16 级）伪量化 + block16 缩放
    scale = (amax / 6.0).to(torch.float8_e4m3fn).to(x.dtype).clamp(min=1e-12)
    q = (xb / scale).round().clamp(-6.0, 6.0)
    xq = (q * scale).reshape(shape)
    return x + (xq - x).detach()      # ← STE：前向量化、反向直通

替换 Sana 的 165 个 nn.Linear，proj_out 按官方默认保留不量化。完全绕开 ModelOpt 训练路径。

  • 前向误差探测（512²，out/e5b/qad_probe.json）：t=999 → 4.56% · t=599 → 31.31%（峰值） · t=0 → 5.04%，cos 全 > 0.95 ⇒ 独立复现了 E5 的「倒 U 形」。
  • 对照组（bf16 全量微调可跑）：1024² = 12.7 s/step / 峰值 6.84 GB；开梯度检查点 = 5.66 s/step / 6.3 GB（更快更省）。

8.4 ⭐ G1 快速判据：初步通过（W4A8）

方法（§5 修订判据的可执行简化版，tools/e5b_g1_fast.py，零新生成、约 1 分钟）：

  • d_ref = bf16 同 prompt 不同 seed 的自然离散度（282 对）= 14.576；
  • d_quant = 同 prompt 同 seed 下量化臂 vs bf16 的特征距离；
  • 判据：d_quant / d_ref ≪ 1 ⇒ 量化偏移小于「换一个 seed」，属同分布内抖动，未改变分布。
臂d_quantd_quant / d_refPSNR（辅助）
W4A8（设计档）7.7990.53516.28
W4A167.6800.52716.87
W4A4（官方默认）12.9600.88913.90

判读：

  • 三臂全部 < 1；
  • W4A8 仅 53.5%，W4A4 达 88.9% ⇒ 激活降到 FP8 几乎不额外损失，实测支持「FP4 权重 + FP8 激活」的设计档；
  • 排序（W4A16 < W4A8 < W4A4）与信号级（7.74% < 9.98% < 29.72%）、端到端 PSNR 三条独立证据链一致。

8.5 G1 状态与遗留

  • 初步通过 G1（W4A8） —— 分布级偏移仅为自然离散度的 53.5%，远小于「换 seed」。
  • 局限 d_quant 每 prompt 仅 3 对，统计薄。正式过门仍建议补 ≥ 50 张/臂的 FID（§5 修订判据）。
  • 已定案 可训性 —— 训练路径（ModelOpt patch 或 自研 STE）、容量边界（必须 adapter 式）都已清楚。
