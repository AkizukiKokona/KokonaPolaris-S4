# 能力接入操作手册 · 怎么给这个模型加一项新本事

> 版本 v1.0 · 2026-10-03 · **操作手册（照着做）**，不是设计文档  
> 目标：**任何人拿着这一份，都能自己把一项新能力接上去。**  
> 本文只描述「接口怎么用 / 数据怎么备 / 训练怎么跑 / 验收怎么过」。  
> **内容由使用者提供。** 这份流程对任何能力都成立，因为这套架构在设计上就是**域无关**的——加画风、加角色、加任何域，走的是同一条流水线。

---

## 0. 三十秒版

**这个模型的能力不是"训进模型里"的，而是"做成外挂包"的。**

所以「加一项新能力」= 走一条流水线 → 产出一个小文件 → 加载它。  
**模型本体一行不动。**

好处：① 加能力不会毁掉模型 ② 不想要了直接卸载 ③ 包很小（1–27MB）④ 甚至能跨模型版本用。

---

## 1. 【第一步】先判断你要加的东西属于哪一档

这一档决定"是花几小时还是几星期"，**不要靠感觉判断，用探针测**。

### 探针（成本：本机 1–2 小时）

1. 收集 **50–200 张目标样本**
2. 跑一次**超短适配**（LoRA rank 8，100 步）
3. 看出图

| 结果            | 结论        | 去哪一档                              |
| ------------- | --------- | --------------------------------- |
| 已经"像"了，只是不够稳  | 模型**见过**  | 再问：是我们主动过滤掉的吗？是 → **①**；否 → **②** |
| 完全出不来，或只剩一点影子 | 模型**没见过** | **③ 跨域型**                         |

| 档         | 什么情况                        | 包的类型            | 要多久                    | 在哪做 |
| --------- | --------------------------- | --------------- | ---------------------- | --- |
| **① 恢复型** | 模型学过，但被**我们显式擦除并记账**        | 一个算子 `E⁻¹`      | **几分钟**                | 本机  |
| **② 长尾型** | 模型见过，但数据太稀（姿势 / 构图 / 组合没覆盖） | Δ-Pack（27MB 级）  | **几小时**                | 本机  |
| **③ 跨域型** | 模型从未见过                      | ∥-Pack（100M–1B） | **几天 + 云**             | 需租云 |
| **④ 载体型** | 换"具体对象"：某角色、某画风             | 数据对象（1–5MB）     | 一次性训 Fitter，之后**秒级切换** | 本机  |

> 经验：**大多数人以为自己需要 ③，实际是 ①② 的组合。**

## 2. 四条流水线，逐步写清

### 流水线 A｜恢复型（最快，几分钟）

**前提（重要）**：模型预训练时必须做过两件事——  
① 主动做数据过滤（而不是继承别人已对齐的底座）  
② 把"擦掉了什么"**记成账本**（`erasure_ledger`）

> ⚠️ 这两件事**只有预训练时做才有效，事后补不回来**。这是全流程唯一不可逆的决策点。

**步骤**

1. 读账本，拿到 `{作用层 L, 有效秩 k, 子空间基 uᵢ/vᵢ, 逐层强度 αᵢ, 保留集边界}`
2. 构造反向算子：`E⁻¹ = I − Σ αᵢ uᵢ vᵢᵀ`（作用在层集合 L 上）
3. 施加到权重，导出包：`{ΔW, g=1, 元数据}`
4. 出图对比

**工具**：numpy / torch，一次 SVD。**不需要 GPU 训练。**  
**验收**

- ⭐ **往返测试**：`E⁻¹∘E` 之后输出分布回到基线（KL 低于阈值）
- 目标概念命中率上升，**非目标概念不漂移** ← 最容易翻车的地方  
  **坑**：作用层要选在"语义已经分化"的深度之后（经验值：网络深度 **~2/3** 处），否则会误伤相邻概念。

---

### 流水线 B｜长尾型（本机几小时）

**你要准备的**：**200–2000 张**同类样本（来源见 §3）。

**步骤**

1. **打标**：用视觉语言模型自动出 caption（Qwen2.5-VL / JoyCaption / Florence-2 任选），人工只做抽查。
2. **训练适配器**
   - 只训低秩旁路，**冻结主干** ← 8GB 卡唯一可行解
   - rank **16–64**；用 **rsLoRA** 缩放 `α/√r`
   - 预算优先给 **`W_o`（注意力输出投影）**，其次 `W_q/W_k/W_v`
   - ⭐ **把 ΔW 限制在 `W₀` 自己的 SVD 子空间里** ← 这是"不打架"的关键
3. **导出**：`{ΔW, g, 元数据}` → 27MB 级单文件

**命令形态（示意）**

```bash
"$KP_PY" train_pack.py \
    --data ./my_data --rank 32 --targets w_o,w_q,w_k,w_v \
    --subspace-svd ./base_w_svd --steps 2000 \
    --out ./packs/my_pack.safetensors
```

**验收**

- ⭐ **谱检查**：把 `ΔW` 与 `W₀` 的全部奇异向量做对；**出现 cos < 0.1 的高排名分量 = 不合格**（这就是"打架"的物理定义）
- 前后 **FID 对比（≥50 张）**
- **门控置 0 时必须与原模型逐位相同（bit-exact）**

**坑**：LoRA 的瓶颈不是"秩低"，是"**有效秩低**"。用**块对角分解**把有效秩从 `r` 提到 `n_l×r`，参数量不变。

---

### 流水线 C｜跨域型（最贵，要云）

适用：模型真的没见过这个世界（全新的视觉域）。

**步骤**

1. **先试着退化成 B**（很多时候够了，先做 ② 再说）
2. 准备数据：**十万张级**。不要爬图——**让渲染器生产**（见 §3）
3. 训一个旁路分支（100M–1B），门控注入主干；或**从教师模型蒸馏**（拿一个在这个域上本来就强的模型当老师）
4. 导出为 ∥-Pack

**成本参照**：**天级 + 租云**。本项目自己的可行性参照：1.16B 模型 + 3700 万图 ≈ **$1.9k**（Micro-Budget 配方：256→512 渐进分辨率 + 75% patch masking）。  
**验收**：同 B，另加"关掉包时与原模型 bit-exact"。

---

### 流水线 D｜载体型（换角色 / 换画风，秒级）

**这是"以后想换个角色、换个画风"的正解。**

**一次性投入**：训一个 **Fitter**（作用：把参考图 → 结构化表示）。

**之后每次换，只要三步**

1. 给 **N 张参考图**
   - 换**角色**：正视图 + 背视图就够
   - 换**画风**：N 张同风格图
2. Fitter **前向一次**（**秒级**，峰值显存 ~1.2GB）
3. 得到"卡"：`{2.5D 语义分层 + 身份 token}`，1–5MB → 加载即用

**要点**

- **二次元的正确表征是 2.5D 分层，不是 3D 网格**
- 身份 token 走 **cross-attention，不要拼进主序列**（拼接会让注意力成本 ×4）
- 卡**不依赖模型坐标系** → 换模型版本还能用

**验收**：身份一致度接近 LoRA 基线；**换角色 < 1 秒**；门控关掉 bit-exact。

## 3. 【你要去找的东西】清单

### ① 数据

**自建（推荐）**：3D 资产 + 渲染器。一个资产线出**四个正交旋钮**：  
**视角 / 着色器 / 分层可见性 / 姿态** → 配对样本是**组合式扩增**，不是线性扩增。

- 引擎：Blender / UE5
- 现成可复用管线：**SynBody**（分层参数化人体，1.2M 图 / 10k 模型 / 1,187 动作）、**UnrealPose**（UE5，100 万帧，**管线开源**）

**二次元角色现成集**

- **NOVA-Human**：10.2k 个 VRM 角色 / 16 随机视角 + 4 正交视角 / 163.2k 图
- **See-through 数据引擎**：自 9,102 个 Live2D 模型自举 **19 类语义层**标注，代码开源

**自收集**：自己截图整理。注意许可。

## 4. 硬件账：这台机器能干什么、不能干什么

| 任务              | 8GB / 20SM 能跑吗                 |
| --------------- | ------------------------------ |
| 推理出图 1024²      | ✅ 峰值约 5GB                      |
| 训练 Δ-Pack（LoRA） | ✅ 几小时                          |
| 训练 Fitter       | ✅                              |
| 训练 ∥-Pack（跨域）   | ❌ 要云                           |
| **全参数训练（任何规模）** | ❌ **不可能**——光优化器状态就要 **12.8GB** |
| 从零预训练           | ❌ 要云                           |

> 一句话：**这是验证机，不是训练机。**  
> 但它**正好**能验证"外挂包"这条路——因为外挂包只需训适配器，不需要全参。

## 5. 每个包出厂前的验收清单（照单打勾）

- [ ] 门控全关 → 输出与原模型 **bit-exact**
- [ ] **谱检查**通过（ΔW 里没有与 `W₀` 正交的高排名分量）
- [ ] 目标指标提升（命中率 / 一致度 / FID）
- [ ] **非目标能力不退化** ← 最常被忽略，也最容易毁掉模型
- [ ] 包体积 / 显存峰值 / 加载耗时 记录在案
- [ ] 元数据齐全（数据来源 / 训练配置 / 许可 / **它做了什么**）

## 6. 三条硬边界（工程上必须写清的）

1. **内容由使用者提供。** 模型本体是干净、可分发的底座；包由使用者自己负责。这三层分离（模型层 / 包层 / 部署层）是**设计条款**，不是免责声明。
2. **许可要分清"自用"和"分发"。** 研究用数据训出来的东西自己用没问题；**要分发就得换线**。
3. **账本必须写进 model card。** 不记录 = 退化成黑盒 = 上面流水线 A 整条作废。

---

## 7. 最短路径建议

如果你只想**尽快拿到一个能用的新能力**：

1. 跑 §1 的**探针**（1–2 小时）判断档位
2. 落在 **①②** → 直接做**流水线 B**（本机，几小时）
3. 落在 **④** → 训**一次** Fitter，之后所有角色 / 画风都是**秒级**
4. 只有落在 **③** 才需要考虑**云和几周时间**

> 换句话说：**先花两小时搞清楚自己在哪一档，比直接开练三天更省时间。**
