01命名：KokonaPolaris（心夏北极星）

1.1 已定下的部分

项取值
家族名KokonaPolaris
中文名心夏北极星
缩写KP
尺寸档KP-S（0.6B，主力）／KP-M（1.5B，质量档）／KP-L（3B，仅作 teacher，不发布）
名字里藏了一层双关——这也是它比随机起名更合适的原因

Polaris = 北极星，而本架构里「对偶 / 极性」结构反复出现：

① 语义 · 细节 双通道 latent（8ch + 32ch）　② 正 · 背 对偶视图（核心训练方式）　③ 擦除 · 恢复 对偶算子（E / E⁻¹）

一个名字同时说了「指引」和「对偶」两件事。

1.2 后缀：已定为 -S4（附四个候选的取舍记录）

✅ 结论（2026-10-02，用户拍板）：正式名定为 KokonaPolaris-S4

世代标签（如 -G1）等原型成型后再加。理由：两个字符装下两个最硬的差异点（S = Single-stream 单流 / 4 = 原生 FP4）；有型号感、好念、易做版本化。

后缀唯一的作用是：让人只看名字就知道它和 SDXL / Flux 不一样在哪。下面四个候选的取舍保留下来，作为决策记录——

候选字母含义第一眼传达好处代价
-S4 Single-stream + native FP4 「单流 + 原生 4-bit」 两个字符装下两个最硬的差异点；型号感强、好念、易版本化（可延伸 KP-S4-S / S4-M） 需要解释一次才懂；可能被误读成「第 4 代」
-DiT Diffusion Transformer 「这是个扩散 Transformer」 零歧义；写论文 / 找别人看时最不容易被误解 不含增量信息（谁都知道是 DiT），真正的差异点一个都没体现
-Duo 对偶（Dual） 「这架构靠对偶结构吃饭」 与 Polaris 的极性双关；一次概括三组对偶；品牌感最强 技术指向弱，不看文档猜不出是什么；易被当成「双卡 / 双模型」
-Mod Modular 「可插拔、能一直挂包」 直接点出全场最独特的差异点（能力总线）；对使用者最直观 读起来像「模块化产品」而不是模型；没体现低显存 / 量化
我的建议

想让名字带信息（推荐）→ KokonaPolaris-S4　｜　想让人一眼不误解、偏学术正统 → KokonaPolaris-DiT　｜　想让名字有品牌辨识度 → KokonaPolaris-Duo

也可以两段都用：正式名 KokonaPolaris-S4；首次出现时写全 —— 「KokonaPolaris-S4（单流 · 原生 FP4 的扩散 Transformer）」。信息量与清晰度都不丢。

A1 有一个反直觉之处

它失效的代价并不大（退回 FP8 方案依然成立），但它优先级仍是第一——因为它一旦为假，前面所有显存测算都要重算。

A2 则相反：它成立与否没人会立刻看出来，但它一旦为假，「让 LoRA 只做长尾」这条主线就直接消失。

为什么 G1 的判据定在 2%（而不是 0.5%）

FLUX 上的实测是——FP4 PTQ 会掉点（ImageReward 1.118 → 1.096，约 2%），FP4 QAT 不掉反微升（1.119）。

所以 2% 正好是「能不能只用 PTQ」的分界线：差距在 2% 以内说明 PTQ 就够，超过 2% 才必须走 QAD。这正是要判断的事，判据就定在这条线上。

05开工顺序（我的建议）

两条腿走路，不开三线

主线　G0 → G1（NVFP4 QAD）　← 几天出结论，唯一能推翻地基

副线　P2′（T0 排版链路）　← 零训练、零依赖，立刻可见产出

  1. G1 必须先做——它是唯一「如果塌了、前面所有显存测算都要重算」的东西。先验地基，再盖楼。
  2. P2′ 必须并行——它不与任何风险绑定：不需要 NVFP4、不需要新主干、甚至不需要训练。哪怕主线全塌，它产出的（会排文本框的 Layout Planner + 字形合成数据管线）依然有用。这是对冲。
  3. 现在不必碰 P2.6（角色卡）——它虽然也独立，但本质属于 G5 的范围。等 G1 有结论、确定要继续时再开，不会损失什么。
如果你手上暂时没有 Blackwell 卡

主线就换成 P2′ + 文档，先不碰 G0 / G1——硬件相关的结论模拟不出来。

06拿去给别人看时，对方最可能挑这六个问题

这一节是为「我想拿去问别人」写的。把这六个问题连同答案一起给他，能省掉一轮无效讨论。

Q1「为什么不直接微调 Z-Image / Sana / Flux，偏要从零？」

因为三处改动每一处都让已有权重作废：换 VAE（latent 空间没有对应关系）、换文本塔（条件分布变了）、换主干（UNet → 单流 DiT，连拓扑都不同）。所以「站在别人肩上」在结构上不成立。成本侧有反证：Micro-budget 证明从零不是千万级（$1,890 / 1.16B）。

Q2「NVFP4 是不是伪需求？FP8 不够吗？」

这是最该被质疑的一点，也是我自己最不确定的一点。诚实地说：如果主要场景是 LoRA 训练，激活显存会淹没权重差异——1.5B 的 FP4 权重只占 0.84GB，激活才是大头。所以 NVFP4 的收益在推理上比在训练上明显。G1 存在的意义正是把这个分歧量化。

Q3「32× 压缩一定丢细节吧？」

会丢，这是信息论问题，不是训练问题。所以：细节由 32ch 细节通道兜底；文字走独立低压缩 ROI 分支（40px 汉字在 32× 下只占 1.25 个 latent 格，靠主干渲染在信息论上不可能）。

Q4「通道分离真能训出来吗？」

不知道，这是全案最大的未验证设计假设（A2 / G2）。唯一能保证的是：不加显式监督，它一定训不出来——主干会图省事把两个通道都塞满。

Q5「角色卡有先例吗？」

有相邻先例（InstantCharacter 单图驱动外置适配器、See-through 的 2.5D 分层表示），但「正 / 反两视图 → 1–5MB 分层角色卡 → 秒级换角色」这条完整路径没有直接先例。

Q6「8GB 卡训 1024² 角色 LoRA 是不是噱头？」

目标是 4–5GB 峰值，依据是 token 数：32× 压缩后 1024² 只有 1024 token，激活与注意力成本按此量级估算。这条同样依赖 G1 / G2 成立。
