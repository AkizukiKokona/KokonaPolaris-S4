# 8GB 单卡方案（无云机预算）

> 起因：用户只有 **8GB 显存的卡**、**没有云机预算**，要求**显存占用必须限在 8GB 内**。
> ⛔ 本文档的数字全部是**本机实测**（RTX 5070 Laptop / 8151 MiB 总量 / 7657 MiB 可用 /
> **24 核 / 总内存 33.7GB 但常态只剩 ~10GB**）。换机必须重测。

---

## 0. 结论先行

| 问题 | 答案 |
|------|------|
| 8GB 能不能训出设计稿要的 ~300M VAE？ | ✅ **能** —— `base=128` = **279.7M**，512² 端到端已跑通 |
| 需要云机吗？ | ❌ **VAE 这条线不需要**。G6 主干预训练仍需租云（见 §5） |
| 最大的显存杠杆是什么？ | ⭐ **8-bit AdamW**（优化器状态 4268 MiB → ~2.2GB 省下） |
| 最大的坑是什么？ | ⭐ **评估预算要按「训练态 reserved」算，不是按空闲显存** |

---

## 1. 为什么 8-bit AdamW 是最大杠杆

`AdamW` 的两个矩（momentum + variance）是 **fp32** ⇒ 每参数 **16 bytes**
（权重 4 + 梯度 4 + 两矩 8）。

`base=128`（279.7M）光**优化器状态**就 **4268 MiB** —— 独吞 8GB 卡一半以上。
`bitsandbytes` 的 `AdamW8bit` 把两矩降到 **2 bytes/param** ⇒ 省约 **2.2 GB**。

### 实测（峰值 = `torch.cuda.max_memory_allocated`）

| 优化器 | 256²bs4 | 256²bs8 | 512²bs2 | 512²bs4 |
|--------|---------|---------|---------|---------|
| `adamw`（fp32） | 5928M ✅ | **OOM** | **OOM** | **OOM** |
| **`adamw8bit`** | 4337M ✅ | 5994M ✅ | 5993M ✅ | **OOM** |
| `sgd`（momentum） | 4860M ✅ | 6517M ✅ | 6518M ✅ | **OOM** |

⇒ **512² 从「不可能」变成「可能」**。

⚠️ 代价与判据：8-bit 矩会损失一些优化精度。
**判据是「能不能训动」，不是「训多优雅」** —— 精度不够可以用更多 epoch 补，OOM 是硬墙。
（`--opt` 默认已改为 `adamw8bit`。）

## 2. ⭐ 评估块大小：连踩三次 OOM 才做对

**这是本方案里唯一真正难的地方**，值得完整记录。

### 三次失败

| 尝试 | 现象 | 根因 |
|------|------|------|
| ① 一次性前向 | 256² 申请 **7.81 GiB** ⇒ OOM | 没分批 |
| ② 硬编码 `batch=64` | 512²×64 ⇒ OOM，**连 1 张都进不去循环** | 块大小是**常数**，而激活 ∝ 分辨率² |
| ③ 块随分辨率缩放 | 仍 OOM，报「已分配 **7.08 GiB**」 | ⭐ **预算按「空闲显存」算，但评估发生在训练态** |

### 正确的口径

```
评估可用预算 = 卡总量 − 训练态 torch.cuda.memory_reserved()
```

**实测**：base=128 / 512² / bs2 / 8bit 训练后 `reserved = 6406 MiB`，
只剩 **~1.2 GB** 给评估 —— 而按「空闲 7657 MiB」去算会以为有 7.6GB。

> ⭐ 这条对**任何「训练中穿插评估」的场景**都成立，不限于本项目。

### 每张图的显存增量（**实测拟合，不能估**）

| 分辨率 | 每张增量 |
|--------|---------|
| 512² | **391.5 MiB** |
| 256² | **98.25 MiB**（≈ 1/4，符合 ∝ 分辨率²） |

由此得到 `_auto_eval_batch(size)`：

| 分辨率 | 块大小 |
|--------|-------|
| 128² | 64 |
| 256² | 17 |
| 512² | 4 |
| 768² | 1 |
| 1024² | 1 |

### ⚠️ 教训

第一版用「张量数估算」算每张开销，得到 **1e−7 MiB** ⇒ 恒返回上限 64 ⇒ 512² 又 OOM。
**显存公式必须实测拟合，不能靠估算。**

### 兜底降级

块大小是公式算的，公式可能对某组合估高 ⇒ `evaluate()` 捕获 OOM 后
**逐级减半重试**（最多 3 次；降到 1 张仍不行则跳过该块，并在输出里**如实报告评估集缩小**）。

> ⚠️ 长跑绝不能崩在评估上 —— 前车之鉴：120k 步训练崩在无关的地方，
> 而当时**只在结束时存盘** ⇒ 56 分钟全丢。

## 3. 已验证的可运行配置

### base=128（279.7M）+ 512² ← 设计稿目标容量

```bash
source ./env.sh
"$KP_PY" -u -m kp.train.vae_pretrain \
  --shards out/data/curated_danbooru/_shards \
  --base 128 --size 512 --batch 2 \
  --steps 20000 --workers 6 \
  --opt adamw8bit --device cuda \
  --n-eval 32 --log-every 5000 \
  --ckpt-dir out/vae/ckpt_b128 --ckpt-every 5000 \
  --out out/vae/b128_512.pt
```

**已实测跑通**（20 步冒烟，eval 正常下降，无 OOM）。

### 各配置的可用性速查

| 目标 | 配置 | 状态 |
|------|------|------|
| 快速迭代 | `--base 16/32 --size 128/256 --opt adamw8bit` | ✅ 余量大 |
| 正式训练 | `--base 64 --size 256 --batch 8` | ✅ 4423M |
| **目标容量** | **`--base 128 --size 512 --batch 2 --opt adamw8bit`** | ✅ **已跑通** |
| 1024² | `--base 128 --size 1024 --batch 1` | ⚠️ 未实测（块大小会自动降到 1） |

## 4. 省显存的其它手段（按性价比排序）

| 手段 | 效果 | 代价 | 何时用 |
|------|------|------|------|
| ⭐ **8-bit AdamW** | **−2.2 GB** | 优化精度略降 | **永远开** |
| 减小评估块 | 已自动 | 无 | 已自动 |
| 梯度累积（放大有效 batch） | 0 | 时间 ×N | 想要大 batch 又装不下时 |
| **梯度检查点** | 激活 −50~70% | 时间 ×1.3 | 高分辨率时（`torch.utils.checkpoint`） |
| bf16 混合精度 | 激活 −50% | 需谨慎处理数值 | 收益与风险要实测 |
| 模型分片（`device_map`） | 可跨机 | 本机单卡无效 | 多卡才行 |
| CPU offload | −VRAM | 慢 10× | 最后手段 |

⚠️ **没做梯度检查点** —— 因为实测发现这个 VAE 是**纯卷积、无 attention**
⇒ 显存随分辨率**线性**增长（不是 O(N²)），块调小就够了。若将来上 DiT 主干则必须做。

## 5. ⛔ 这套方案解决不了什么（诚实边界）

| 事项 | 能否 8GB 本机 | 说明 |
|------|-------------|------|
| **P1 训 VAE** | ✅ **能** | 本文档的全部内容 |
| **P1 验收 / 评估** | ✅ 能 | `kp/train/vae_eval.py` |
| **P2 训 DiT 主干（小规模）** | ⚠️ 需分阶段 | 单流 DiT 有 attention ⇒ 激活 ∝ token² |
| **G6 全量预训练** | ⛔ **不能** | Micro-Budget 用 3700 万图；即使 1024²/0.6B 也要数天 GPU |

⇒ **现实的分工**：
- **本机 8GB**：P1 全部（VAE 训到 512²/1024²）、所有验证门、代码与设计
- **租云**：仅 G6 一次全量预训练（**不是持续需求**，是一次性事件）

> 💡 如果连租云也省：**G6 可以缩到「极小数据 + 极短步数」做通路验证**，
> 证明能出图即可，**画质靠 P1.8 + 能力包在推理侧补**。
> 代价是主干的「上限」没被验证 —— 属于「先证明路通，再决定要不要投资」。

## 6. 复现本文档的测量

```bash
source ./env.sh
nvidia-smi --query-gpu=memory.total,memory.used,memory.free --format=csv,noheader
"$KP_PY" -c "import psutil; vm=psutil.virtual_memory(); print(vm.available/1e9)"
```

⚠️ **测显存前必须**：
1. 确认无残留 python 进程（`tasklist | grep -ci python` 应为 0）
2. **每个配置用独立进程**测 —— 同进程内反复重建模型会造成碎片，
   导致「0 张都放不下」这种假象（本轮真实踩到）
