# KokonaPolaris 补充设计 05 · 可逆擦除与能力谱系

**Reversible Erasure & the Capability Cost Spectrum**

> 版本 v1.0 · 2026-10-02 · 设计稿（未实现）
> 关联主文档：v1.5
> 本轮解决的问题：**「能力可插拔」这条路线，在成本上到底分几档？以及为什么其中最难的一档其实是最便宜的？**

---

## 0. 结论先行

**技术上是可行的，而且它是整套能力谱系里最便宜的一类——比「二次元 → 写实」跨域便宜一个数量级。**

原因是一个**对称性**：

> 在这个架构里，「拿掉一个能力」和「加回一个能力」用的是**同一个算子，只差一个符号**。而现代的概念擦除方法已经被证明是 **闭式、低秩、秒级**的。所以只要擦除是「**可记录的**」，添加就是「**可计算的**」。

它有**一条硬边界**：只对**「底模本来学到过、后来被抑制」**的能力便宜。对「底模从未见过」的分布，它和别的能力一样贵。

本架构**不需要为此新增任何机制**——它是能力总线表格里的一行，与「画风包」结构完全同类。因为门控默认 0 且满足 bit-exact 不变量，**带这个接口发布的成本严格为零**。

## 1. 先补上我上一轮判据里的一个缺口

上一轮我给的判据是：

> **支撑集内 = 低秩扰动能改；支撑集外 = 低秩扰动改不了。**

这条判据没错，但**漏了一类**：**支撑集内、但被人为推出去的那部分**。

| | 性质 | 需要的操作 | 代表 |
|---|---|---|---|
| **跨域** | 底模**从未见过**该分布 | 扩容量（并联分支 / 重训） | 二次元 → 写实、文字渲染 |
| **能力恢复** | 底模**见过**，但被投影掉了 | **反向投影** | 被合规/对齐抑制掉的能力 |

这两个在成本上**差一个数量级**，但在「能不能用低秩实现」这个问题上，**答案完全相反**——前者不能，后者不但能，甚至是闭式的。

**所以完整判据要变成两问：**

```
第一问：底模见过这个分布吗？
  没见过 → 支撑集外扩 → ∥-Pack（并联分支，需重训）
  见过   → 第二问
第二问：它被人为抑制过吗？
  是 → 恢复型 → 闭式算子 / Δ-Pack（秒–小时）
  否 → 长尾型 → Δ-Pack（小时）
```

## 2. 机理：擦除几乎不销毁知识

四条独立证据，指向同一个结论。

### 2.1 擦除主要是「回避」，不是「销毁」

**arXiv 2505.17013《When Are Concepts Erased From Diffusion Models?》**（NYU · Northeastern，7 种擦除方法 × 13 个概念 × 10 万+ 次生成）

论文把擦除机制分成两类：

- **Guidance-based avoidance（引导式回避）**：把模型从目标概念**重定向**走，概念本身还在；
- **Destruction-based removal（销毁式移除）**：压低生成该概念的**无条件似然**。

论文给的结论要点：

- **多数现有方法属于前者**；
- 被"抹掉"的概念可以被 **「向去噪轨迹重新注入噪声」** 这类探测手段捞回来；
- 二者的真正差别是**权衡关系**：destruction 类更抗对抗提示词，但**会损害无关输出**（论文原话：robustness comes at a cost）。

> **对本案的意义**：如果擦除多数时候只是「重定向」，那么"恢复"就不是重新学习，而是**解除重定向**。

### 2.2 安全对齐本质是「零空间投影」，而且极低秩

**《What Makes and Breaks Safety Fine-tuning? A Mechanistic Study》**

- 安全微调（DPO / RLHF）**不会改写底层知识**，而是学一个**最小的、几乎正交于原权重的 ΔW**；
- 关键结构发现：**ΔW 的列空间高度对齐于原权重 W 的零空间**——即安全微调是"把不安全激活投影到零空间里"，是一个**滤波器**，不是一次重学；
- 不安全样本的内部特征在深层**塌缩到单一主导方向**（不安全样本特征协方差**首奇异值占 ~62% 方差**，安全样本只有 **~12%**）。

### 2.3 整个「行为模式」住在极少数方向上

**LoX（Low-rank Extrapolation）** 给出的数字：安全子空间的**有效秩 k ≈ 6**。

做法：对 `ΔW = W_aligned − W_base` 做 SVD，取 top-k 奇异向量，用 `α ≈ 1.25` 外推回去：

```
W_LoX = W_aligned + α · Proj_k(ΔW)
```

**结果**：仅靠这 6 个方向的外推，就能显著改变整个安全行为，并使后续微调难以洗掉它。

> **这就是全案最反直觉的一个数字：一整个「行为模式」，住在 6 个方向上。** 相比之下，我们主干的 hidden dim 是 1152。

### 2.4 于是反向操作是闭式的、秒级的

| 方法 | 年份 | 机制 | 关键数字 |
|---|---|---|---|
| **CURE** | NeurIPS 2025 | Spectral Eraser：对 forget / retain 两个 token 嵌入集做 SVD，得**闭式正交投影**，单步更新权重 | **22 秒**完成；明确覆盖 explicit content 类目标；训练免费 |
| **MACE** | CVPR 2024 | 闭式 cross-attention 精修 + 逐概念 LoRA | 可同时处理 **100 个概念**；「多个 LoRA 之间互不干扰」 |
| **UCE** | 2024 | 把 cross-attention 投影权重的修改写成**闭式优化** | 保持非目标概念的原始输出 |
| **GLoCE** | — | **门控低秩**模块，把目标嵌入投影到零子空间 | **可开关**（这点最关键） |
| **CA-LoRA** | 2023 | 压缩模型的**知识恢复模块** R：`σ(XD)U`，带非线性以适应"非低秩"损失 | 为"恢复被压缩掉的能力"提供先例 |

> **合起来：{ 低秩 k≈6 } + { 闭式 } + { 秒级 } + { 可门控 }。这四个性质同时成立，意味着「加回来」不是训练问题，而是求逆问题。**

**且注意 CA-LoRA 已经在「恢复被压缩损失的知识」这个场景验证过**——它甚至指出了 LoRA 的一个局限：LoRA 是低秩的，而压缩损失往往不是低秩的，所以它在恢复模块里加了非线性激活。**这条经验对我们的 Δ-Pack 设计直接适用。**

## 3. 但它仍然是混合问题：三个子类

**不要把它当成一件事。**

| 子类 | 性质 | 归属层 | 成本 | 判据 |
|---|---|---|---|---|
| **① 被抑制的能力恢复** | 底模学过 → 被投影掉 | 闭式算子 / Δ-Pack | **秒–分钟** | 有没有被擦过 |
| **② 长尾内容分布** | 支撑集内但覆盖稀疏 | Δ-Pack（需容量、可能需非线性） | **小时** | 数据密度 |
| **③ 真正的新分布** | 支撑集外扩 | ∥-Pack（100M–1B） | **需重训** | 底模见过没有 |

**多数人直觉里以为的「那个能力」，实际是 ①② 的组合，而不是 ③。**

而 ③ 恰好是「二次元 → 写实」和「文字渲染」所在的那一格。**所以：同一张能力表，不同格子的成本差两个数量级。**

**工程含义**：先把 ① 和 ② 做掉，能覆盖绝大部分需求，且**完全不需要动主干、不需要重训**。只有当需求真的落到 ③，才要付出并联分支的代价。

## 4. ⭐ 架构贡献：可逆擦除账本（Reversible Erasure Ledger）

这是本轮真正值钱的部分。**它同时改善两件事：可合规性 和 可扩展性。**

### 4.1 我们手上有一个「白拿」的结构性优势

我们**必须**在训练数据里做合规过滤（法律与可分发性）。也就是说：

> **抑制是由我们自己主动施加的。** 它不是外部厂商灌进来的黑盒 RLHF。

这正是现有社区做"恢复"时的困境所在：**他们不知道被擦掉的方向是什么**，只能靠对抗搜提示词、靠猜、靠噪声探测——arXiv 2505.17013 那一整套 probing 框架就是为这件事发明的。

**而我们可以知道。** 这是一个结构性的、白拿的优势。

### 4.2 账本的设计

把合规抑制实现为一个**显式的、有记录的低秩算子 `E`**，而不是黑盒对齐：

```
E = Σᵢ αᵢ · uᵢ vᵢᵀ        作用在指定层集合 L
```

训练时**同时记录**：

| 记录项 | 用途 |
|---|---|
| 擦除子空间基 `{uᵢ, vᵢ}` | 定义反向算子的精确方向 |
| 有效秩 `k` | 决定 `E⁻¹` 的容量上界 |
| 作用层 `L` 与逐层强度 `αᵢ` | 定位语义分化的深度 |
| **保留集 / 目标集的语义边界** | 用于检验特异性，防止误伤 |

**后果：恢复 = 应用 `E⁻¹`。** 我们知道**方向、量级、层位、边界**。不需要探测，不需要对抗搜索。

> **一句话：把「擦除」从一次不可逆的手术，改成一个有据可查的账本条目。**
> 而**账本的逆运算，就是能力包**——`Pack_recover ≡ E⁻¹`。

### 4.3 为什么这同时让「擦除」本身也更好

文献反复指出擦除的核心矛盾，而显式低秩 + 可门控的设计**第一次让它们可以分开调**：

| 文献里的矛盾 | 账本式设计怎么解 |
|---|---|
| **Generality vs Specificity**（擦得干净 vs 不伤无辜）——MACE 整篇论文就在解这个 | 记录「保留集边界」→ 特异性变成**可测量、可优化的约束**，而不是事后碰运气 |
| **Robustness has a cost**（销毁式更强但损害无关输出） | 强度 `αᵢ` 连续可调 → 可以在「干净」与「不伤无辜」之间走**连续路径**，而不是二选一 |
| 擦除会**震荡到早期去噪步**（MACE 发现：改早段预测会误伤同名的其他概念，因为早期轨迹还都在同一个人脸流形上） | MACE 的 **spontaneous symmetry breaking** 观察直接给出了判据：**作用层应当选在「语义已经分化」的深度之后**。文献经验值：**网络深度约 2/3 处最有效** |
| 训练期对齐会被后续微调洗掉 | **LoX 那条记录里：用完全无害的 GSM8K 微调 2 个 epoch，拒绝率就能从 ~0% 打到 50% 以上**。→ 说明"对齐"必须能被**重新施加**，而不是一次性 |
| — | **可门控** → 部署策略层可以按场景决定是否施加（见 §6） |

> 一句更本质的话：**「可逆」不是安全性的敌人，反而是安全性的前提。**
> 一个不可逆的黑盒擦除，既无法审计、也无法修复、也无法随政策更新——它只是一个无法验证的承诺。而账本式擦除是**可审计、可回滚、可重配**的。

### 4.4 成本严格为零

| 项 | 成本 |
|---|---|
| 门控默认值 | **0** |
| bit-exact 不变量 | 账本存在与否**不改变裸模型输出** |
| 账本本体 | 只是元数据（若干基向量 + 标量），**不吃显存、不进权重** |

**所以「预留接口」这件事在这个架构里不是一个决策，而是一个推论。**

## 5. 数据供给：一条 3D 资产线，四个正交旋钮

如果需求真的走到子类 ②/③，数据从哪来？**和角色卡完全同一条线。**

### 5.1 现成证据：分层参数化人体

**SynBody（ICCV 2023，商汤 / 上海 AI Lab / NTU / 港中文）**

- 核心是 **SMPL-XL**，一个「自底向上」的**分层参数化人体模型**：
  - **Base Body**（参数化体表，可采样不同体型）
  - **Hair**（32 种发型 / 13 种胡须）
  - **Garments**（程序化外套 / 衬衫 / 裤 / 裙）
  - **Accessories**（鞋 / 眼镜）
- 规模：**1.2M 图 / 10,000 个人体模型 / 1,187 个动作 / 26,960 段视频 / 2.7M SMPL-X 标注**
- 管线：UE5 + **XRFeitoria** 渲染工具链，动捕重定向自 AMASS
- 配套标注：depth map、optical flow、语义分割
- ⚠️ **许可：CC BY-NC-SA 4.0**；SMPL-X 用于商用需向 Meshcapade 单独授权 → **只能研究用**

**论文自己的一句结论值得记下**：因为是「逐层构造」，所以**即使被宽松服装遮住，"真实体型"的 ground truth 也是已知的**——这是扫描式数据集做不到的。

### 5.2 关键结构性质：分层带来零成本监督

| 旋钮 | 得到的监督 | 已有出处 |
|---|---|---|
| **视角** | 多视角身份一致性 | 补充 04 角色卡线 |
| **着色器** | 几何/姿态/相机完全一致的**画风配对** | 补充 03 已提出 |
| **分层可见性** | **部件级**分割与结构监督（层边界天然自带 mask） | 本轮新增 |
| **姿态** | 动作、遮挡关系、绘制序 | 本轮新增 |

**四个旋钮相互正交 → 配对样本是组合式扩增，不是线性扩增。**

> 这也回答了第一轮那个开放问题（「有没有更聪明的数据源提供方式」）：
> **答案是「分层 + 多旋钮」，而不是「更多图」。** 我们用结构性先验换数据量。

### 5.3 其他可复用的合成线（同轮查到）

- **UnrealPose（arXiv 2601.00991，2026）**：UE5 + Movie Render Queue 离线渲染，**UnrealPose-1M**（约 100 万帧），输出 3D 关节、2D 投影 + COCO 关键点（含遮挡/可见性标记）、bbox、相机内外参。**管线也一并开源**——可直接接我们的资产线。
- 这两条线共同说明：**「分层参数化资产 + 引擎渲染」已经是成熟可复用的基础设施**，不需要我们从零造。

## 6. 部署边界：三层责任

这里必须说清一件**工程事实**（不是立场，是架构）：

安全文献里有一条明确的设计原则——**约束应当在架构层强制，而不是只靠训练期对齐**。理由不是道德，而是**训练期对齐在工程上不可靠**：

- LoX 那条记录：**用完全无害的数据集（GSM8K）微调 2 个 epoch，拒绝率从 ~0% 升到 50% 以上**；
- 另一条：即使只重置 **~0.2% 的权重**就能把有害率从 33.25% 压回 1.74%——**说明对齐与不对齐之间只隔着极小的权重改动**，因此它天然脆弱。

**套到我们身上，就是三层分工：**

| 层 | 内容 | 谁负责 | 我们的设计 |
|---|---|---|---|
| **模型层** | 干净底座 + 门控总线 + **擦除账本** | 我们 | 可分发、可审计、bit-exact |
| **包层** | 能力包（并联 / 叠加 / 角色卡 / 排版） | 生态 | 可插拔、可替换、体积 1–27MB |
| **部署层** | 加载同意、输入输出策略、能力白名单 | 使用者 / 平台 | 模型不内建 |

**这个分层的工程价值**：

1. **底座保持干净且可分发**——这既是许可要求，也是平台要求；
2. 能力包由使用者自行承担——**这正是社区生态已经验证跑得通的运作方式**（CivitAI 式模式）；
3. 因为门控是 bit-exact 的，**交付一个「不装任何包就等于原版」的模型，成本为零**。
