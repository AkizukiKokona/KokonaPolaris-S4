🧭 读前必看：这个项目到底在做什么（v1.12 新增）

刚打开这份文档的话，先读这一段。这三句话此前散落在 11 份文档里、从没有集中写过 —— 这是本次审计补上的最大缺口。

1️⃣ KokonaPolaris-S4 是一份「设计稿」，目前 0 行代码。目标是设计一个全新的文生图模型（不是改造 SDXL / Flux），把「低显存 + 原生 FP4 + LoRA 友好」当成第一性目标。

2️⃣ ⭐ 现在能跑出图的，不是 KP，是 Sana 1.6B。那是我们下载的、别人已经训好的开源模型，被当作靶子（替身 / 试验台）。选它是因为它的 latent 压缩率（32×）与 token 数（1024）与 KP 完全同构 → 在它身上验证出的量化结论可直接外推到 KP。

3️⃣ 本机是「验证机」，不是「训练机」。RTX 5050 Laptop / 8 GB / 20 SM 只够把假设一条条打掉（跑 G0–G5 与副线 P2′），不够从零训一个大模型（G6 全量预训练必须租云）。

👉 所以「刚做第一步就能出图」不是矛盾 —— 出图的是靶子模型 Sana，我们做的是在别人的模型上验证我们自己的设计假设。KP 本体至今一张图都没生成过、一行架构代码都没写 —— 目前 D:\model\tools\ 下的全部是在 Sana 上做实验的脚本，不是 KP 本身。

三个编号系统，别混淆（这是最容易读乱的地方）：

· P0–P4 = 产品路线 —— KP 本体的建设顺序：「模型怎么一步步造出来」（P0 验证 NVFP4 → P1 换 latent → P2 换主干 → P3 身份模块 → P4 少步化）
· G0–G7 = 验证门 —— 每条关键假设的关卡：「这假设成立吗？不成立怎么办」（G0 环境 ✅ → G1 NVFP4 不掉点（W4A8）✅ 初步通过 → G2 通道分离 → G3.5 L1 轴真实性）
· E0–E8 = 环境准备任务 —— 一次性工程活：「桌子摆好了吗」（E1 建 venv ✅ / E2 定格版本 ✅ / E4 下靶子 ✅ / E5 量化实测 ✅）

E（摆桌子 · 已基本完成） ──▶ G（在桌上做实验 · 验假设） ──▶ P（按结果真正把模型造出来）
                                    ▲ 现在在这里：G0 已通关，G1（W4A8）初步通过，待补正式 FID

v1.13 修订摘要（详见《KokonaPolaris_补充09_G1前哨量化实测与判据修订》v1.1）—— G1 从「做实验」推进到「初步通过」

⑥ ✅ E5b 可训性定案（补充 09 §8）—— ModelOpt 量化后的模型只能推理、不能训，blocker 精确定位为 FP8SDPA 无 backward（diffusers 插件把 F.scaled_dot_product_attention 换成了只实现 forward 的自定义算子）——与量化器开关、与 CUDA 扩展均无关，patch 回原版 SDPA 后 W4A8/W4A4 全参 backward 通过。⚠️ 并更正一处根因误判：不是「本机缺 MSVC」（实测 4 处 VS 安装，cl.exe 只是不在 PATH）。

⑦ ⭐ 容量结论：8 GB 卡必须 adapter 式 QAD —— 全参 QAT 的 AdamW 优化器状态 = 2×1.604e9×4B ≈ 12.8 GB，绝无可能；改「冻结主干 + 只训低秩旁路」（5.99 M 可训、峰值 3.41 GB）。与设计稿「Δ-Pack / 能力包」完全同构 → 不是妥协，是把架构决策提前实证了。另给出自研可微 NVFP4 fake-quant（STE）作为绕开 ModelOpt 训练路径的独立方案。

⑧ ✅ G1 快速判据初步通过（W4A8）（§10）—— 用 d_quant / d_ref（量化偏移 ÷「换一个 seed」的自然离散度）取代全量 FID：W4A8 仅 53.5%（W4A16 52.7% / W4A4 88.9%，三臂全 < 1）⇒ 激活降到 FP8 几乎不额外损失，实测支持「FP4 权重 + FP8 激活」设计档。⚠️ 统计薄（每 prompt 3 对），正式过门仍需 ≥50 张/臂 FID。

⑨ 🔧 一条流程规范（用户明确要求）：连续「日志 0 字节 + exit 1」不是脚本 bug，而是失联子代理的孤儿进程占卡（e5b_qat_mopt.py --steps 700 一直在跑、占 ~4.8 GB）→ 叠任务爆显存。⇒ 派 GPU 任务前先清同名孤儿；长任务每步极小增量 + -u 实时输出 + 几十秒级读日志 + 断点续跑。

⑤ ⚠️ 两条边界如实标注：(a) PTQ 是模拟量化（权重仍 bf16 驻留）→ 本轮显存数字不能用来论证 NVFP4 的显存收益；(b) ModelOpt 的 NVFP4 fake-quant 忽略 block_sizes 配置（16/32/64 逐位相同）→ 官方 "block 32" 不带来额外损失。

v1.11 修订摘要（详见《KokonaPolaris_补充08_控制件与L1基座依赖风险》）—— 用户警告触发的一次地基级审查

⓵ ⚠️ 发现一处真缺口：「选层判据」里从来没有 L1。原「两问」只在 L2/L3 之间分流，把承担 90% 需求的 L1 预设为"免费已得"。→ 这不只是"过度信赖基座"，是从未检验。已在 §4.8 补上「第零问：这个轴存在吗？」，并新增 §4.8.7 全节。

⓶ ⚠️ L1 的低比特风险被确认为「全案第三个隐藏关键假设」（前两条：NVFP4 QAD、通道分离退化），且比第二条更外层——通道退化让 L1 失真，覆盖率不足让 L1 不存在。机制：FP4 激活只有 16 个量化级（E2M1），若风格靠激活精细结构传递，量化会系统性压缩轴的分辨率 → 「旋钮行程变短、转到一半就饱和」。G0–G7 全未覆盖。

⓷ ✅ 加固四条：① 措辞纠正——90/9/1 是调用量分布、非能力分层（「L1 覆盖 90% 调用量，L3 承担 100% 兜底责任」）；② 新增 Axis Probe + 验证门 G3.5（单调/正交/可逆/低比特行程四测，未通过者默认归 L3）；③ 新增 Style-Pack（风格也走载体路线，与角色卡/TypographyPack 共用分层格式）；④ 立设计律「控制权原则」：能显式写入的，就不要隐式请求。

⓸ ⭐ 一条免费的正交监督手段：§4.8.4 的 shader 配对数据此前只当"数据来源"，现有第二用途——同一场景不同 shader，几何/光照/相机/姿态完全一致，条件向量的差异理论上只应落在风格维，其余维度必须为零 → 天然的逐维独立监督信号。加上它，L1 才能从「黑盒旋钮」变成「已标定控制面板」（16 维，逐维命名）。

⓹ 📌 ControlNet 定位确认：等价物是 条件包（§4.7.9，Adapter/带分支/depth·pose·seg），属「能做但贵」（独立分支 + 天级重训），不进当前预算；ControlNet 原有的两个职责已被「语义 8ch 通道 + Layout token」与「角色卡」拆走 → 「只为了生成角色才需要它」的判断成立。

v1.10 修订摘要（详见《KokonaPolaris_补充07_环境基线报告》v1.3，功耗天花板翻案）—— 推反 v1.9 的功耗结论

㊼ ⚠️ 【翻案】115 W 完全可达，实测峰值 113.8 W（＝上限的 98.1%），温度 82 °C，降频标志 clocks_event_reasons.active 恒为 0x0（零降频）。v1.9 ㊶ 的「天花板只有 ≈80 W / 115 W 不可达」作废。

㊽ 🔍 根因是测量口径错误：v1.9 的 80 W 是 bf16 负载的功耗，被误当成整卡上限。功耗是「负载形态」的函数——实测 5 种形态各 18 秒：D2D 拷贝 68.4 W / fp32 elementwise 66.9 W / bf16 tensor 79.7 W / 三流并发 79.8 W / FP4 tensor 113.0 W（峰 113.8）。

㊾ 🎯 对架构判断反而是强化，不是削弱：设计主线的 FP4 路径正是把功耗打满的那条——120.5 TFLOPS 是在 113 W 下取得（不是 80 W），且已逼近 20 SM 的 tensor 理论峰值（20×1024 MAC×2×2.797 GHz ≈ 114.6 TFLOPS）→ 「瓶颈是 20 SM 而非功耗」现在有了硬证据：再给瓦数也买不到 FLOPS。

㊿ 📌 新规范（永久）：功耗必须按负载形态分别测，不能用一个负载的功耗代表整卡上限；测功耗上限时必须同时读 clocks_event_reasons.active。 另：FP4 每瓦算力 1.07 TFLOPS/W，是 bf16（0.32）的 3.3 倍——进一步支撑「原生 FP4」这条主线。

v1.5 修订摘要（详见《KokonaPolaris_补充05_可逆擦除与能力谱系》）

v1.4 修订摘要（详见《KokonaPolaris_补充04_身份载体与双向包体系》）

⑮ 身份载体升为一等公民：新增数据类型「角色卡」（1–5MB，2.5D 分层 + 伪深度 + 身份 token），身份不再由 Δ-Pack 承担。

⑯ 能力挂件二分为双向包体系：并联包 ∥-Pack（旁路，能力可大，物理上不可能打架）/ 叠加包 Δ-Pack（ΔW，必须锁子空间，只做长尾）——分工边界由数学规定。

⑰ 找到「打架」的物理机理：LoRA 会产生 入侵维度（intruder dimensions）——正交于底模权重的奇异向量（arXiv 2410.21228）。据此新增 「禁止入侵维度」硬约束（含训练后谱检查）。

⑱ 叠加包规格升级：块对角分解（有效秩 n_l×r，参数量不变）+ rsLoRA α/√r 缩放 + 按 GID 分层 + W_o 优先分配预算。

⑲ 身份 token 走 cross-attention、不拼主序列（256 token，非 1024）——反对照抄 InstantCharacter。

⑳ 主干双域预训练 + domain 条件向量：让「写实」成为内生旋钮（默认 anime），不做事后外挂。

㉑ ComfyUI 不作为路线依赖，只预留四个兼容接口；㉒ TypographyPack 与角色卡共用同一套分层表示。

v1.3 修订摘要（详见《KokonaPolaris_补充03_LoRA天花板与三层控制栈》）

⑨ 新增「三层控制栈」：L1 主干内生条件轴（约 90% 需求，零成本）＋ L2 外置条件编码器（约 9%）＋ L3 子空间约束 LoRA（约 1%）——让 LoRA 只做长尾，它的两个天花板从根上消失。

⑩ 能力包默认采用 SVD 子空间约束（LoRA-X 式，ΔW = Ũ·ΔΣ·Ṽᵀ）→ 跨主干版本可迁移，零额外成本。

⑪ ⚠️ 新增必做项：通道分离的显式监督——无监督则两通道都会塞满信息，画风解耦失效（全案第二个隐藏关键假设）。

⑫ 新增分辨率维度 Matryoshka（早期步骤跑 256 token，后期长到 1024；实测 FID 改善且 FLOPs −60%）。

⑬ 重要更正：删除「从零预训练需千万级算力」的判断——Micro-Budget 证据把成本拉到 $1,890 / 1.16B，可行性边界已变。

⑭ 风格条件轴的数据钥匙：同一 3D 场景 × 不同 shader 渲染 = 内容对齐、风格不同的完美配对。

v1.2 修订摘要（详见《KokonaPolaris_补充02_能力总线与文字渲染》）

⑤ 新增「能力总线」：冻结主干 + 可插拔能力包（画风 / 角色 / 领域 / 条件 / 文字）。单包约 27MB，门控默认 0 时输出 bit-exact。

⑥ 明确「可插拔」的分界线：同一支撑集内的能力（画风 / 身份）可做 LoRA 包；支撑集外扩的能力（文字渲染、空间推理）必须进主干或带独立分支——低秩适配能改「怎么画」，不能改「看得见什么」。

⑦ 新增 TypographyPack：主干保持 32× 压缩不动，文字走独立的低压缩 ROI 分支（字形条件 + AttnX 注入，<0.6B）。

⑧ 新增 Layout Planner（独立 100M–1B 小模型）：把「版式规划」从像素生成里剥离，输出 JSON 版面结构。

v1.1 修订摘要（详见《KokonaPolaris_补充01_底模策略与注意力稀释》）

① 不选「底模」，改选教师——主教师 Z-Image-Turbo（Apache 2.0）+ DINOv3 语义锚定 + Qwen3-4B 文本教师。因为架构全自研，一个权重都继承不了，所以「底模」对本案唯一的意义是教师。

② 注意力从「3:1 线性:softmax」改为「3:1 线性:Sigmoid/Softpick」（去 softmax）——同时解决长提示稀释与 NVFP4 激活离群值。

③ 新增 16 个 layout token 两段式路由；④ 浅层前 4–6 block 保留 double-stream，借鉴 Flux 的文本对齐优势。

02核心判断

显存的第一性来源是 token 数，不是参数量。

1024² 在 f8/4ch latent 下是 16384 token，注意力与激活按 O(N²)/O(N) 膨胀；32× 压缩后只剩 1024 token。参数量只决定权重大小——FP4 下 1.5B 才 0.84GB；token 数才决定激活、注意力、KV、梯度，后者才是 8GB 卡真正的瓶颈。

因此设计动作的优先级是

PRIORITY 1

决定 token 数，直接决定一切
PRIORITY 2
注意力复杂度
线性 vs softmax，决定分辨率能否外推
PRIORITY 3
权重位宽
NVFP4，二级放大器
PRIORITY 4
参数量
最后才考虑
把 NVFP4 当第一因去设计，会得到一个权重很小、但一开图就 OOM 的模型。

NVFP4 是放大器，不是地基。地基是 latent 压缩率。

03总体架构

五段式流水线。文本、身份、几何、图像 latent 四类 token 全部拼进同一条序列，共享同一套注意力权重。

为什么必须是单流

  • 参数效率：Z-Image 用 6B 单流打平 20B+ 双流，参数量能压到 1/3。
  • LoRA 友好：只有一个 block 结构，注入点唯一，不需要为 text-stream 和 image-stream 分别设计 rank 与学习率。
  • 双流本身就是冲突来源：两套参数对同一扰动响应不同，容易「改了风格也歪了结构」。

04五个模块

模块 1

文本塔 · 小，但不缓存

~220M，从 T5-XXL 或 Qwen3-4B 蒸馏（参考 CVPR 2025 的 T5 蒸馏：11GB → 285MB，整管线快 2.7×，FID/CLIP 基本持平）。

  • 输出多层特征聚合，不用末层——自回归 LLM 末层为 next-token 优化，对图像生成并非最优。
  • 不缓存 embedding。缓存能省 5GB，但会砍掉 prompt dropout、文本侧 LoRA 训练、CFG 负向文本三项能力。省显存靠 latent 压缩，不靠牺牲训练灵活性。
  • 实测开销仅 0.22GB（FP8），完全可接受。
创新 1

混合 Latent · 语义 8ch + 细节 32ch

把 latent 通道分成两组承担不同职责：语义通道对齐冻结 DINOv3（管「是什么、在哪、什么姿态」），细节通道走 DC-AE 式重建（管纹理、光照、高频）。

  • 低数据训练的救星：语义通道等于把 REPA / RAE 的收益免费内置了（REPA-E 报告收敛快 17–45×）。
  • 身份与画风的天然解耦：CharaBridge 只读语义通道，底模画风只影响细节通道——这是「LoRA 不打架」的物理基础。
  • 注意力成本几乎不变：通道数不参与 O(N²) 项。40ch vs 16ch 的投影开销增加不到 2.5×，但 token 数少 16×，绝对开销仍远低于 f8。
为什么不做纯 RAE？

RAE 不做空间压缩（256² → 256 token），对低显存是反向的；纯语义 latent 在文字渲染与细纹理上会糊。所以是混合，不是替换。

模块 2

单流混合注意力主干

  • 3:1 线性 : Sigmoid/Softpick（v1.1 修订，去 softmax）。每 4 层 = 3 层 gated linear + 1 层非归一化注意力。依据：SANA-Video 2.0 代理实验确认 25% 最优，前向 3.2×。
  • 为什么把 softmax 换掉：softmax 把所有 token 权重归一化到总和为 1，token 之间竞争同一块概率质量——提示词越长，有效词分到的份额越小。这就是 SDXL「词一多就乱画」的根因（T2I-CompBench 上 SDXL 的 Spatial 只有 21.3 / 100）。Sigmoid 对每个 query-key 对独立打分；Softpick 是 softmax 与 ReLU 的中间态。
  • 附带的巨大红利：Sigmoid / Softpick 能实现接近零的 attention sink 率并显著减少激活离群值 → 让低比特量化更鲁棒。而 attention sink 正是 NVFP4 最怕的 outlier 主要来源之一。一个改动同时打中长提示稀释与 FP4 精度两个问题。
  • 非 softmax 层只放低分辨率层（前 1/3 深度），高分辨率层全线性 → 显存随分辨率线性而非平方增长。
  • Layout token 两段式路由（v1.1 新增）：插入 K=16 个可学习布局 token（4×4 粗网格 + 2D 位置编码）。文本 → 路由 → 布局 token → 送达图像 latent。把一次性 attention 拆成两段式，显式引入空间先验。弱监督可直接复用 3D 合成数据的 bbox / depth，零额外标注成本。
  • QK-Norm 必开：抑制高分辨率下 logits 爆炸，对 4-bit 路径几乎必需。
  • adaLN-Single：所有 block 共享一个 timestep 调制 MLP，让 timestep 调制只需在一个地方保高精度。
  • 无位置编码，用 Mix-FFN（3×3 深度卷积 + GLU）提供隐式位置信息。同时消除 RoPE 在 4-bit 下的精度敏感性。
创新 2

CharaBridge · 多视角身份与几何模块

直接对着你的痛点设计。输入 K 张参考图（K=2–8，典型是正视图 + 背视图），双分支解耦：

  • 外观分支：DINOv3 语义特征 → Perceiver Resampler → N 个 identity token，聚合时做置换不变池化。
  • 几何分支：轻量重建头（~5M 参数）预测 normal + depth + ray-pose → M 个 geometry token。
  • gated cross-attention 注入，只打在第 4 / 10 / 16 层，门控初始化为 0。
三条关键约束

① 可关断 & bit-exact：id_weight=0 时输出与底模逐位一致（参考 PuLID 只在第 2/4 block 加残差）。

② 审美不进身份 token：外观分支只吃语义特征，不吃像素纹理 →「是谁」与「画成什么风格」分离。

③ 几何与外观解耦：训练时背景与光照被显式剥离（Zero123++ 的教训：灰底会让重建把背景色差误认为几何）。

为什么是外置模块而不是 LoRA？LoRA 改主干权重，本质是「覆盖」底模先验；外置编码器是「并联」的新通路，物理上不可能覆盖底模。这是解决冲突的结构性方案，而不是靠调参。

创新 3

可伸缩深度 · Matryoshka 式主干

同一份权重，不同分辨率跑不同深度：512² 跑满全部层，1024² 跑前 20 层，2048² 跑前 14 层 + 分块。训练时对多个出口同时施加损失。

价值：把「低显存」从硬约束变成可调谱系——8GB 卡在 1024² 不必跑满整个模型。

diffusers issue #9291 / #10989，v0.32.2 才修。表现为「不出错，但风格完全没变化」。所以从架构层面就要留接口。

项选择理由
主干冻结 · NVFP4前向走 TransformerEngine FP4 kernel
适配器BF16 LoRA / DoRA梯度只走适配器，无需穿透量化器

07不跟底模打架的四条机制

冲突不是学习率调错了，而是结构上让两股力量抢同一块地盘。

机制做法消除的冲突表现
M1 通道分离身份只走 CharaBridge 独立通路，画风/结构走主干「改角色就改画风」
M2 正交注入门控初始化为 0 + 对注入子空间施加正交约束特征叠加（经典「四耳」问题）
M3 Latent 解耦身份信号只读语义通道 8ch，不写细节通道 32ch色调漂移 / 塑料感
M4 可关断保证id_weight=0 时底模 bit-exact提供「完全干净的底模」安全基线
冲突的量化理解

遗忘程度 ≈ α(1 − cos²θmin)，θmin 是相邻任务梯度子空间的最小主角。当子空间本身接近正交时，rank 与遗忘几乎无关。

所以 M2 的意义在于主动把 θmin 推向 90°，而不是靠降学习率被动缓解。

08低数据的三大护栏

「低数据做训练并非灾难」是对的，但需要前提。

① 表征对齐
REPA-E 式，用冻结 DINOv3 对齐主干第 8/16/24 层特征。本方案里这条已被混合 Latent 内置了一部分。收敛快 17–45×——低数据下最有效的杠杆。
② Prior Preservation
DreamBooth 的核心结论：小样本微调会引发语言漂移，模型逐渐忘掉「同类概念」的生成能力。用冻结底模自采样同类图加正则项。
③ 时序感知正则
T-LoRA 指出高噪声步最先过拟合——这些步把结构、细节连同位置背景一起记死。要在高噪声步施加更强的 rank masking，而不是一刀切砍掉（砍掉会显著掉保真）。

对偶视角损失 · 对着你的「正视图 + 背视图」场景

你的条件很特殊：两视角夹角接近 180°，中间的 90° 完全无观测。普通多视角训练会翻车——模型学到的是「记住这张正视图的纹理」，而不是「这个角色长什么样」。

约束做法
① 置换不变性identity token 聚合必须对视图顺序不敏感，用「交换输入顺序输出不变」的一致性损失强制
② 对偶一致性f(正视图) 与 f(背视图) 映射到同一组 identity token，但保留各自的 viewpoint 条件 → 强制学「旋转不变的身份」而非「某个视角的像素」
③ 虚拟视角插值训练时用 3D 资产在正/背之间渲染中间视角做辅助监督（推理时不需要），让模型见过「从正到背是怎么转过去的」
第 ③ 条是「低数据也能出质量」的关键

训练数据是稠密的，用户输入是稀疏的。渲染中间视角几乎没有额外标注成本——用数据成本换渲染成本。

10落地路线

现实前提

从零预训练一个 T2I 底模需要千万级算力，不是个人能承担的。所以路线是「借力起步、逐层替换」。

P0 · 验证 NVFP4 假设 最高优先级
拿现成 1–2B DiT（Sana / Lumina），打 NVFP4 QAD，跑通敏感层白名单 + 四件套
验收：FP4 vs BF16 在 GenEval / ImageReward 上差 < 1%
P1 · 换 Latent
DC-AE 1.5 + DINOv3 拼出混合 encoder/decoder，替换现成模型的 latent，只重训主干
验收：1024² 重建 PSNR / 文字渲染不劣化
P2 · 换主干
换成自研单流主干 + 混合注意力，从 teacher 蒸馏
验收：0.6B 打平 1.5B baseline
P3 · CharaBridge
接入多视角分支，用 Engine-Synthetic Triplet 训练
验收：正+背两图 → 角色一致，且 id_weight=0 时 bit-exact
P4 · 少步 + 后训练
Decoupled-DMD → rCM，Flow-DPO / DMDR
验收：4 步内质量接近 20 步
P0 是唯一必须最先做的实验

如果 NVFP4 QAD 在扩散上不能保精度，整个方案的量化基础就塌了——而这个结论只需要几天就能验证。

约束再分类与排程（v1.8 新增，v1.10 更正功耗数据）

更正：功耗不是硬约束，是可调工况

本机只有两个真·硬约束：显存 8 GB + 20 SM（不可变）。另两项常被误当约束：

项性质排程含义
磁盘（D: 180 GB 可用）工程约束，已解决不再挡路；新增大文件一律落 D:\model\
功耗（45.7 W 静音 ↔ 113 W 满血实测）工况变量只影响速度（静音档已拿到满血 82%），不影响可行性
批次任务何时做
不敏感批（纯 IO / CPU）E1 建 venv · E2 定格版本 · E3 G0 收尾 · E4 下靶子模型 · E6 P2′随时，静音工况即可
敏感批（真算力）~~E7 基准复测~~ ✅ · ~~E8 功耗复测~~ ✅ · E5 G1 QAD 训练（静音也可跑，仅慢 ~20%）解锁可选，不再是阻塞项
一条会影响所有后续估算的规范（v1.10 加强）

① 凡对外报「这机器有多少算力」的数字，必须在解锁功耗下测。实测两档 = 静音 45.7 W（20.9 / 99.2 TFLOPS）与满血 bf16 @80 W → 25.8 / FP4 @113 W → 120.5 TFLOPS。拿静音值估算会偏低 ~19%；功耗收益实际只有 ~1.2×，不是 2–2.5×。

② 功耗必须按负载形态分别测——同一张卡，显存负载 68 W、bf16 tensor 80 W、FP4 tensor 113 W。用一个负载的功耗代表整卡上限，是本项目 v1.9 犯过的错。

③ 测功耗上限必须同时读 clocks_event_reasons.active；只有它为 Active 才说明被限住。

✅ v1.13 · G1 初步通过（W4A8）—— E5b 可训性定案 + 快速判据（详见补充 09 §8）

E5 前哨已在真实 Sana 1.6B 上跑完 4 路量化对照：信号级误差 W4A16 7.74% / W4A8（设计档）9.98% / W4A4 29.72% —— 误差几乎全部来自「激活」量化，设计档落在两者之间，设计选择被实测支持。

⚠️ 但发现一个会误导判决的方法论问题：W4A4 出图 PSNR 只有 9.67 dB，看着像"崩了"，实际画质正常、只是换了构图。→ 固定种子的逐像素指标测的是「轨迹稳定性」，不是「画质」。因此 G1 主判据改为分布级指标（FID / 多样本质量评估，≥ 50 张），逐像素 PSNR/SSIM 降为辅助参考、不作门。

✅ 初步通过：用分布级偏移比 d_quant / d_ref（量化偏移 ÷「换一个 seed」的自然离散度）快速判定 —— W4A8 仅 53.5%（W4A16 52.7% / W4A4 88.9%，三臂全 < 1）⇒ 激活降到 FP8 几乎不额外损失，实测支持「FP4 权重 + FP8 激活」设计档。

⑧ 可训性同时定案：ModelOpt 训练路径的 blocker 是 FP8SDPA 无 backward（非环境问题，已 patch）；8 GB 卡全参 QAT 不可行（优化器状态 12.8 GB）→ 必须 adapter 式 QAD，与设计稿「Δ-Pack / 能力包」同构。

⚠️ 遗留：快速判据统计薄（每 prompt 3 对），正式过门仍需 ≥50 张/臂 FID。

11风险与明确不做

已识别风险

风险级别缓解
NVFP4 在扩散上的公开验证稀少高现有 FP4 扩散证据集中在 FLUX PTQ/QAT、SANA-Video、Sol-RL；「从零 NVFP4 预训练 DiT」目前无公开报告。必须靠 P0 自测
CFG 引导放大残留纹理高只在初始化阶段用 CFG，之后去 CFG；或用 Decoupled-DMD 的 CFG 增强 + 分布匹配解耦
算术强度下降中小架构下 FP4 可能在访存受限层出现负收益。逐层 benchmark，这类层回退 FP8
SM120 无 tcgen05，吞吐只有数据中心卡 1/5中直接复用 CUTLASS sm120 kernel，不自己写；接受这个物理上限
32× latent 的文字/纹理上限中细节通道 32ch 兜底；文字渲染单独评估
v-pred 是 MSE 性质，易过度平滑中配合 4 步 refiner 与高频加强损失
LoRA 在 4-bit 路径静默失效中架构层保证注入点绕过量化器 + 训练时断言「关掉 LoRA 输出必须变」
⚠️ L1 条件轴「从未被任何判据检查」
v1.11 新增		高选层判据里没有 L1 的入口，而它承担 90% 需求。缓解：补「第零问」+ G3.5 探针；未验证的轴默认归 L3
⚠️ L1 在 FP4 下轴行程被压缩
v1.11 新增		高FP4 激活仅 16 个量化级，连续风格轴可能被抹平（旋钮转到一半就饱和）。与 E5 实测咬合，G0–G7 全未覆盖。缓解：G3.5 第四测 + Style-Pack 退路
L1 出错不可修（控制权在基座手上）
v1.11 新增		中高轴在基座内部，出问题只能重训主干；而 L3 可做谱检查、可重训包。缓解：设计律「控制权原则」——能显式写入的，就不要隐式请求

明确不做

✗ 不做 10B+ 参数
与低显存目标正交。20B Qwen-Image / 32B Flux.2 路线直接放弃
✗ 不做纯自回归 / VAR
KV cache 与串行 decode 与目标冲突；文本对齐系统性更弱（GenEval：Chameleon-7B 0.39 vs Flux.1-dev 0.82）
✗ 不做双流 MMDiT
LoRA 要打两套，参数效率低
✗ 不量化 VAE
参数量小、只跑一次、逐像素影响大。省不到显存还引入全局伪影
✗ 不做纯 RAE
不压缩的语义 latent 方向与低显存相反，只用它的思想
✗ 不缓存文本 embedding
省 5GB 但砍掉 prompt dropout 与文本侧 LoRA 训练能力
KokonaPolaris 架构设计方案 v1.0
所有显存数字为基于公开数据的估算，需实测校正。
