## 0. 一句话

**不管以后要接入什么能力，数据的格式只有一套。**
**你只需要交 3 项：图片 + 文字描述 + 分类标签。其余全部由工程侧自动生成。**

> ⚠️ **这份规范是通用的**，不针对任何特定内容。画风、角色、材质、某个题材——**同一个插座，插什么由你决定**。

## 1. 项目是什么（先对齐定位，避免后续沟通错位）

### 1.1 一句话定位

> **KP（心夏北极星）是一个面向 8GB 消费级显卡、原生 4bit 的二次元文生图模型架构。**
> 卖点不是「参数更大」，而是**「小到能塞进 8GB，还能往上挂任何能力」**。

| 维度 | 答案 |
|---|---|
| 是什么 | **文生图（Text-to-Image）模型** —— 输入文字，输出图像 |
| 跑在哪 | **8GB 显存消费卡**（RTX 50 系那档）—— 第一性约束 |
| 主打 | **二次元 / 日系画风**；写实作为内置开关保留 |
| 差异 | 原生 NVFP4 + 单流 DiT + 32× 混合 latent + **能力总线（一套底座、无限挂件）** |

### 1.2 产品构成（**这是 KP 本体**）

```
KP 成品 = ① 文本塔（~220M 语言模型，自蒸馏）
        + ② DiT 主干（自研，0.6B / 1.5B）
        + ③ VAE（图像 ↔ latent）
        + ④ 可选能力挂件（按需加载）
```

**⚠️ 常见误解：「我们接了两个生图模型」—— 没有这回事。** 见下表。

### 1.3 零件 vs 工具（**最容易搞混的一层**）

| 名字 | 类型 | 角色 | 进产品吗 |
|---|---|---|---|
| **Sana 1.6B** | 生图模型 | **试件** —— 一次性，只用来验「4bit 会不会掉画质」 | ❌ 验完即弃 |
| **Z-Image-Turbo** | 生图模型 | **教师** —— 训练时出图当示范 | ❌ 只存在于训练期 |
| **DINOv3** | 视觉编码器 | **教师** —— 冻结，语义锚定（不出图） | ❌ 推理不需要 |
| **Qwen3-4B** | 语言模型 | **教师** —— 蒸馏出我们的 220M 文本塔 | ❌ 师傅走，徒弟留 |
| **Gemma2-2B / 220M 塔** | 语言模型 | **文本编码器**（文本 → 向量） | ✅ **进产品** |

> ⭐ **教师有三个，不只有生图模型**，而且**教师给的不只是「图」**：
> ① Z-Image → 出图与去噪轨迹；② DINOv3 → 语义特征对齐；③ Qwen3-4B → 文本表示。
> **为什么不能只看图？** 0.6B 的学生学 6B 的师傅，光看成品不够——还要看到师傅**每一步的手感**（中间特征与轨迹）。

> ⚠️ **「扔掉」的准确含义**：指**产品里不含它们**，不是「白学了」。本事留在学生权重里；教师**只需离线跑一次，不需常驻**。

## 2. 分工界线（**从第一天就存在，不因任何需求而改变**）

| 侧 | 谁 | 负责 |
|---|---|---|
| **架构侧** | 工程 | 过滤管线的**接口** · **擦除算子 `E`**（低秩矩阵，纯数学对象）· **账本格式与写入** · **可逆性验证脚本** |
| **数据侧** | 你 | **数据池的内容** —— 收集 / 制作 / 标注 / **边界划定** / 来源与许可 |

**关键性质**：架构侧做的东西**与「里面装了什么」完全无关** —— 像 USB 接口不关心你插的是键盘还是硬盘。
⇒ **不是「走到某一步被迫停手」，而是本来就分属两侧。**

**交接点 = 训练开跑前**：你把数据（含 manifest）交过来，接进通用管线。

## 3. 能力接入：**唯一的死线**

### 3.1 三层 deadline（**只有第 ① 层不可逆**）

| # | 要做的事 | 死线 | 错过怎么办 |
|---|---|---|---|
| **①** | 让能力**存在**于主干（喂进去） | **预训练开始前 · 数据管线定稿** —— **不可逆** | 只能重训主干；或永久走最贵的 ∥-Pack |
| **②** | 让能力**可逆地关掉**（擦除 + 记账） | 预训练**之后**、发布**之前**（依赖 ①） | ① 没做则无从谈起 |
| **③** | 让能力**部署时可开可关** | **任何时间** | 随时可做（加载挂件） |

**① 的日历位置 = P2 换主干 / G6 预训练**，是全案**最靠后**的几步之一。**现在离死线还很远。**

> ⭐⭐ **重要细化（v1.1 修正）：「预训练」是一个「窗口期」，不是一个「瞬间」。**
> 训练是**分阶段**的 —— **预训练 → 中训 → 后训**，每个阶段都能引入新数据。所以准确的说法是：
> **「越早进主干越便宜、越稳」**，而不是「错过某个瞬间就永久报废」。
>
> | 进场时机 | 代价 | 风险 |
> |---|---|---|
> | **早进（预训练）** | 最低 —— 数据直接参与学基础表征 | 最低 |
> | **晚进（中训 / 后训）** | 更高 —— 要额外算力 | 有**扰动已学能力**的风险（需更小学习率 + 更强正交约束） |
> | **完全不进** | 只能走挂件 ∥-Pack（最贵） | 天级 + 重训 |
>
> ⇒ **窗口期有几个月量级。你不需要今天就凑齐数据，也不需要一次交全。**

### 3.2 悖论的解法：**别决定「要不要」，只决定「要不要留门」**

| 方案 | 成本 | 将来想要时 |
|---|---|---|
| **喂了 + 显式擦除并记账** | **≈ 0**（多喂一部分数据 + 记一笔账） | **`E⁻¹` 秒级取反**，不训练、不伤其它能力 |
| **不喂** | 0 | 只能加并联助手 ∥-Pack：**天级 + 重训 + 可能掉画质** |

> **这是「期权」，不是「承诺」。** 买到的是"未来能一秒打开它的权利"，标价接近零。
> 账本躺在硬盘上**不占任何运行时开销**（门控默认 0）。

### 3.3 ⚠️ 留门的代价（**必须如实知道**）

1. **擦除可能有残留** —— 擦得不够干净，痕迹会渗到别的提示词上。
2. **擦得太狠会伤邻近能力** —— 擦除是低秩算子，动手过猛会波及语义相邻的方向。

**把关方式**：`E⁻¹∘E` 之后输出分布回到基线的 **KL 测试**。
⇒ **这是我们训练期间可以自测的，不依赖你。** 属**工程侧承担的技术风险**。

**技术依据**：擦除多为「引导式回避」而非销毁（arXiv 2505.17013）；安全子空间**有效秩 k≈6**（LoX）；闭式擦除 **22 秒**（CURE, NeurIPS 2025）。**因为我们自己做数据过滤 ⇒ 我们知道擦了什么**（这是社区做不到的）。

## 4. ⭐ 数据交付规范（**核心章节**）

### 4.1 你必须准备的 —— **3 项，不多不少**

| # | 项 | 要求 |
|---|---|---|
| **1** | **图片** | 格式 PNG / JPG / WebP；**短边 ≥ 1024 px**（我们 latent 是 32× 压缩，1024² → 32×32；低于 1024 会被二次浪费）；**不要水印、不要字幕条、不要边框**（除非那正是你要训练的内容） |
| **2** | **文字描述 caption** | 中 / 英文皆可，**一句话到一段话**。建议覆盖：**主体 + 动作 + 构图/视角 + 场景 + 风格** |
| **3** | ⭐ **分类标签 `tag`** | **关键项**：标明这条数据属于哪个能力维度。**这是擦除账本能定位的唯一依据 —— 没有 tag 就无法「留门」，只能全丢。** |

### 4.2 目录组织

```
D:\model\data\<批次名>\
├── images\
│   ├── 0001.png
│   ├── 0002.jpg
│   └── ...
└── manifest.csv
```

**manifest.csv 格式**（前 4 列表头固定，逗号分隔，含逗号的字段用双引号包住）：

```csv
file,tag,caption,source,character,view,pose
0001.png,类别A,"一名角色站在雨中，全身构图，冷色调，日式动画风格",自摄,kokona,front,stand
0002.jpg,类别A,"同一角色背面，与正视图同姿势，室内暖光",自绘,kokona,back,stand
```

| 列 | 必需 | 说明 |
|---|---|---|
| `file` | ✅ | 图片文件名（相对 `images/`） |
| `tag` | ✅ | **分类标签**（同批次内自定名，但**必须能区分"要不要擦"的那些**） |
| `caption` | ✅ | 文字描述 |
| `source` | 建议 | 来源 / 许可备注（便于合规追溯） |
| `character` | 可选 | 角色标识（缺省回落到 `tag`）。**角色卡线用它分组** |
| `view` | 可选 | 视角（如 `front`/`back`/`left`/`right`）。⭐ **角色卡配对的关键列** |
| `pose` | 可选 | 姿态标识（如 `stand`/`sit`）。**配对时要求"相同"**，这样才是"只动视角" |
| `shader` | 可选 | 着色器 / 渲染风格标识（四旋钮之一，用于风格线的正交监督） |

> ⭐ **轴列（`character`/`view`/`pose`/`shader`）必须由渲染器或生成脚本填写，不要手工敲。**
> 它们不是"额外的标注负担"——**渲染器本来就知道视角**，生成脚本本来就知道提示词，
> 顺手写进 manifest 即可。
>
> ⚠️ **为什么不能靠文件名猜**：早期版本靠文件名里有没有 `front` 来判正视图。
> 这是**猜**——一旦数据线换命名（渲染器导出、批量生成、别处拿来的图），
> 猜测会**静默给出错误的配对**，而错误配对直接污染 Fitter 的训练目标，比报错难查得多。
> ⇒ 现在的规则是：**有声明就用声明；没有声明就明说没有**。
>
> 配对报告（`python -m kp.character.pipeline --pairing --target-views front,back,left,right`）
> 会直接告诉你**还缺哪些视角**（"该补拍什么"）。

> 校验器：`python tools/data_spec/validate_manifest.py --dir D:\model\data\<批次名>`
> 它会检查：目录结构、manifest 列名、文件是否存在、**短边分辨率**、**重复率（感知 hash）**、caption 缺失、tag 分布。
> caption 语言与形态另由 `audit_captions.py` 把关（§4.8.1）。

### 4.3 我们自动生成的（**你完全不用管**）

| 自动生成项 | 用什么 |
|---|---|
| 姿态 / 景别 / 构图 | 现成人体与姿态估计模型 |
| 深度 / 法线 | 现成几何估计模型 |
| 分割掩码 / 部件 | 现成分割模型 |
| **DINOv3 语义特征**（语义通道对齐） | 训练时在线计算 |
| 质量打分与过滤（模糊 / 低信息量） | 自动流水线 |
| **感知去重** | 自动流水线 |
| 分辨率分桶 | 自动流水线 |
| 人脸 / 人体检测 | 自动流水线 |

> ⛔ **严禁给你派人工标注任务**。分层 / 掩码这类如果靠人工，**成本会失控**——全部自动。
> **你的活止于「给图 + 一句话 + 打一个标签」。**

### 4.4 三条硬提醒

1. **同一个东西不要给多份** —— 我们会做感知去重，但源头去重更省时间。
2. **分辨率宁高勿低** —— 短边 1024 是及格线；低于它，那部分信息在 32× 压缩里会被丢掉。
3. **来源与边界由你这一侧确认** —— 这是分工，不是推诿：这批数据会**进产品权重**，且**预训练一旦开始，「喂过」这个事实就固定了**（对应 §3.1 的唯一死线）。

### 4.5 首批试点与验收

**分两级，别一次凑齐：**

| 级别 | 规模 | 目的 |
|---|---|---|
| **第一级 · 先打通管线** | **50–100 张** | 只要够跑通「格式校验 → 入库 → 编码」全流程即可 |
| **第二级 · 看覆盖度** | 500–2000 张 | 判断概念覆盖度与标签可分性，据此定最终规模 |

| 步骤 | 谁 | 产出 |
|---|---|---|
| ① 交第一级小批 | 你 | `data/<批次名>/`（**50–100 张就够起步**） |
| ② 跑可用性检查 | 我 | 格式校验报告：**目录/列名/分辨率/重复率/tag 分布/caption 质量** |
| ③ 给建议规模 | 我 | 依据真实数据给出**建议规模**，而不是拍一个假数字 |
| ④ 分批补齐 | 你 | 按建议规模分批交，**每批都独立可用** |

> ⚠️ **数据池是增量累积的，不是一次交齐。**
> 你有多少先交多少；缺的部分标成「待补」，**中训 / 后训阶段还能继续进**（见 §3.1 的「窗口期」说明）。
> **不要为了凑齐而卡住整个项目 —— 先喂能拿到的。**
>
> **关于「量」的现实提醒**：一张图生成几十秒，听起来要「等」，但那是**机器在等，不是你在等**。
> 批量任务是**无人值守**的（挂上去 → 去做别的事 / 睡觉 → 醒来看结果）。**需要的是一个批处理任务，不是一个团队。**

### 4.6 你已有的资产怎么用（**不是混乱，是资产**）

| 已有资产 | 能否迁移到 KP | 能用来干什么 |
|---|---|---|
| **本地某个 WAI 系模型** | ❌ 不能（架构、latent 全不同） | 作为**风格 / 角色数据的生产工具**（由你自己运行） |
| **你自己训的角色 LoRA** | ❌ **不能直接迁移** | ⭐ **生产「角色卡」所需的配对数据** —— 同一角色、多视角、同一身份（P2.6 / G5 的输入） |

**两个要点：**

1. **LoRA 不能跨模型迁移** —— 硬事实：LoRA 是**绑死在特定权重 `W₀` 上**的，换权重即失效（这正是主文档「Δ-Pack 必须建在 `W₀` 子空间」那条设计的由来）。
   **但这不是浪费** —— 它证明你**已经在做「能力挂件」这件事了**；KP 只是把它做成 **标准化 / 秒级 / 可跨版本**。
2. ⭐ **它是角色卡数据线的现成引擎**：同一角色、同一 LoRA，**只换视角与姿势** → 天然的多视角配对数据。
   - 产出：`data/<角色名>/{front, back, left, right, 3q}.png` + 身份标注
   - 用途：**G5 角色卡 / P2.6 Character Fitter**
   - ⭐ **这条线现在就能开跑**：不依赖 KP 代码、不依赖量化、不依赖任何其它前置 —— **它只依赖你手上已有的东西。**

### 4.7 为什么「加标签就触发」不可迁移 —— 以及 `tag` 的真正用途

**你的观察是对的：在别的模型上能触发，KP 上不会。原因不是「没训到位」，是机制根本不同。**

**「标签触发」是三样东西的联合产物：**

| # | 成分 | 说明 |
|---|---|---|
| 1 | **词嵌入** | 文本塔把那个 tag 编码成什么向量 |
| 2 | **条件通路** | 该向量如何在主干里传播、被哪些层消费 |
| 3 | **共现统计** | 训练时「该 tag ↔ 该类内容」的耦合强度 |

在某个模型 + 某个 LoRA 上，这三样是**已经耦合好的一个整体**。搬到 KP，**三样全变** —— 所以标签不会触发同样的东西。

⇒ **两条推论（都很硬）：**
- ❌ **不能靠"复现标签"来复现能力** —— 换了主干、换了文本塔，标签的语义要**重新建立**。
- ❌ **也不能把别的模型的输出当"真值"** —— 它带着那个模型的偏差，以及那个 LoRA 自身的缺陷（数据极少 → 学到的方向不干净 → 极端输入下行为怪异）。

> ⚠️ 顺带印证一条设计结论：**LoRA 数据极少会学到不干净的更新方向**（对应主文档的「入侵维度」问题）。
> 这正是 KP 里「Δ-Pack 必须建在 `W₀` 的 SVD 子空间内 + 训练后做**谱检查**」那条约束的由来 ——
> **不干净的 LoRA 不是"训得不好"，是方法本身的固有性质。**

#### ✅ 正解：不复制「标签触发」，而是建 KP 原生的「显式条件轴」

| | 标签触发（旧路） | **显式条件轴（KP 路线）** |
|---|---|---|
| 机制 | 靠自然语言 tag 的**共现统计** | 靠**结构化的条件维度** |
| 可标定 | ❌ 不可（黑盒） | ✅ 可（逐维命名） |
| 可审计 | ❌ | ✅（Axis Probe 四测） |
| 出错时 | 只能重训 | 可定位、可回滚 |
| 对应设计律 | 隐式**请求** | 显式**写入** |

#### ⭐ 于是 `tag` 这一列是**一鱼两吃**

| 用途 | 说明 |
|---|---|
| **① 擦除账本定位** | 标出哪些数据属于「要擦」的那一类 |
| **② 条件轴的训练标签** | 训练时把 `tag` 映射到条件维度上 —— **将来拨这根轴就能触发** |

> ⇒ **`tag` 不是随手写的备注，它是「标签 → 条件轴」这条通路的原始材料。**
> **写得越规范、越一致，将来在 KP 上「拨动即可触发」就越可靠。**

**把关门 = G3.5 Axis Probe**（单调性 / 正交性 / 可逆性 / **低比特可用行程**）。

- ⚠️ **「加标签立刻触发」正是「单调性」这一测的特例。**
- ⚠️ **诚实提醒**：**低比特下轴的分辨率受限**（FP4 激活只有 16 级 E2M1）→ **"秒级秒触发"不是零成本，代价在低比特下更大。** 这正是 G3.5 存在的理由。

### 4.8 caption 用什么语言写 —— **中文优先**

**结论：中文优先，保留少量英文做跨语言对齐。** 这不是偏好问题，是**架构决定**的。

| | SDXL 时代 | **KP** |
|---|---|---|
| 文本塔 | **CLIP**（英文图文对比学习） | **~220M 语言模型**（自 Qwen3-4B 蒸馏，多语言） |
| 中文 | 基本是噪声（语料里没见过） | **天生支持** |
| 输入风格 | 逗号标签串（tag soup） | **自然语言句子** |
| 「标签」的角色 | 用户要写的**输入咒语** | 内部**条件轴的训练标签**（由工程侧处理） |

- **为什么 SDXL 必须全英文**：它的文本塔是 CLIP —— 用**英文图文对**对比学习出来的词向量表，中文 token 基本没被训过 → 等于噪声。
- **为什么 KP 可以中文**：文本塔的**教师是多语言语言模型**（Qwen3-4B），中文是它的原生能力；蒸馏时**刻意保留**即可。
  ⇒ **「能理解语言」和「认识英文单词」是两回事** —— LLM 塔走的是前者，CLIP 走的是后者。

> ⚠️ **但中文能力不是白送的** —— 它还取决于**训练数据里中文 caption 的占比**。所以这**是个可调的旋钮，要主动设计**（而不是"反正模型支持"）。

> ⭐⭐ **这是一条硬要求，不是偏好（2026-10-03 用户明确）**：KP **必须从底层就支持中文自然语言描述**。
> - ⇒ 已写入**正式路线图条目 P1.8**（主文档 §9.1），**与 P2 换主干同批**。
> - ⇒ 它不是"以后加个功能"，而是**「预训练前数据管线定稿」的一个子项** —— 定稿后**不可逆**（与「能力接入」共享第 ① 层死线）。
> - ⇒ **工程侧对应件**：文本塔（`kp/models/text_tower.py`）的多语言词表 + 蒸馏时**刻意保留**中文；**数据侧对应件**：**caption 中文优先**（就是下面三条建议）。
> - ⚠️ **反面教材**：不要为了"保险"退回「纯英文标签串」——那等于**主动放弃** KP 相对 SDXL 的最大语言优势（详见 §4.7：标签触发本就不可迁移）。

**给你的三条建议：**

1. **caption 用中文写** —— 母语描述最准确、信息量最大。
2. 保留 **10–20% 英文 caption**（做跨语言对齐，便于将来接英文提示词）。
3. ⚠️ **不要写成「逗号标签串」** —— 写成**通顺的一句话 / 一小段话**（KP 的塔是语言模型，不是词袋）。

**一句话**：SDXL 里 tag 是「**输入**」；KP 里 tag 退到「**内部标注**」，**用户面对的是自然语言**。

#### 4.8.1 可执行判据 —— `audit_captions.py`（v1.3 新增）

上面三条建议**不能只停在纸面**：配比一旦进了预训练就**改不动了**，所以它必须**有可跑的守门人**。

```bash
# 审一个交付批次（读 manifest.csv 的 caption 列）
python tools/data_spec/audit_captions.py --dir D:\model\data\<批次名>

# 顺便看「还差多少条」
python tools/data_spec/audit_captions.py --dir ... --plan 2000

# 出 JSON 报告给下游
python tools/data_spec/audit_captions.py --dir ... --json out/caption_audit.json
```

**判据（`kp/config.py` 的 `CAPTION`，全是可调旋钮）**：

| 项 | 目标 | 含义 |
|---|---|---|
| 中文占比 | **80%**（可接受 70–90%） | 低于下界 = 白白丢掉 LLM 塔的原生优势 |
| 英文对齐占比 | **8–22%** | 低于下界 = 英文 prompt / 跨语言泛化退化 |
| 日文占比 | ≤ 15% | 日系画风需要日文，但不宜反客为主 |
| 中英混排 | ≤ 25% | 混排会让塔学到"同句切语言"的**伪相关** |
| 标签串 | **禁止**（得分 ≥ 0.6 判违规） | 见 §4.7：标签会退回"不可迁移的隐式通路" |
| 字数 | 8–300 | 过短信息不足、过长稀释 token 预算 |

**「标签串」怎么判**（不硬编码任何具体标签词，避免过拟合到某个社区的写法）：
被分隔符切出的片段**多且短** + 分隔符**密集** + **无句末标点** + **无虚词/连接词** ⇒ 判为标签串。
（全角句末标点直接算；半角只认**行尾**的 `.`/`!`/`?` —— 否则 `8k.` 这类结尾会骗过检查。）

**语言判定用「词数」不用「字母数」**：`少女穿着白色 dress 站在海边。` 里拉丁字母数会压过汉字数，
但在语义上它仍是**中文 caption**。按字母数判会误判成 mixed，从而**错误触发"混排偏高"告警**。

**汉字覆盖统计**：报告会列出这批语料里**出现过的不同汉字**（去重并集），
用于对文本塔 tokenizer 的词表覆盖把关 —— **没出现过的字，塔学不到**。

> ⭐ **一句话**：这条检查的价值不在"报告好看"，而在于它是**不可逆死线前唯一的刹车**。

## 6. 交接清单（checklist）

- [ ] **数据格式**：`images/` + `manifest.csv`，列名 `file,tag,caption,source`
- [ ] **图片**：短边 ≥ 1024，无多余水印 / 字幕条

- [ ] **tag**：每张都有，且**能区分"要不要擦"的那一类**
