# 第一部分：底模到底该怎么选

## 1.1 先把概念对齐

你说的「底模」，在不同语境里可能是三件不同的事：

| 理解 | 含义 | 你的方案需要吗 |
|---|---|---|
| **(a) 起点权重** | 我从它的权重开始继续训练 | ❌ **要不了** |
| **(b) 教师** | 我从它学，但不继承权重 | ✅ 需要，而且是唯一需要的 |
| **(c) 风格来源** | 画风、审美从哪来 | ✅ 需要，但这归到 (b) 里了 |

**关键结论：你的架构是全自研的，所以 (a) 这条路在数学上就不存在。**

## 1.2 为什么「继承权重」这条路不存在

用最直观的方式说清楚。你设计里的三处改动，每一处都会让已有权重**全部作废**：

**改动一：换 VAE**

你把 latent 从 SDXL 的 `f8/4ch` 换成 32× 压缩的混合 latent（语义 8ch + 细节 32ch）。

想象一下主干的第一个卷积层，它原本看到的是"128×128×4 个数值，数值范围大概 -4 到 4"。换完之后它看到的是"32×32×40 个数值，而且前 8 个通道是 DINOv3 语义特征（范围完全不同）、后 32 个通道是重建 latent"。

这两组数值**没有任何对应关系**。不是"需要微调"，是"完全无效"——就像你拿着一本中文词典去读德文，一个字都对不上。

**改动二：换文本塔**

从 T5-XXL（4096 维、512 token）换成 220M 蒸馏塔（可能 1024 维、多层聚合）。条件分布也变了，主干的 cross-attention 里 K/V 的统计特性完全不同。

**改动三：换主干**

UNet → 单流 DiT。连层的拓扑都不一样了，权重连"位置"都没有，谈不上搬。

> **所以：只要你的架构有任一实质性创新，就必然是从零初始化。**

## 1.3 这其实是好消息

听起来很残酷，但换个角度：

**你自由了。你不受任何底模的架构约束。**

- 不用管 SDXL 的 latent 是什么形状
- 不用管 Flux 的双流是怎么排的
- 不用管人家的文本塔多少维

你可以纯粹按"低显存 + LoRA 友好"这两个目标去设计，不用向任何已有架构妥协。

**代价只有一个：算力。** 我们后面说的"落地路线"（P0→P4）就是为了把这个代价压到你可承受的范围。

## 1.4 那「底模选择」到底在选什么

既然权重继承不了，底模对你只剩下一个作用：**教师（teacher）**。

于是选择标准变了：

> ❌ 不是「哪个底模好」
> ✅ 而是「**哪个教师能让我蒸馏出最强的 student，并且许可证允许我分发**」

## 1.5 限制只有三条（这才是「有没有限制」的答案）

### 限制一：许可证 —— 唯一的硬墙

| 许可证 | 代表模型 | 商用 |
|---|---|---|
| **Apache 2.0**（无任何限制） | **Z-Image / Z-Image-Turbo**、**Sana**、**Lumina-Image 2.0**、**Qwen-Image**、FLUX.1 [schnell]、FLUX.2 [klein] **4B** | ✅ 随便用 |
| CreativeML Open RAIL++-M | SDXL / SD1.5 | ✅ 可商用，有使用条款约束 |
| Stability Community License | SD 3 / 3.5 | 🔺 年收入 < 100 万美元免费 |
| **Non-Commercial** | **FLUX.1 [dev]**、FLUX.2 [klein] **9B**、FLUX.2 [dev] | ❌ 不能做产品/付费服务 |

> ⚠️ **一个容易踩的坑：FLUX.2 [klein] 的 4B 是 Apache 2.0，9B 却是 Non-Commercial。同名不同命，别看名字。**

**对你的意义：**
- 如果**只自己用** → 许可证不构成限制，FLUX.1 [dev] 随便当教师，它是目前最好的视觉教师之一。
- 如果**要发布 / 商用 / 给人用** → 教师必须在 Apache 2.0 白名单里。这时 Z-Image-Turbo 是最优选。

### 限制二：Latent 空间兼容性

教师和 student 的 latent 必须能对齐。如果不能，蒸馏之前得先训一个 bridge（额外的训练成本 + 精度损失）。

**这也是我为什么把混合 Latent 的语义通道对齐 DINOv3。**

DINOv3 是所有教师共享的「公共语言」：
- 不管教师是 SDXL、Flux 还是 Z-Image 生成的图
- 都可以用**同一个冻结的 DINOv3** 编码成对齐目标

→ 这让**教师选择变得可替换**。你以后想换教师，只要重新生成一遍数据就行，架构不用动。

这是主设计里那个"混合 Latent"决定的隐藏价值：它不只是省显存，它还是**多教师蒸馏的接口**。

### 限制三：算力

好消息：教师只需要**离线跑一次**来生成蒸馏数据，不需要常驻在你的 8GB 卡上。

- 12B 教师在 8GB 卡上 4-bit + offload，一张图几十秒是完全可行的
- 跑 5 万张大概要几天到一周（可以慢慢跑，挂着就行）
- 生成完之后，教师就再也不需要了

**这个成本是可以接受的。**

## 1.6 我的具体选择

| 角色 | 选择 | 为什么是它 |
|---|---|---|
| **主教师**（视觉质量） | **Z-Image-Turbo**（6B，Apache 2.0） | 开源最强质量/速度比；Artificial Analysis ELO 1152，超过 32B 的 FLUX.2；许可证干净；6B 规模蒸馏成本可控 |
| 质量上限参照（仅离线对照，不参与分发） | FLUX.1 [dev]（12B，Non-Commercial） | 它是目前最好的视觉教师之一，只用来做离线对照和"最后一档"蒸馏；不碰许可证红线 |
| **语义锚定** | **DINOv3**（冻结，不训练） | 混合 Latent 的公共语言 + REPA 目标，跨教师通用 |
| **文本教师** | **Qwen3.5-4B-Base** → 蒸馏到 ~220M | Z-Image 已经验证它对中英文字形与指令遵循有效 |
| **少步教师** | ⚠️ **不要直接抄 Z-Image-Turbo 的 8 步** | 它自己就是蒸馏产物。链式蒸馏会累积失真。应该从**我们自己的 BF16 teacher** 重新做 Decoupled-DMD → rCM |

## 1.7 「flux 代表未来，结合一点」—— 借什么、不借什么

你这句话我同意，但要精确到部件级别。

**值得借：**

| 部件 | 怎么借 |
|---|---|
| **Rectified Flow 目标** | 直接采用（主设计里已经是了）。它是 Flux 最根本的贡献 |
| **双流 → 单流的过渡结构** | 浅层（前 4–6 个 block，此时分辨率最低）保留 **double-stream**，让文本与图像各自有一套权重再交叉交互；深层全部 single-stream。**这样既拿到 Flux 的文本对齐优势，又保持单流主体对 LoRA 友好** |
| **Schnell 的 LADD 蒸馏经验** | 参考它怎么把 20–50 步压到 1–4 步 |

**不要借：**

| 部件 | 为什么不借 |
|---|---|
| 12B 规模 | 与低显存目标直接冲突 |
| T5-XXL 文本塔 | 单独占 9.8GB，是 Flux 在 8GB 卡上必须 offload 的主因 |
| 全栈双流 | LoRA 要打两套 block，训练与调参成本翻倍 |
| Non-Commercial 许可 | 除非你只自己用 |

> **一句话：借 Flux 的「思想」，不借它的「体积」。**

# 第二部分：注意力为什么会涣散

## 2.1 一句话说清病根

> **Softmax 是「分蛋糕」：总概率永远是 1。人越多，每个人分到的越少。**

SDXL 的 cross-attention 里，图像 token 当 query，文本 token 当 key/value。softmax 会把所有文本 token 的注意力权重**归一化到总和恰好等于 1**。

你写 10 个有效词，它们要去跟 BOS、EOS、标点、以及一堆无意义的 token **抢这 1 块蛋糕**。写得越长，有效词分到的份额越小 → 模型「听到了但没听清」→ 开始乱画。

**这不是 SDXL 的 bug，是 softmax 的数学性质。** 任何用 softmax 的模型都有这个问题，只是 SDXL 的"盘子"特别小，所以最先崩。

## 2.2 SDXL 的三重叠加

### 第一重：77 token 的硬上限

- SDXL 用**两个 CLIP**（CLIP-L + OpenCLIP-bigG/14），**各自 77 token 上下文，实际可用 75**。
- 文本条件 = 两个编码器输出的通道拼接：`c = concat(h_L, h_G) ∈ R^{77 × 2048}`
- 超过 75 的部分怎么办？UI（ComfyUI / A1111）会**每 75 token 切一块，分别编码再拼起来**。
  - 但 SDXL **训练时从没见过这种长文本**（分布外）
  - 而且**跨 chunk 的注意力是断的**——chunk 边界两侧的 token 互相看不见
  - 所以 chunking 有时候比直接截断还糟
- 最阴的是：**截断是静默的**。UI 不会报错，你只会发现"我明明写了，图里没有"。

> 你说的「空间实在太小了」——完全准确。`77 × 2048` 就是 SDXL 的全部条件空间。

### 第二重：Softmax 稀释（上面那张图）

### 第三重：CLIP 本身是「概念袋子」

- CLIP 的预训练目标是**整句图文匹配**（对比学习），不是细粒度组合理解。
- 它对"红球在蓝方块左边"这种**空间关系基本无感**——因为对比学习只需要"这句话大致描述这张图"，不需要精确的方位。
- 这就是为什么后来大家都往文本塔里塞 T5 或 LLM：
  - Flux：T5-XXL **512 token** + CLIP 77
  - SD3.5 Large：T5-XXL **256 token** + CLIP-L + CLIP-G 各 77

## 2.3 硬数据：问题有多大

**T2I-CompBench**（组合能力基准，满分 100）：

| 模型 | Color | Shape | Texture | **Spatial** | Complex | 平均 |
|---|---|---|---|---|---|---|
| SD 1.5 | 37.6 | 37.1 | 41.9 | **11.7** | 30.5 | 31.8 |
| **SDXL-base-1.0** | 58.8 | 46.9 | 53.0 | **21.3** | 32.4 | **42.5** |
| PixArt-α | 66.9 | 49.3 | 64.8 | 20.6 | 34.3 | 47.2 |
| FLUX.1 | 74.1 | 57.2 | 69.2 | **28.6** | 37.0 | 53.2 |
| OmniGen2 | 77.6 | 51.6 | 70.9 | **39.3** | 37.1 | 55.3 |
| Bagel + R3-Refiner | 84.2 | 60.3 | 73.9 | **35.7** | 39.8 | **58.8** |

**这张表把你的痛点量化了：**

1. **SDXL 的 Spatial = 21.3，几乎是全场垫底**（SD1.5 才 11.7）。
2. 它的 Color 能到 **58.8**（不差！），但 Spatial 只有 **21.3**。
   → 这就是你描述的"**颜色管得住，位置管不住，东西一多就开始串**"。
3. **FLUX 也才 28.6**。空间关系是**所有模型都没解决**的问题，只是 SDXL 特别差。
4. 从 SDXL（42.5）到 FLUX（53.2）的提升主要来自 Color/Texture，**Spatial 只涨了 7 分**——加个大文本塔并不能治本。

> **结论：这确实是一块巨大的优化空间。而且它有成熟基准（T2I-CompBench / GenEval），可以量化验收。**

## 2.4 KokonaPolaris 的五层解法

### 解法一（治本）：不用 softmax 做归一化竞争

把注意力里的 softmax 换成 **Sigmoid** 或 **Softpick**：

| 类型 | 公式 | 行为 |
|---|---|---|
| Softmax | `softmax(QKᵀ/√d)` | 强制总和 = 1，**token 互相抢** |
| **Sigmoid** | `σ(QKᵀ/√d)` | 每个 query-key 对**独立**打分，**无归一化，互不干扰** |
| **Softpick** | `relu(exp(x)−1) / Σ relu(exp(x)−1)` | softmax 与 ReLU 之间的中间态，保留一点稀疏性 |

**效果：从「选出最重要的那一个」变成「同时考虑所有相关的」。**

### ⚡ 意外收获：这一招同时治好了 NVFP4 的痛点

这是我这次调研最有价值的发现，必须单独说：

> 研究表明，**Sigmoid / Softpick 这类改造过的注意力能做到接近零的 attention sink 率，并显著减少激活离群值（activation outliers）→ 让低比特量化显著更鲁棒。**

为什么这重要？

我们的 NVFP4 设计最怕的就是**激活离群值**——FP4 只有 15 个可表示的数值，一个巨大的 outlier 会把整块的 scale 拉爆，同块的其他值全被压成 0。这也是为什么 NVIDIA 的四件套配方里要有 RHT（随机 Hadamard 变换）去专门平滑 outlier。

**而 attention sink 恰恰是激活离群值的主要来源之一。**

所以换掉 softmax = 一举三得：

| 收益 | 说明 |
|---|---|
| ① 长提示不再被稀释 | Spatial 分数直接受益（你的核心诉求） |
| ② 激活离群值减少 | **NVFP4 精度提升，QAT 更容易收敛** |
| ③ 无归一化竞争 | 天然适配线性注意力，更省显存 |

**同一个改动，同时打中你的两个痛点。**

### 代价（要诚实说出来）

- ⚠️ **必须从零训练**，无法在预训练模型上改造 —— 无所谓，我们本来就是从零
- ⚠️ **可能和现有优化过的 attention kernel 不兼容** —— 需要自己写 Triton kernel（工作量可控）
- ⚠️ **过度平坦会损失「sharp attention」能力** —— 所以**不要全换**，保留极少量 softmax 锚点层

### 解法二（架构级，最值钱）：显式空间 token（Layout Tokens）

这是我觉得最有前景的一条：

```
现在（SDXL / Flux）：
   文本 token  ─── 一次性 cross-attention ──▶  图像 token
              （信息在一坨里，容易串味）

KokonaPolaris：
   文本 token  ──▶ [K 个布局 token] ──▶ 图像 latent token
                   ↑                  ↑
              路由层分配内容      2D 网格位置编码送达
```

具体做法：
- 序列里额外加入 **K 个可学习的「布局 token」**（比如 K = 16，对应 4×4 的粗网格）
- 文本 token 通过一个轻量**路由层**把信息分配给各个布局 token（名词→主体区，背景词→边缘区）
- 布局 token 带 **2D 网格位置编码**，把内容"送达"对应的图像 latent token

**本质是把「文本→图像」的一次性 attention，拆成「文本→布局→图像」的两段式路由。** 路径更清晰、更不容易串味，而且**显式引入了空间先验**。

### 解法三（性价比最高）：提示词编译器

模型改不动的话，**改输入**。用一个小 LLM 把用户的短提示**编译**成结构化表示：

```
用户输入：
  "赛博朋克少女在雨夜东京"

      ↓ 小 LLM 编译器（可离线，不占生成显存）

结构化输出：
  主体:  少女    属性: 青铜护目镜 / 湿发    位置: 画面中央
  环境:  涩谷十字路口        时间: 雨夜     光照: 霓虹反射
  背景:  悬浮广告屏(左上) / 磁浮车(右侧中景)
  风格:  电影感 / 浅景深
```

模型消费的是这个**结构化表示**，而不是原始的一句话。

Z-Image 已经有 Prompt Enhancer 在做类似的事。**这条对「低数据训练」尤其关键：结构化标注等于给模型提供了免费的空间监督信号。**

### 解法四（工程）：文本侧 KV 分组

把文本 token 按角色分组（名词短语 / 属性 / 风格 / 关系），组内和组间走不同的注意力路径，避免所有 token 挤在一个池子里抢。

### 解法五（后训练）：奖励筛选

T2I-CompBench 的原始论文就提出了 **GORS**（Generative model finetuning with Reward-driven Sample selection）——用组合能力的奖励信号筛出好样本再微调。**成本低、见效快，是投入产出比最高的一环。**

## 2.5 修订后的注意力设计

**v1.0 原设计**：`3 层线性 : 1 层 softmax`

**v1.1 修订为**：

```
每 4 层构成一个单元：
  ├─ 3 层  : Gated Linear Attention      （O(N)，省显存）
  └─ 1 层  : Sigmoid / Softpick Attention（非归一化，不稀释）

额外约束：
  · 全局不出现 softmax（仅在 patch embed 后的第 0 层保留一次，用于初始对齐）
  · 文本条件走独立的 K=16 个 layout token 路由（2D 网格位置编码）
  · 文本侧 KV 按角色分组，组间不共享注意力池

训练时的额外损失：
  · 布局 token 与真实空间布局的弱监督（可用 3D 合成数据的 bbox / depth 免费得到）
  · T2I-CompBench 风格的空间关系奖励（后训练阶段，GORS 式）
```

**验收指标（可直接量化）：**

| 指标 | 基线（SDXL） | 目标 |
|---|---|---|
| T2I-CompBench Spatial | 21.3 | **> 35** |
| T2I-CompBench 平均 | 42.5 | **> 55** |
| 长提示（>150 token）下的一致性 | 显著退化 | **不退化** |
