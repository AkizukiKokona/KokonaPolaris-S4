# KokonaPolaris 补充 13 · P1（训 VAE）的验收门

> 版本 v1.0 · 2026-10-04 · **门线由实测校准，不是拍脑袋**
> 关联：补充 12（G2 判据重写）、补充 14（8GB 单卡方案）

---

## 0. 为什么要有这道门

🔴 **一个结构性问题**：设计稿的验证门是 **G0–G7**，**七道门里没有一道覆盖 P1**。
但 `P1 → P2 → G6` 是**唯一必经链**（出图需要三者全通）——
⇒ **P1 缺自己的门 ⇒ 「P1 算不算做完」只能靠感觉。**

本文补上这道门。**门线用外部真 VAE 校准**（Sana 自带的 DC-AE），不是凭经验定。

---

## 1. 校准用的参照系

| 项 | 值 |
|---|---|
| 模型 | `mit-han-lab/dc-ae-f32c32-sana-1.0`（**Sana 自己就用它**） |
| 许可证 | Apache-2.0（可作基准） |
| 参数量 | **312.3M** |
| 压缩率 | **32×**（与 KP 相同 ⇒ 可比） |
| 位置 | `models/Sana_1600M_1024px_BF16_diffusers/vae` |
| 为何用它 | 同压缩率、同为「训练充分的真 VAE」、本地已有、Sana 产线在用 |

⚠️ **它是 32ch，我们 40ch（语义8+细节32）** ⇒ **只作相对参照，不作等式对照**。

---

## 2. 校准结果（2026-10-04 实测）

评估集 = 固化 2000 张 @512² 存盘、评估在 256²；各模型用**各自合适的后处理**（见 §5）。

| 指标 | 我们 base32 (17.6M) | 参照 DC-AE (312.3M) | 倍差 |
|------|-------------------|-------------------|------|
| L1↓ | 0.1124 | **0.0691** | 1.63× |
| PSNR↑ | 21.22 | **24.37** | −3.15 dB |
| SSIM↑ | 0.6610 | **0.7964** | −17.0% |
| edge↓ | 0.3198 | **0.2648** | 1.21× |
| **LPIPS↓** | 0.3446 | **0.0764** | **4.51×** |
| **rFID↓** | 168.14 | **11.80** | **14.24×** |
| *随机初始化（下限参照）* | 0.6723 | — | — |

### ⭐ 差距的**结构**才是结论
**像素层只差 1.63×，但感知层差 4.51×、分布层差 14.24×。**

⇒ ⛔ **P1 远未完成**（不是「差一点」）。
⇒ ⭐ **瓶颈不在「像素重建精度」，在「重建的自然度 / 分布对齐」。**
⇒ 这**解释了另一条实测**：4× 容量只换 1–3% 收益
   —— 容量不是杠杆，**「罚像素」这件事本身已在天花板**。
⇒ 下一步该投的是**度量空间**（预训练特征），不是参数或分辨率。

## 3. 门线（建议值，待跑完 tlpips 臂再校准一次）

| 指标 | 门线 | 依据 |
|------|------|------|
| **rFID** | **≤ 40** | 参照系 11.8；留 ~3.4× 余量。**这是主指标**（分布级，项目规范要求） |
| **LPIPS** | **≤ 0.15** | 参照系 0.0764；留 ~2× 余量 |
| L1 | ≤ 0.11 | 参照系 0.0691；我们已在 0.1124，**门线故意设在此** |
| PSNR | ≥ 21.0 dB | 已达到，**设为回归保护**（防改动把它弄坏） |
| SSIM | ≥ 0.65 | 同上 |

⛔ **rFID / LPIPS 是门；L1 / PSNR / SSIM 只作回归保护。**
理由：项目规范明确「逐像素指标**不可判画质**」，
而 §2 证明 L1 与真实画质的**相关性最弱**。

⚠️ 门线**不是**「必须超过参照系」—— 312.3M 在海量通用图上训过，
   我们 17.6M 在 34 万张上训 6 万步，要求持平不现实。

## 4. 怎么复现测量

```bash
source ./env.sh
"$KP_PY" -u -m kp.train.vae_eval \
  --eval-set out/eval/fixed2k_512 --size 256 \
  --ckpt out/vae/full338k_b32.pt \
  --ref-vae models/Sana_1600M_1024px_BF16_diffusers/vae \
  --include-untrained --batch 16 --device cuda \
  --out out/eval/report_p1_gate.json
```

**三铁律**（缺一则结论无效）：
1. **评估集必须固化共享**（`--make-eval-set`）—— 否则不可比。
2. **后处理必须各自合适**（`--post auto`）—— 见 §5。
3. **⛔ 不能用训练损失当指标**（自证）。评估器用**独立实例**。

## 5. 🔴 一个会把结论完全搞反的坑（务必读）

`evaluate_model` 原先对**所有**模型统一套 `tanh`。这对我们的 `HybridVAE` 是对的
（输出无界，训练时用 tanh 压回 [-1,1]）。
但 **DC-AE 输出本来就在 [-1,1] 附近**，再套 tanh 会**把输出压扁**：

| 后处理 | 输出范围 | 标准差 | L1 | PSNR |
|--------|---------|--------|-----|------|
| 原始 | [-1.315, 1.457] | 0.5672 | **0.0515** | **25.28** |
| 套 tanh | [-0.865, 0.897] | 0.4669（**−17.7%**） | 0.1265 | 21.73 |

⛔ 带着多余 tanh 评参照系 → 得到「参照系 L1 0.1474 vs 我们 0.1124」
⇒ **虚假地显示我们更好**。去掉后真相是 0.0691 vs 0.1124（**我们差 1.63×**）。

⇒ 通用教训：**比较不同来源的模型前，先确认「后处理/归一化」对双方都对**。
   一个 clip 的差异就足以把结论反转。

## 6. 过门后的退路

| 若 rFID 卡在 40–80 | 手段 |
|---|---|
| 感知损失不够 | 加 **GAN 判别器**（rFID 距参照系还有 14×，GAN 是标准手段） |
| 容量/分辨率不够 | 前面实测容量收益小；分辨率按 sweep 结论**先上 512²** |
| 就是**不足** | 换更大的参照目标（DC-AE 级训练量），或引入 teacher 蒸馏 |

⚠️ 但**不要在门线未过时先上 P2** —— 换一个更差的 latent 会让 P2 的结论全部失真。

## 7. 与其他门的关系

| 门 | 覆盖 | 与 P1 门的关系 |
|---|---|---|
| **G2** | 32× 混合 latent 的通道分离 | ⚠️ **G2 的真图结论必须等 P1 过门**（现在用的是未训练/小数据 VAE） |
| G4 | Matryoshka 分辨率 | 依赖 P1 提供多分辨率 latent |
| P2 | 换主干 | 依赖 P1 过门（latent 质量直接决定主干上限） |
