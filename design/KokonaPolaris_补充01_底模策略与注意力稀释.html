01底模到底该怎么选

先把概念对齐

你说的「底模」，在不同语境里可能是三件不同的事：

理解含义你的方案需要吗
(a) 起点权重我从它的权重开始继续训练要不了
(b) 教师我从它学，但不继承权重需要，且是唯一需要的
(c) 风格来源画风、审美从哪来归到 (b) 里
关键结论：你的架构是全自研的，所以 (a) 这条路在数学上就不存在。

只要架构有任一实质性创新，就必然是从零初始化。

为什么「继承权重」这条路不存在

你设计里的三处改动，每一处都会让已有权重全部作废：

改动一
换 VAE
从 f8/4ch 换成 32× 混合 latent。主干第一个卷积层原本看到的是「128×128×4 个数值，范围 -4~4」，换完后看到的是「32×32×40，前 8 通道还是 DINOv3 语义特征」。两组数值没有任何对应关系——不是「需要微调」，是「完全无效」。就像拿中文词典去读德文。
改动二
换文本塔
从 T5-XXL（4096 维 / 512 token）换成 220M 蒸馏塔。条件分布也变了，cross-attention 里 K/V 的统计特性完全不同。
改动三
换主干
UNet → 单流 DiT。连层的拓扑都不一样了，权重连「位置」都没有，谈不上搬。

这其实是好消息

你自由了。你不受任何底模的架构约束。

  • 不用管 SDXL 的 latent 是什么形状
  • 不用管 Flux 的双流是怎么排的
  • 不用管人家的文本塔多少维

你可以纯粹按「低显存 + LoRA 友好」两个目标去设计。代价只有一个：算力——落地路线 P0→P4 就是为了把这个代价压到可承受的范围。

于是选择标准变了

不是「哪个底模好」，而是「哪个教师能让我蒸馏出最强的 student，并且许可证允许我分发」

一个容易踩的坑

FLUX.2 [klein] 的 4B 是 Apache 2.0，9B 却是 Non-Commercial。同名不同命，别看名字判断。

对你的意义：只自己用 → 许可证不构成限制，FLUX.1 [dev] 随便当教师。要发布/商用 → 教师必须在 Apache 2.0 白名单里，此时 Z-Image-Turbo 最优。

限制二 · Latent 空间兼容性

教师和 student 的 latent 必须能对齐，否则蒸馏前得先训一个 bridge（额外成本 + 精度损失）。

这就是「混合 Latent 的语义通道对齐 DINOv3」的隐藏价值

DINOv3 是所有教师共享的公共语言：不管教师是 SDXL、Flux 还是 Z-Image 生成的图，都能用同一个冻结的 DINOv3 编码成对齐目标。

→ 这让教师选择变得可替换。以后想换教师，重新生成一遍数据就行，架构不用动。

限制三 · 算力

好消息：教师只需要离线跑一次生成蒸馏数据，不需要常驻在 8GB 卡上。

  • 12B 教师在 8GB 卡上 4-bit + offload，一张图几十秒完全可行
  • 跑 5 万张大概几天到一周（挂着慢慢跑就行）
  • 生成完之后，教师就再也不需要了

02注意力为什么会涣散

一句话说清病根

Softmax 是「分蛋糕」：总概率永远是 1。人越多，每个人分到的越少。

SDXL 的 cross-attention 里，图像 token 当 query，文本 token 当 key/value。softmax 会把所有文本 token 的注意力权重归一化到总和恰好等于 1。

你写 10 个有效词，它们要去跟 BOS、EOS、标点、以及一堆无意义的 token 抢这 1 块蛋糕。写得越长，有效词分到的份额越小 → 模型「听到了但没听清」→ 开始乱画。

这不是 SDXL 的 bug，是 softmax 的数学性质。任何用 softmax 的模型都有，只是 SDXL 的盘子特别小，所以最先崩。

方块 = 文本 token 示意（实际 77 个）；下方柱高 = 该 token 获得的注意力权重

SDXL 的三重叠加

第一重 · 77 token 的硬上限

  • SDXL 用两个 CLIP（CLIP-L + OpenCLIP-bigG/14），各自 77 token 上下文，实际可用 75。
  • 文本条件 = 两个编码器输出的通道拼接：c = concat(h_L, h_G) ∈ R^(77×2048)
  • 超过 75 的部分：UI（ComfyUI / A1111）会每 75 token 切一块，分别编码再拼起来。
    • 但 SDXL 训练时从没见过这种长文本（分布外）
    • 而且跨 chunk 的注意力是断的——chunk 边界两侧的 token 互相看不见
    • 所以 chunking 有时候比直接截断还糟
  • 最阴的是：截断是静默的。UI 不报错，你只会发现「我明明写了，图里没有」。
你说的「空间实在太小了」——完全准确

77 × 2048 就是 SDXL 的全部条件空间。

第二重 · Softmax 稀释（上面那张图）

第三重 · CLIP 本身是「概念袋子」

  • CLIP 的预训练目标是整句图文匹配（对比学习），不是细粒度组合理解。
  • 它对「红球在蓝方块左边」这种空间关系基本无感——对比学习只需要「这句话大致描述这张图」，不需要精确方位。
  • 这就是为什么后来大家都往文本塔里塞 T5 或 LLM：Flux 用 T5-XXL 512 token + CLIP 77；SD3.5 Large 用 T5-XXL 256 token + 两个 CLIP 各 77。

KokonaPolaris 的五层解法

解法一（治本）· 不用 softmax 做归一化竞争

类型公式行为
Softmaxsoftmax(QKᵀ/√d)强制总和 = 1，token 互相抢
Sigmoidσ(QKᵀ/√d)每个 query-key 对独立打分，无归一化，互不干扰
Softpickrelu(exp(x)−1) / Σ relu(exp(x)−1)softmax 与 ReLU 之间的中间态，保留一点稀疏性

效果：从「选出最重要的那一个」变成「同时考虑所有相关的」。

⚡ 意外收获：这一招同时治好了 NVFP4 的痛点

这是我这次调研最有价值的发现：Sigmoid / Softpick 这类改造过的注意力能做到接近零的 attention sink 率，并显著减少激活离群值（activation outliers）→ 让低比特量化显著更鲁棒。

为什么重要？我们的 NVFP4 设计最怕的就是激活离群值——FP4 只有 15 个可表示的数值，一个巨大的 outlier 会把整块的 scale 拉爆，同块其他值全被压成 0。这也是为什么 NVIDIA 的四件套配方里必须有 RHT 去专门平滑 outlier。

而 attention sink 恰恰是激活离群值的主要来源之一。

① 长提示不再被稀释
Spatial 分数直接受益 —— 你的核心诉求
② 激活离群值减少
NVFP4 精度提升，QAT 更容易收敛
③ 无归一化竞争
天然适配线性注意力，更省显存
同一个改动，同时打中你的两个痛点。
代价（要诚实说出来）

⚠️ 必须从零训练，无法在预训练模型上改造 —— 无所谓，我们本来就是从零。

⚠️ 可能和现有优化过的 attention kernel 不兼容 —— 需要自己写 Triton kernel，工作量可控。

⚠️ 过度平坦会损失「sharp attention」能力 —— 所以不要全换，保留极少量 softmax 锚点层。

解法二（架构级，最值钱）· 显式空间 token（Layout Tokens）

解法三（性价比最高）· 提示词编译器

模型改不动的话，改输入。用一个小 LLM 把短提示编译成结构化表示：

Z-Image 已经有 Prompt Enhancer 在做类似的事。这条对「低数据训练」尤其关键：结构化标注等于给模型提供了免费的空间监督信号。

解法四（工程）· 文本侧 KV 分组

把文本 token 按角色分组（名词短语 / 属性 / 风格 / 关系），组内和组间走不同的注意力路径，避免所有 token 挤在一个池子里抢。

解法五（后训练）· 奖励筛选

T2I-CompBench 的原始论文就提出了 GORS（Generative model finetuning with Reward-driven Sample selection）——用组合能力的奖励信号筛出好样本再微调。成本低、见效快，投入产出比最高的一环。

修订后的注意力设计

层类型说明
每 4 层中 3 层Gated Linear AttentionO(N)，省显存
每 4 层中 1 层Sigmoid / Softpick Attention非归一化，不稀释

额外约束：

  • 全局不出现 softmax（仅在 patch embed 后的第 0 层保留一次，用于初始对齐）
  • 文本条件走独立的 K = 16 个 layout token 路由（2D 网格位置编码）
  • 文本侧 KV 按角色分组，组间不共享注意力池

训练时的额外损失：

  • 布局 token 与真实空间布局的弱监督（可用 3D 合成数据的 bbox / depth 免费得到）
  • T2I-CompBench 风格的空间关系奖励（后训练阶段，GORS 式）
