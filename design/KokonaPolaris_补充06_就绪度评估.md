## 0. 结论先行

**设计准备好了；工程还没准备好。**

| 层 | 状态 | 就绪度 | 一句话 |
|---|---|---|---|
| **设计层** | ✅ 已收敛 | ~90% | 架构闭环、判据自洽、无逻辑缺口；剩下的是超参与消融 |
| **假设层** | ⚠️ 未就绪 | ~15% | 7 条关键假设里只有 2 条有旁证，**其中 2 条能推翻结构** |
| **实现层** | ❌ 未开始 | 0% | 0 行代码 |

> **判决：可以开工，但不能「照着文档直接开训」。**
> 正确的开工方式是把 7 条假设变成 8 道**带退路的门**（主文档 §9.2 / 本文档 §04），一关一关过。

为什么不是「全好了」？因为这方案里的东西分两类：

- **推导出来的**（第一性原理 → 结构）——**这部分已经封口**：比如「token 数是显存第一因」「ΔW 可以入侵底模、旁路不能」「LoRA 是加法，不是创造」；
- **赌出来的**（没有先例 → 只能自测）——**这部分一条都还没验**。别人问「凭什么」，我们现在只能答「凭推理」。

## 1. 命名：KokonaPolaris（心夏北极星）

### 1.1 已定下的部分

| 项 | 取值 |
|---|---|
| 家族名 | **KokonaPolaris** |
| 中文名 | **心夏北极星** |
| 缩写 | **KP** |
| 尺寸档 | **KP-S**（0.6B，主力）/ **KP-M**（1.5B，质量档）/ **KP-L**（3B，仅作 teacher，不发布） |

**名字里藏了一层双关**，这也是它比随机起名更合适的原因：Polaris = 北极星，而本架构里「对偶 / 极性」结构反复出现——

- **语义 · 细节** 双通道 latent（8ch + 32ch）
- **正 · 背** 对偶视图（你的核心训练方式）
- **擦除 · 恢复** 对偶算子（`E` / `E⁻¹`）

**一个名字同时说了「指引」和「对偶」两件事。**

### 1.2 后缀：已定为 `-S4`（附四个候选的取舍记录）

> **✅ 结论（2026-10-02，用户拍板）**：正式名定为 **`KokonaPolaris-S4`**。世代标签（如 `-G1`）等原型成型后再加。
> 理由：**两个字符装下两个最硬的差异点**（S = Single-stream 单流 / 4 = 原生 FP4）；有型号感、好念、易做版本化。

后缀唯一的作用是：**让人只看名字就知道它和 SDXL / Flux 不一样在哪。**
下面四个候选的取舍保留下来，作为**决策记录**——

| 候选 | 字母含义 | 第一眼传达 | 好处 | 代价 |
|---|---|---|---|---|
| **`-S4`** | **S**ingle-stream + native FP**4** | 「单流 + 原生 4-bit」 | 两个字符装下**两个最硬的差异点**；型号感强、好念、易版本化（可延伸 `KP-S4-S` / `S4-M`） | 需要解释一次才懂；可能被误读成「第 4 代」 |
| **`-DiT`** | Diffusion Transformer | 「这是个扩散 Transformer」 | **零歧义**；写论文 / 找别人看时最不容易被误解 | 不含增量信息（谁都知道是 DiT），**真正的差异点一个都没体现** |
| **`-Duo`** | 对偶（Dual） | 「这架构靠对偶结构吃饭」 | 与 Polaris 的极性双关；一次概括三组对偶；**品牌感最强** | 技术指向弱，不看文档猜不出是什么；易被当成「双卡 / 双模型」 |
| **`-Mod`** | Modular | 「可插拔、能一直挂包」 | 直接点出**全场最独特的差异点**（能力总线）；对使用者最直观 | 读起来像「模块化产品」而不是模型；没体现低显存 / 量化 |

**我的建议**：

- 想让名字**带信息**（推荐）→ `KokonaPolaris-S4`
- 想让人**一眼不误解**、偏学术正统 → `KokonaPolaris-DiT`
- 想让名字**有品牌辨识度** → `KokonaPolaris-Duo`

**也可以两段都用**：正式名 `KokonaPolaris-S4`；在论文 / 文档首次出现时写全——「KokonaPolaris-S4（单流 · 原生 FP4 的扩散 Transformer）」。信息量与清晰度都不丢。

## 3. 未验证假设登记表（这张表就是「准备好了没有」的真正答案）

| # | 假设 | 等级 | 现有证据 | 若为假的后果 |
|---|---|---|---|---|
| **A1** | NVFP4 **QAD** 在扩散 Transformer 上不掉点 | 🔴 结构性 | NVIDIA 在 FLUX 上 QAT 持平 / 微升、PTQ 掉点；**但无「从零预训练」报告** | 量化地基塌 → 整体回退 FP8 |
| **A2** | 32× 混合 latent 的**通道分离能被损失函数强制** | 🔴 结构性 | **无直接先例**（本方案自创） | L1 三层控制栈作废，画风解耦失效 |
| **A3** | **Sigmoid / Softpick** 注意力在长提示上更好、且对量化更友好 | 🟠 配方性 | LLM 侧有「零 attention sink」实证；扩散上未验证 | 退回 softmax，改用 layout token 补偿 |
| **A4** | **分辨率维度 Matryoshka** 与无位置编码主干兼容 | 🟡 配方性 | PostDiff 有实证，但不是我们的架构 | 关掉，只保留深度维度 Matryoshka |
| **A5** | **角色卡 + Fitter** 能从正 / 反两视图解出可用表示 | 🟠 配方性 | InstantCharacter 单图驱动外置适配器；See-through 2.5D 分层有先例；**「正反两视图 → 分层角色卡」这条具体路径无先例** | 退回 LoRA；角色卡降级为辅助条件 |
| **A6** | **Micro-budget 配方**在我们规模上可复现 | 🟠 配方性 | Sony AI：1.16B / 3700 万图 / \$1,890 / FID 12.7 | 改走逐层替换 |
| **A7** | **少步蒸馏** 4 步不塌 | 🟡 配方性 | 社区先例充分（sCM / MeanFlow / DMD2） | 保持 8–12 步 |

**分类的意义**：

- **A1、A2 是结构性的**——为假就得改架构，所以要最早验、优先验；
- **A3–A7 是配方性的**——为假只影响效果上限，可以边做边调。

> ⚠️ A1 有一个**反直觉之处**：它失效的代价并不大（退回 FP8 方案依然成立），但它**优先级仍是第一**。因为它一旦为假，**前面所有显存测算都要重算**。
> A2 则相反：它成立与否没人会立刻看出来，但它一旦为假，**「让 LoRA 只做长尾」这条主线就直接消失**。

## 4. 验证门 G0–G7

（与主文档 §9.2 同一张表，此处补上「判据为什么这么定」）

| 门 | 成本 | 通过判据 | 不过的退路 |
|---|---|---|---|
| G0 环境 | 1–2 天 | FP4 block-scaled matmul 数值正确、模型能加载 | 回退 FP8 |
| **G1 NVFP4 QAD** | 几天–1 周 | FP4 vs BF16 差距 < 2%，且 QAT 优于 PTQ | 回退 FP8 |
| **G2 通道分离** | 1–2 周 | 交叉扰动后结构指标降 < 5% | L1 作废，改单通道 latent |
| G3 Sigmoid 注意力 | 1–2 周 | 长提示 Spatial 更优、短提示不退化 | 退回 softmax |
| G4 分辨率 Matryoshka | 1 周 | FID 不劣 + FLOPs −30% | 关掉 |
| G5 角色卡 | 2–3 周 | 一致度接近 LoRA、换角色 < 1 秒 | 退回 LoRA |
| G6 Micro-budget | 数周 + ~\$2k | 零样本 FID 可接受 | 逐层替换 |
| G7 少步蒸馏 | 数周 | 4 步 ≈ 20 步的 90% | 保持 8–12 步 |

**为什么 G1 的判据定在 2%（而不是 0.5%）**：
FLUX 上的实测是——FP4 **PTQ** 会掉点（ImageReward 1.118 → 1.096，约 2%），FP4 **QAT** 不掉反微升（1.119）。所以 2% 正好是「**能不能只用 PTQ**」的分界线：差距落在 2% 以内说明 PTQ 就够，超过 2% 才**必须走 QAD**。这正是我们要判断的事，所以判据就定在这条线上。

## 5. 开工顺序（我的建议）

**两条腿走路，不开三线。**

```
主线   G0 → G1（NVFP4 QAD）      ← 几天出结论，唯一能推翻地基
副线   P2′（T0 排版链路）         ← 零训练、零依赖，立刻可见产出
```

**为什么这么排：**

1. **G1 必须先做**——它是唯一「如果塌了、前面所有显存测算都要重算」的东西。**先验地基，再盖楼。**
2. **P2′ 必须并行**——它**不与任何风险绑定**：不需要 NVFP4、不需要新主干、甚至不需要训练。哪怕主线全塌，它产出的（会排文本框的 Layout Planner + 字形合成数据管线）依然有用。**这是对冲。**
3. **现在不必碰 P2.6（角色卡）**——它虽然也独立，但本质属于 G5 的范围。等 G1 有结论、你确定要继续时再开，不会损失什么。

**如果你手上暂时没有 Blackwell 卡**：主线就换成 **P2′ + 文档**，先不碰 G0 / G1——硬件相关的结论模拟不出来。

## 6. 拿去给别人看时，对方最可能挑这六个问题（附我的回答）

> 这一节是为「我想拿去问别人」写的。**把这六个问题连同答案一起给他，能省掉一轮无效讨论。**

**Q1「为什么不直接微调 Z-Image / Sana / Flux，偏要从零？」**
因为三处改动**每一处都让已有权重作废**：换 VAE（latent 空间没有对应关系）、换文本塔（条件分布变了）、换主干（UNet → 单流 DiT，连拓扑都不同）。所以「站在别人肩上」在结构上不成立。成本侧有反证：Micro-budget 证明从零不是千万级（\$1,890 / 1.16B）。

**Q2「NVFP4 是不是伪需求？FP8 不够吗？」**
**这是最该被质疑的一点，也是我自己最不确定的一点。** 诚实地说：如果主要场景是 LoRA 训练，**激活显存会淹没权重差异**——1.5B 的 FP4 权重只占 0.84GB，激活才是大头。所以 NVFP4 的收益在**推理**上比在训练上明显。G1 存在的意义正是把这个分歧量化。

**Q3「32× 压缩一定丢细节吧？」**
会丢，这是信息论问题，不是训练问题。所以：细节由 32ch 细节通道兜底；**文字走独立低压缩 ROI 分支**（40px 汉字在 32× 下只占 1.25 个 latent 格，靠主干渲染在信息论上不可能）。

**Q4「通道分离真能训出来吗？」**
**不知道，这是全案最大的未验证设计假设（A2 / G2）。** 唯一能保证的是：不加显式监督，它**一定训不出来**——主干会图省事把两个通道都塞满。

**Q5「角色卡有先例吗？」**
有相邻先例（InstantCharacter 单图驱动外置适配器、See-through 的 2.5D 分层表示），**但「正 / 反两视图 → 1–5MB 分层角色卡 → 秒级换角色」这条完整路径没有直接先例。**

**Q6「8GB 卡训 1024² 角色 LoRA 是不是噱头？」**
目标是 4–5GB 峰值，依据是 token 数：32× 压缩后 1024² 只有 1024 token，激活与注意力成本按此量级估算。**这条同样依赖 G1 / G2 成立。**
