## 1. 参考图 / 空间控制：设计里到底有什么

### 1.1 三条对应件（对照常规 SDXL 生态）

| 常规生态 | 它承担的职责 | **KP 的对应件** | 成熟度 |
|---|---|---|---|
| **IP-Adapter**（参考图 → 风格/身份特征） | 外观特征注入 | **CharaBridge（内建）**：K 张参考图（K=2–8）→ **双分支解耦**：外观分支 + **几何分支**（预测 normal + depth + ray-pose → geometry token） | 设计级，未实现 |
| **ControlNet**（depth / pose / seg → 结构锁定） | 空间密集控制 | **条件包**（Adapter，**带分支**）——**§4.7.9 能力包清单里已经列了** | 设计级，且补充 02 明确标注：<br>「⚠️ 需要新增分支，**主干没有对应输入位，要加 encoder**」 |
| **img2img / inpaint / outpaint** | 局部编辑 | **编辑包**（Adapter，带分支） | 设计级，未实现；⚠️ 见 §1.2 的隐患 |

**所以不是一个"有 / 没有"的问题，是"在哪一层"的问题：**

- **参考图理解** → KP 是**内建且升级**的。IP-Adapter 只提取**外观**特征然后并联注入；CharaBridge 额外**解出几何**（normal / depth / ray-pose）。对二次元尤其占便宜——平面着色下几何条件信噪比高，几乎不受材质干扰（补充 04 §4.4）。
- **空间密集控制** → KP **有对应件但不在主干内**。这是有意的：主干的条件输入位只有「文本 + latent + 身份 token」，depth/pose 这类新模态要**挂一个带 encoder 的分支**。**它被设计成可插拔的外挂，不是主干的一部分。**

### 1.2 ⚠️ 一个必须先说清的隐患：40ch 混合 latent 会让 img2img 生态全部重写

主文档已经记过这一条，但值得在这里再强调一次，因为它正是"图生图"这个需求的直接拦路石：

> **下游 img2img / inpaint / 放大节点全部假设固定通道数（通常 4ch），我们的 40ch 混合 latent 需要重写。**

这不是"能不能做"的问题，是**现有的生态工具全部不通用**的问题。也就是说：即使我们做出了条件包，能直接用它的第三方工具也是零。**这决定了这条路线在早期没有任何生态杠杆可用。**

### 1.3 但你的直觉是对的：常规生态里 ControlNet 干的两件事，在 KP 里已经被拆走了

这是本节的要点。常规工作流里 **ControlNet 表面上在做"控结构"，实际同时承担了两个完全不同的职责**：

| 常规里 ControlNet 实际在承担的职责 | KP 里由谁承担 |
|---|---|
| ① **锁结构 / 锁姿态**（保持构图、不让构图跑掉） | **语义 8ch 通道（原生管结构）**——§4.2 明确写「语义通道承担"这是什么、在哪、**什么姿态**」<br>+ **Layout token**（§4.2，K=16 个可学习布局 token，4×4 粗网格 + 2D 位置编码，两段式路由）<br>+ 弱监督可直接复用 3D 合成数据的 bbox / depth（**零额外标注成本**） |
| ② **参考图定角色**（我要的是"这个角色"） | **角色卡 / CharaBridge**——给正反两图 → 前向 → 秒级出卡 |

**于是得到一个很干净的判断：**

> - **如果你只要「这个角色」→ 不需要 ControlNet**。走角色卡（秒级，不打架，跨版本可迁移）。
> - **如果你要「像素级锁死这个姿势、只换画风」→ 还是需要条件包**。而它是「**能做但贵**」（独立分支 + 天级重训），且早期没有生态可用（§1.2）。

**你说"这不是刚需，之前只是为了生成角色才要它"——这个判断在设计上是成立的**，因为角色那条路径已经被走通了（在机制层面），而且比 ControlNet 那条更干净。

### 1.4 结论：这条不进第一步

三条理由，每条都是独立的：

1. **不是刚需**（用户自己的判断，且设计支持）；
2. **成本档是"天级"**（§4.8 成本档：跨域/新模态 = 独立分支 + 重训）；
3. **有前置依赖**：它要挂在**能力总线的外挂加载框架**上（P1.5），那套框架现在还不存在。

→ **建议：写进 P3 之后的可选清单，不占当前预算。** 现在记下来只是为了"不忘记它存在、以及为什么不做"。

## 2. ⚠️ 你的警告：L1 过度依赖基座

### 2.1 最硬的证据：设计的「选层判据」里，L1 完全缺席

这是我在核查时发现的最关键一处。主文档 §4.8 的选层判据原文是：

```
第一问：底模见过这个分布吗？
   没见过 → 支撑集外扩 → L2 ∥-Pack（并联分支，需重训）
   见过   → 第二问
第二问：它被人为抑制过吗？
   是 → 恢复型 → 闭式算子 E⁻¹ / Δ-Pack（秒–小时）
   否 → 长尾型 → Δ-Pack（小时）
```

**注意：两问只在 L2 与 L3 之间分流。L1 完全没有出现在判据里。**

而 L1 承担的是——

| 层 | 覆盖需求 |
|---|---|
| **L1** | **约 90%** |
| L2 | 约 9% |
| L3 | 约 1% |

**也就是说：占比 90% 的控制路径，从来没有经过任何判据的检查。** 它被预设成"免费已得的能力"。

> 所以**你的说法还可以再加重一层**：这不只是"过度信赖"，而是「**从未检验**」。信赖至少隐含"我看过它表现"；而这里连看都没看过——**判据根本没为它设过入口**。

### 2.2 四条风险机制（逐条给物理图像）

#### 风险 1：覆盖率假设 —— "90%" 是**调用量分布**，不是**已验证能力**

L1 之所以能号称覆盖 90%，隐含要求：**主干的风格条件轴覆盖足够广**。（要求基座在预训练时见过足够多的风格轴，且它们被正确解耦）

**这是一个隐藏假设。** 而设计文档已经识别了一个同类假设——§4.8.5 的「通道分离退化」（如果只切通道不加监督，主干会偷懒，两个通道都塞满信息，L1 整个失效），并把它称为"**全案第二个隐藏关键假设**"（第一个是补充 02 的 NVFP4 QAD）。

**但漏掉了这一个。** 严格说它是**第三个隐藏关键假设**，而且它比第二个更外层：通道分离退化会让 L1 **失真**；覆盖率不足会让 L1 **直接不存在**。

#### 风险 2：隐式接口**不可独立验证，且不可修**

对比 L3（LoRA）——

| | L3（Δ-Pack） | L1（主干条件轴） |
|---|---|---|
| 本质 | **写入**（直接改权重，或改子空间系数） | **请求**（希望基座理解这个轴） |
| 可审计性 | ✅ 可做**谱检查**——补充 04 条目 17 已规定硬约束：「Δ-Pack 必须在底模的 SVD 子空间内构造；训练后做谱检查，**发现正交入侵维度即判定包不合格**」 | ❌ **无法独立检查**。只能靠出图间接看 |
| 出错后能否修 | ✅ 重训这个包（小时级），或直接不用它 | ❌ **修不了**——轴是基座内部的，只能**重训主干** |
| 控制权归属 | **我们** | **基座** |

> **这一列对比就是"过度依赖基座"的精确含义：控制权从我们手上转移到了基座手上，而且转移得无声无息。**

#### 风险 3：⚠️ 与 E5 实测直接咬合 —— 低比特下 L1 可能被"抹平"（本文件新增，且有实测背景）

这是本文件**唯一有实测数据支撑的风险**，而且它把两轮工作连起来了。

**E5 已实测**（真实 Sana 1.6B，15 例平均）：

| 配置 | noise_pred 相对误差 | 峰值位置 |
|---|---|---|
| W4A16 | 7.74% | — |
| **W4A8（设计档）** | **9.98%** | — |
| **W4A4** | **29.72%** | **t≈500 时冲到 35.4%（倒 U 形）** |

而且端到端出图证实：W4A4 的误差**表现为轨迹漂移**（固定种子下给出"另一个同样合理的样本"，构图变了但画质正常）。

**现在把这两件事放在一起看**：

> **L1 用的恰恰是一个低维、连续的控制信号。而量化噪声最可能摧毁的，正是这种信号。**

两个具体机制：

- **(a) 噪声被误读为控制信号**：控制向量和采样噪声住在**同一个隐空间**里。当量化把噪声预测打偏 30%，主干接收到的"这个 latent 应该往哪走"的信号里，混进了与风格轴同量级、但**方向随机**的成分。对 bf16 来说这一点点噪声不影响；但对一个靠**低维连续值**编码的风格轴来说，噪声本身就是**同量级干扰**。

- **(b) 分辨率压缩（更隐蔽，也更致命）**：FP4 的激活只有 **16 个量化级**（E2M1：1 符号 + 2 指数 + 1 尾数）。如果风格信息是**通过激活的精细结构**传递的（这是 L1 的"连续可调"所要求的），那么只有 16 级的量化会**系统性地压缩这个轴的分辨率**。
  → 外在表现不是"画错了"，而是：**旋钮行程变短、转到一半就饱和、或者中间一大段值给出同样的输出**。**功能还在，但"连续可调"这个 L1 的核心卖点消失了。**

**这个风险是可实测的，而且现有验证门 G0–G7 全部没有覆盖它。** 见 §2.3 方案 ②。

#### 风险 4：条件轴**互相耦合**（文档只处理了"通道退化"，没处理"轴耦合"）

§4.8.5 处理的解耦是**通道间**的（语义 8ch ↔ 细节 32ch）。但 L1 的可用性还要求**轴与轴之间**正交：转"厚涂"旋钮不应连带改变构图密度、光照方向、色彩饱和。如果轴是纠缠的，用户就**无法通过调一个数值得到想要的结果**——L1 的"一根旋钮"叙事就不成立。

而这里**有一个天然的验证手段被漏掉了**：§4.8.4 的 **shader 配对数据**。同一 3D 场景、不同 shader，**几何/光照/相机/姿态完全一致，只有渲染风格不同** —— 意味着条件向量的差异**理论上只应落在风格维度上，其余维度必须是零**。这是一个**免费的正交性监督信号**，设计里只把它当"数据来源"，没把它当"监督手段"。

### 2.3 加固方案（五条：不推翻 L1，但给它上保险）

#### ① 措辞纠正：90 / 9 / 1 是**调用量分布**，不是**能力分层**

保持 L1 在主线上的地位（它确实是省事的那条路），但**必须写死一句**：

> **L1 覆盖 90% 的调用量，但 L3 承担 100% 的兜底责任。**
> L1 是**默认档**，L3 是**一等公民**——不是"1% 的长尾兜底"。

现在的表述（"覆盖约 90%" / "底模确实没见过的东西 → 约 1%"）会诱导一种危险的读法：**"L1 够用了，L3 很少要用"**。而正确读法是：**"L1 是快路，L3 是保底；两者的地位不是按使用频率排的。"**

#### ② 新增 **Axis Probe（条件轴探针）** + 验证门 **G3.5**

这是把 L1 从"信仰"变成"可验证"的核心动作。四测：

| 测项 | 判据 | 不达标后果 |
|---|---|---|
| **单调性** | 轴值单调递增 → 输出沿该维度单调变化（用 CLIP / DINO 特征投影测方向一致性） | 轴不成立 → 该风格改用 L3 实现 |
| **正交性** | 转该轴时，构图（bbox 布局差）、光照（平均亮度/色温）、色相漂移 < 阈值 | 轴耦合 → 拆分或改用 L3 |
| **可逆性** | `+a` 再 `−a` 回到原图（在容差内） | 轴不可逆 → 不可用 |
| **⚠️ 低比特可用行程** | FP4 下**可分辨的轴步数** ÷ bf16 下的步数 > 阈值（例如 ≥ 70%） | **L1 在 FP4 下退化 → 必须改用 Style-Pack（方案 ③）** |

最后一项直接接住 §2.2 风险 3。

##### ✅ 已可执行（2026-10-03）

测量装置已落地，不再是纸面判据：

| 件 | 位置 | 说明 |
|---|---|---|
| **探针** | `kp/probe/axis.py` | `AxisProbe(responder).run()` —— responder 可换成「主干 + 该轴注入路径」的探针函数 |
| **对照样本** | `kp/probe/synthetic.py` | 4 类合成轴系统（clean / coupled / suppressed / nonlinear） |
| **门线** | `kp/config.py::AXIS` | 单调 ≥0.90｜串扰 ≤0.30｜可逆 ≥0.90｜行程 ≥0.80（**全是旋钮**） |
| **演示** | `tools/axis_probe_demo.py` | 在已知答案的样本上跑四测并对照期望 |
| **自检** | `kp.selftest` 第 16 节 | 3 项，含下面这条要害断言 |

> ⭐ **为什么先跑合成样本**：**测量装置必须先能在已知答案的样本上给出正确答案**，
> 否则它在真模型上给出的数字没有意义。自检里守的正是这一点 ——
> 而且有一条断言专门守 **`suppressed` 只挂第 ④ 测**：
> 若它同时也挂了前三条，就说明第 ④ 测可被替代，而设计稿的论点恰恰是它**不可替代**
> （「低比特行程在 bf16 上调参时完全看不出来」）。
> 实测：被抑制的轴 单调 1.00 / 串扰 0.00 / 可逆 1.00 **全过**，只有行程 0.25 挂。

**③ 可逆性的落地口径**（与上表措辞对齐）：对**无状态**的前馈函数，
「`+a` 再 `−a` 走一遍就回去了」是恒真的废话。真正的物理来源是**二次项 / 滞回**，
所以实现取它的无状态等价形式 —— **响应沿该轴奇对称**：
`d± = f(v=±a) − f(v=0)`，取 `err = ‖d₊+d₋‖/(‖d₊‖+‖d₋‖)` 的最大值，可逆性 = `1 − max err`。
（另报一个**辅助**指标「线性读出 R²」，不设门线 —— 它回答的是「轴值还在不在响应里」，与可逆性互补但不等价。）

#### ③ **Style-Pack：把风格也做成"显式对象"**（最优雅的一条）

设计里**已经有**这个机制了——Character Carrier（补充 04 §3.3）：参考图 → Fitter 前向 → 得到一个**数据对象**（1–5MB）。

> **同一套机制可以直接做风格。**

```
给 N 张同风格参考图  →  Style Fitter 前向一次  →  Style-Pack（数据对象）
```

收益是结构性的：

| 收益 | 说明 |
|---|---|
| **不依赖基座理解** | 风格不再要求"基座见过这个轴"——它被**显式编码在对象里**（这正是绕过风险 1） |
| **可检查** | 对象是数据，可以比对、可以求相似度、可以看它变了多少（这正是绕过风险 2） |
| **可迁移 / 可分享** | 与角色卡同理：数据对象不依赖坐标系，跨我们自己的主干版本可迁移 |
| **零新增架构** | 复用 Fitter + 载体格式，没有新机制 |
| **格式统一** | 补充 04 条目 22 已经提出「TypographyPack 与角色卡**共用同一套分层表示**」——**加 Style 是自然的第三项**。三类载体（角色 / 风格 / 文字）共用一套格式，`load_adapter()` 一个入口（条目 ④ 的接口） |

**这就是这条警告的正面解法**：不是把 L1 做强，而是**给"风格"也备一条显式路径**，让 L1 只需承担它真正验证过的部分。

#### ④ **设计律（新增）：控制权原则**

从 §2.2 风险 2 那一列对比直接推出来：

> ### **能显式写入的，就不要隐式请求。**
>
> - L1 是「**我们向基座请求**」（请求它可以被拒绝、可以被误解、无法审计）；
> - L3 / Pack / 载体是「**我们直接写入**」（可检查、可回滚、可迁移）。
>
> 在 **① 低比特（FP4）+ ② 自研架构（我们控制主干）+ ③ 摆脱基座束缚（项目初衷）** 这三条同时成立的项目里——
> **写入优先于请求。**
>
> → **L1 只用于「轴独立性经探针验证过、且低比特行程达标」的那些维度。** 未经 G3.5 验证的维度，**默认归属 L3**。

这条原则和补充 03 §2.2 那条「能力越大、越域外，就越不能住在 ΔW 里」是**对偶的**：
- 补充 03 说的是"**大的能力不能塞进小的容器**"（域外能力不能进 ΔW）；
- 本条说的是"**关键的控制权不能交给不受控的对方**"（可靠控制不能依赖隐式请求）。
两条合起来，构成控制手段的完整分工边界。

#### ⑤（附带）L1 的**显式化改造**：让它真的可以被信赖

⚠️ 这是唯一能让 L1 **本身**变可信的办法（而非绕过它）。

不要让 L1 是一个**裸数值**，而是给它一个**已命名、逐维标定**的低维条件向量（例如 16 维，每一维对应一个已命名的风格轴：写实度 / 描边强度 / 平涂度 / 冷暖 / 对比度 / 笔触粗度…）。

训练时用 **shader 配对数据强制逐维独立** —— 因为 shader 本身是**正交的**（同一场景不同 shader，几何 / 光照 / 相机 / 姿态完全一致），所以条件向量的差异**理论上只应落在 shader 维度上，其余维度必须是零**。

**这样 L1 就从「黑盒旋钮」变成「已标定控制面板」。** 用户看到的不是一个 0–1 的神秘数字，而是"描边强度 0.3、平涂度 0.7"这种可预期、可复现、可文档化的东西。

> **这是唯一能把 L1 从"信仰"变成"工具"的路径**，而且它已经躺在设计里（§4.8.4 的 shader 配对），只是没有被赋予"正交监督"这个用途。

## 5. 一句话总结

> **① 参考图理解有（CharaBridge，且比 IP-Adapter 强）；空间密集控制有对应件（条件包），但它是"能做但贵"、且进不了第一步——而你说"只为了角色才需要它"，这个判断在设计上成立。**
>
> **② 「L1 过度依赖基座」这条警告成立，而且更准确的说法是「从未检验」：设计的选层判据里根本没有 L1 的入口，而它承担 90% 的需求。**
> **加固的方式不是把 L1 做强，而是 ① 把 90/9/1 读回"调用量分布"、② 加 G3.5 探针把 L1 从信仰变成可验证、③ 给风格也备一条显式路径（Style-Pack）、④ 立一条设计律：能显式写入的，就不要隐式请求。**
