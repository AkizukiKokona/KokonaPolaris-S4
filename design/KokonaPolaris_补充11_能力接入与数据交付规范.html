能力接入与数据交付规范

面向两方：数据交付方（你）+ 工程侧（我）· 格式只有一套，换能力不换格式

2026-10-03接口规范（非推演）配套：主文档 v1.13 · 补充 04 / 05 / 10v1.1：试点分两级 · 窗口期 · 已有资产用法 · §4.7 标签不可迁移 · §4.8 中文优先
一句话

不管以后要接入什么能力，数据的格式只有一套。

你只需要交 3 项：图片 + 文字描述 + 分类标签。其余全部由工程侧自动生成。

⚠️ 这份规范是通用的，不针对任何特定内容 —— 同一个插座，插什么由你决定。

01项目是什么（先对齐定位）

一句话定位

KP（心夏北极星）是一个面向 8GB 消费级显卡、原生 4bit 的二次元文生图模型架构。

卖点不是「参数更大」，而是「小到能塞进 8GB，还能往上挂任何能力」。

维度答案
是什么文生图（Text-to-Image）模型 —— 输入文字，输出图像
跑在哪8GB 显存消费卡（RTX 50 系那档）—— 第一性约束
主打二次元 / 日系画风；写实作为内置开关保留
差异原生 NVFP4 + 单流 DiT + 32× 混合 latent + 能力总线（一套底座、无限挂件）

1.2 产品构成（这是 KP 本体）

KP 成品 = ① 文本塔（~220M 语言模型，自蒸馏）
        + ② DiT 主干（自研，0.6B / 1.5B）
        + ③ VAE（图像 ↔ latent）
        + ④ 可选能力挂件（按需加载）

1.3 零件 vs 工具（最容易搞混的一层）

名字类型角色进产品吗
Sana 1.6B生图模型试件 —— 一次性，只用来验「4bit 会不会掉画质」不进
Z-Image-Turbo生图模型教师 —— 训练时出图当示范只训练期
DINOv3视觉编码器教师 —— 冻结，语义锚定（不出图）推理不需要
Qwen3-4B语言模型教师 —— 蒸馏出我们的 220M 文本塔师傅走徒留
220M 文本塔语言模型文本编码器（文本 → 向量）进产品
⚠️ 两个高频误解

① 「我们接了两个生图模型」—— 没有这回事。产品里只有一个生图主干；Sana 是量尺、Z-Image 是师傅，都是工具台。

② 「教师只有一个，而且只给图」—— 是三个，且给的不只是图。Z-Image → 出图与去噪轨迹；DINOv3 → 语义特征；Qwen3-4B → 文本表示。0.6B 学 6B，光看成品不够，还要看手感。

02分工界线（从第一天就存在）

侧谁负责
架构侧工程过滤管线的接口 · 擦除算子 E（低秩矩阵，纯数学对象）· 账本格式与写入 · 可逆性验证脚本
数据侧你数据池的内容 —— 收集 / 制作 / 标注 / 边界划定 / 来源与许可

关键性质：架构侧做的东西与「里面装了什么」完全无关 —— 像 USB 接口不关心你插的是键盘还是硬盘。

⇒ 不是「走到某一步被迫停手」，而是本来就分属两侧。 交接点 = 训练开跑前。

03能力接入：唯一的死线

3.1 三层 deadline（只有第 ① 层不可逆）

#要做的事死线错过怎么办
①让能力存在于主干（喂进去）预训练开始前 · 数据管线定稿 —— 不可逆只能重训主干；或永久走最贵的 ∥-Pack
②让能力可逆地关掉（擦除 + 记账）预训练之后、发布之前（依赖 ①）① 没做则无从谈起
③让能力部署时可开可关任何时间随时可做（加载挂件）

① 的日历位置 = P2 换主干 / G6 预训练，是全案最靠后的几步之一。现在离死线还很远。

⭐⭐ v1.1 重要细化：「预训练」是「窗口期」，不是「瞬间」

训练是分阶段的 —— 预训练 → 中训 → 后训，每个阶段都能引入新数据。准确说法是：「越早进主干越便宜、越稳」，而不是「错过某个瞬间就永久报废」。

进场时机代价风险
早进（预训练）最低 —— 数据直接参与学基础表征最低
晚进（中训 / 后训）更高 —— 要额外算力有扰动已学能力的风险（需更小学习率 + 更强正交约束）
完全不进只能走挂件 ∥-Pack（最贵）天级 + 重训

⇒ 窗口期有几个月量级。你不需要今天就凑齐数据，也不需要一次交全。

3.2 悖论解法：别决定「要不要」，只决定「要不要留门」

方案成本将来想要时
喂了 + 显式擦除并记账≈ 0（多喂一部分数据 + 记一笔账）E⁻¹ 秒级取反，不训练、不伤其它能力
不喂0只能加并联助手 ∥-Pack：天级 + 重训 + 可能掉画质
这是「期权」，不是「承诺」

买到的是「未来能一秒打开它的权利」，标价接近零。账本躺在硬盘上不占任何运行时开销（门控默认 0）。

3.3 ⚠️ 留门的代价（必须如实知道）

  1. 擦除可能有残留 —— 擦得不够干净，痕迹会渗到别的提示词上。
  2. 擦得太狠会伤邻近能力 —— 擦除是低秩算子，动手过猛会波及语义相邻的方向。

把关方式：E⁻¹∘E 之后输出分布回到基线的 KL 测试 ⇒ 我们训练期间可自测，不依赖你。属工程侧承担的技术风险。

技术依据：擦除多为「引导式回避」而非销毁（arXiv 2505.17013）；安全子空间有效秩 k≈6（LoX）；闭式擦除 22 秒（CURE, NeurIPS 2025）。因为我们自己做数据过滤 ⇒ 我们知道擦了什么（社区做不到）。

04数据交付规范（核心）

4.1 你必须准备的 —— 3 项，不多不少

#项要求
1图片PNG / JPG / WebP；短边 ≥ 1024 px（latent 32× 压缩，1024² → 32×32；低于 1024 会被二次浪费）；不要水印、字幕条、边框
2文字描述 caption中 / 英皆可，一句话到一段话。建议覆盖：主体 + 动作 + 构图/视角 + 场景 + 风格
3分类标签 tag关键项：标明这条数据属于哪个能力维度。这是擦除账本能定位的唯一依据 —— 没有 tag 就无法「留门」，只能全丢。

4.2 目录组织

D:\model\data\<批次名>\
├── images\
│   ├── 0001.png
│   ├── 0002.jpg
│   └── ...
└── manifest.csv
file,tag,caption,source
0001.png,类别A,"一名角色站在雨中，全身构图，冷色调，日式动画风格",自摄
0002.jpg,类别A,"角色特写，正面视角，室内暖光",自绘
列必需说明
file✅图片文件名（相对 images/）
tag✅分类标签（同批次内自定名，但必须能区分「要不要擦」的那些）
caption✅文字描述
source建议来源 / 许可备注（便于合规追溯）

校验器：python tools/data_spec/validate_manifest.py --dir D:\model\data\<批次名>
它会检查：目录结构、manifest 列名、文件是否存在、短边分辨率、重复率（感知 hash）、caption 缺失、tag 分布。

4.3 我们自动生成的（你完全不用管）

自动生成项用什么
姿态 / 景别 / 构图现成人体与姿态估计模型
深度 / 法线现成几何估计模型
分割掩码 / 部件现成分割模型
DINOv3 语义特征（语义通道对齐）训练时在线计算
质量打分与过滤（模糊 / 低信息量）自动流水线
感知去重自动流水线
分辨率分桶自动流水线
人脸 / 人体检测自动流水线
⛔ 严禁给你派人工标注任务

分层 / 掩码这类如果靠人工，成本会失控 —— 全部自动。你的活止于「给图 + 一句话 + 打一个标签」。

4.4 三条硬提醒

  1. 同一个东西不要给多份 —— 我们会做感知去重，但源头去重更省时间。
  2. 分辨率宁高勿低 —— 短边 1024 是及格线；低于它，那部分信息在 32× 压缩里会被丢掉。
  3. 来源与边界由你这一侧确认 —— 这是分工：这批数据会进产品权重，且预训练一旦开始，「喂过」这个事实就固定了（对应 §3.1 的唯一死线）。

4.5 首批试点与验收

分两级，别一次凑齐：

级别规模目的
第一级 · 先打通管线50–100 张只要够跑通「格式校验 → 入库 → 编码」全流程即可
第二级 · 看覆盖度500–2000 张判断概念覆盖度与标签可分性，据此定最终规模
步骤谁产出
① 交第一级小批你data/<批次名>/（50–100 张就够起步）
② 跑可用性检查我格式校验报告：目录/列名/分辨率/重复率/tag 分布/caption 质量
③ 给建议规模我依据真实数据给出建议规模，而不是拍一个假数字
④ 分批补齐你按建议规模分批交，每批都独立可用
⚠️ 数据池是增量累积的，不是一次交齐

你有多少先交多少；缺的部分标成「待补」，中训 / 后训阶段还能继续进（见 §3.1 的「窗口期」说明）。

不要为了凑齐而卡住整个项目 —— 先喂能拿到的。

关于「量」的现实提醒：一张图生成几十秒，听起来要「等」，但那是机器在等，不是你在等。批量任务是无人值守的（挂上去 → 去做别的事 / 睡觉 → 醒来看结果）。需要的是一个批处理任务，不是一个团队。

4.6 你已有的资产怎么用（不是混乱，是资产）

已有资产能否迁移到 KP能用来干什么
本地某个 WAI 系模型❌ 不能（架构、latent 全不同）作为风格 / 角色数据的生产工具（由你自己运行）
你自己训的角色 LoRA❌ 不能直接迁移⭐ 生产「角色卡」所需的配对数据 —— 同一角色、多视角、同一身份（P2.6 / G5 的输入）
  1. LoRA 不能跨模型迁移 —— 硬事实：LoRA 是绑死在特定权重 W₀ 上的，换权重即失效（这正是主文档「Δ-Pack 必须建在 W₀ 子空间」那条设计的由来）。但这不是浪费 —— 它证明你已经在做「能力挂件」这件事了；KP 只是把它做成标准化 / 秒级 / 可跨版本。
  2. ⭐ 它是角色卡数据线的现成引擎：同一角色、同一 LoRA，只换视角与姿势 → 天然的多视角配对数据。
    产出：data/<角色名>/{front, back, left, right, 3q}.png + 身份标注
    用途：G5 角色卡 / P2.6 Character Fitter
    ⭐ 这条线现在就能开跑：不依赖 KP 代码、不依赖量化、不依赖任何其它前置 —— 它只依赖你手上已有的东西。

4.7 为什么「加标签就触发」不可迁移 —— 以及 tag 的真正用途

你的观察是对的

在别的模型上能触发，KP 上不会。原因不是「没训到位」，是机制根本不同。

「标签触发」是三样东西的联合产物：

#成分说明
1词嵌入文本塔把那个 tag 编码成什么向量
2条件通路该向量如何在主干里传播、被哪些层消费
3共现统计训练时「该 tag ↔ 该类内容」的耦合强度

在某个模型 + 某个 LoRA 上，这三样是已经耦合好的一个整体。搬到 KP，三样全变 —— 所以标签不会触发同样的东西。

两条推论（都很硬）

❌ 不能靠「复现标签」来复现能力 —— 换了主干、换了文本塔，标签的语义要重新建立。

❌ 也不能把别的模型的输出当「真值」 —— 它带着那个模型的偏差，以及那个 LoRA 自身的缺陷（数据极少 → 学到的方向不干净 → 极端输入下行为怪异）。

⚠️ 顺带印证一条设计结论

LoRA 数据极少会学到不干净的更新方向（对应主文档的「入侵维度」问题）。这正是 KP 里「Δ-Pack 必须建在 W₀ 的 SVD 子空间内 + 训练后做谱检查」那条约束的由来 ——

不干净的 LoRA 不是「训得不好」，是方法本身的固有性质。

✅ 正解：不复制「标签触发」，而是建 KP 原生的「显式条件轴」

标签触发（旧路）显式条件轴（KP 路线）
机制靠自然语言 tag 的共现统计靠结构化的条件维度
可标定❌ 不可（黑盒）✅ 可（逐维命名）
可审计❌✅（Axis Probe 四测）
出错时只能重训可定位、可回滚
对应设计律隐式请求显式写入

⭐ 于是 tag 这一列是「一鱼两吃」

用途说明
① 擦除账本定位标出哪些数据属于「要擦」的那一类
② 条件轴的训练标签训练时把 tag 映射到条件维度上 —— 将来拨这根轴就能触发

⇒ tag 不是随手写的备注，它是「标签 → 条件轴」这条通路的原始材料。 写得越规范、越一致，将来在 KP 上「拨动即可触发」就越可靠。

把关门 = G3.5 Axis Probe（单调性 / 正交性 / 可逆性 / 低比特可用行程）。

  • ⚠️ 「加标签立刻触发」正是「单调性」这一测的特例。
  • ⚠️ 诚实提醒：低比特下轴的分辨率受限（FP4 激活只有 16 级 E2M1）→ 「秒级触发」不是零成本，代价在低比特下更大。 这正是 G3.5 存在的理由。

4.8 caption 用什么语言写 —— 中文优先

结论：中文优先，保留少量英文做跨语言对齐

这不是偏好问题，是架构决定的。SDXL 的中文不行，是因为它的文本塔是 CLIP；KP 的塔是语言模型。

SDXL 时代KP
文本塔CLIP（英文图文对比学习）~220M 语言模型（自 Qwen3-4B 蒸馏，多语言）
中文基本是噪声（语料里没见过）天生支持
输入风格逗号标签串（tag soup）自然语言句子
「标签」的角色用户要写的输入咒语内部条件轴的训练标签（工程侧处理）

为什么 SDXL 必须全英文：它的文本塔是 CLIP —— 用英文图文对对比学习出来的词向量表，中文 token 基本没被训过 → 等于噪声。

为什么 KP 可以中文：文本塔的教师是多语言语言模型（Qwen3-4B），中文是它的原生能力，蒸馏时刻意保留即可。⇒ 「能理解语言」和「认识英文单词」是两回事 —— LLM 塔走前者，CLIP 走后者。

⚠️ 但中文能力不是白送的

它还取决于训练数据里中文 caption 的占比。所以这是个可调的旋钮，要主动设计（不是「反正模型支持」）。

给你的三条建议：

  1. caption 用中文写 —— 母语描述最准确、信息量最大。
  2. 保留 10–20% 英文 caption（跨语言对齐，便于将来接英文提示词）。
  3. ⚠️ 不要写成「逗号标签串」 —— 写成通顺的一句话 / 一小段话（KP 的塔是语言模型，不是词袋）。

一句话：SDXL 里 tag 是「输入」；KP 里 tag 退到「内部标注」，用户面对的是自然语言。

05夜间与排程规范

时段允许禁止
夜间（安静模式 · GPU ~40 W）文档 · 代码 · 工具链 · 数据校验（CPU/IO） · 单张轻量实验—
夜间—⛔ 压力测试 / 基准跑分 / 大批量出图 / 训练
白天 / 用户解锁（115 W）全部，含吞吐基准 · FID 批 · 训练—

理由：夜间 GPU 被强制压到 40 W，重算力跑出来的数字无效。需要真算力时由用户手动切档（nvidia-smi 推不动）。
