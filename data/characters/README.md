# 角色样图投递口（character reference drop）

> 本目录用于接收**角色参考图**，是「角色卡」数据线的入口。
> ⭐ **这条线不依赖 KP 主干** —— 你随时可以投，我不需要等模型就绪。

---

## 1. 最少需要什么

| # | 项 | 说明 |
|---|---|---|
| 1 | **正视图**（正对镜头） | 全身或半身 |
| 2 | **背视图**（正对后方） | **与正面尽量同一姿势**（配对数据） |

**这两张就是硬约束④「正视图 + 背视图」的最低要求。**

> ⭐ **有更多视角就更好**（左 / 右 / 3/4 侧 / 仰 / 俯）—— 多一个视角，遮挡补全与伪深度就准一分。
> ⭐ **姿势一致比视角多更重要**：配对数据要求「只变视角，不变姿势」。
> 没有更多也没关系，**两张能起跑**。

### 分辨率要求（**与通用训练集不同**）

| 用途 | 门槛 |
|---|---|
| 通用训练集图片（走 32× latent） | **短边 ≥ 1024**（硬性） |
| ⭐ **角色参考图**（喂 Fitter 做身份提取） | **角色本体界框 长边 ≥ 1024、短边 ≥ 512** —— 不强制画布尺寸 |

> ⚠️ **关键是「角色在画面里占多大」，不是「画布多大」**。
> 一张 1024×1024 但角色只占中间 300 px 宽的图，**有效分辨率只有 300 px**。
> ⇒ **截图时请把镜头拉近，让角色（含发型与服装）尽量填满画面。**
> 背景请用**纯色**（纯白最好），不要阴影、不要特效、不要文字。

## 2. 怎么放

```
data/characters/<角色名>/
├── images/
│   ├── front.png          ← 正视图（正对镜头）
│   ├── back.png           ← 背视图
│   ├── left.png           ← 可选
│   ├── right.png          ← 可选
│   └── 3q.png             ← 可选：3/4 侧
├── manifest.csv           ← 见下方格式
└── source/                ← 可选：原始素材
    └── model.vrm          ← ⭐ 若手上有 3D 模型文件本体（.vrm/.fbx/.glb/.pmx/.blend）
```

> ⚠️ **目录结构统一为 `images/` + `manifest.csv`** —— 与通用数据批**完全一致**，
> 因为校验器 `validate_manifest.py` 按同一套规格检查（换能力不换格式）。

### ⭐ 如果手上有 **3D 模型文件本体**

那比截图更值钱：**我们可以自己渲染任意视角 + 任意姿态**（对应设计里的「四旋钮」）。
⇒ 把模型文件丢进 `source/`，**同时仍然放 front/back 截图**（作为对齐锚点）。

## 3. manifest.csv

```csv
file,tag,caption,source
front.png,<角色名>,"角色正面全身，站立正对镜头，双手叉腰，<发色>配<配饰>，<配色>主题服装，日式动画风格，纯白背景",3D模型正视截图
back.png,<角色名>,"同角色背面全身，与正面同一姿势，背对镜头，可见发型后部与服装背面结构，纯白背景",3D模型背视截图
```

| 列 | 说明 |
|---|---|
| `file` | 文件名（相对 `images/`） |
| `tag` | ⭐ **填角色名 / 角色 ID** —— 身份唯一键，也是将来分轴定位的依据 |
| `caption` | **中文**自然语言一句话（**不要写标签串**），覆盖 主体/视角/姿势/配色/风格 |
| `source` | 来源备注 |

## 4. 校验

```bash
# 通用数据批（默认短边 1024）
python tools/data_spec/validate_manifest.py --dir D:\model\data\characters\<角色名>

# 角色参考图（参考图门槛较松）
python tools/data_spec/validate_manifest.py --dir D:\model\data\characters\<角色名> --min-side 512
```

检查：目录结构 / 表头 / 文件存在 / 短边分辨率 / 重复率 / caption 缺失 / tag 分布。

| 步骤 | 谁 | 产出 |

---

## 6. ⚠️ 两条处理红线

1. ⛔ **不使用生成式 AI 超分**处理身份参考图。
   生成式超分会**编造不存在的细节**（发丝、瞳纹、服饰纹理）——
   对身份参考是**有害**的：它会把「模型猜的」当成「这个角色的事实」固化进角色卡，**反而降低身份保真度**。
   要更高分辨率，**只能重新渲染 / 重新截图**（真信息）。
2. ⛔ **无损裁切 + 传统重采样（Lanczos）可以做**，AI 生成式放大不做。

## 7. ⭐ 重新截图清单（要拍更高清时照这个来）

### ⚠️ 先纠正一个常见误区：**不要只截头部特写**

| | 只截头部特写 | ⭐ **截「角色占满画面」的全身** |
|---|---|---|
| 头部细节 | 高 | 高（一样高） |
| 身体细节 | **没提升** | 高 |
| 2.5D 分层 / 伪深度绘制序 | ❌ **做不了**（要全身同一投影尺度） | ✅ 一张图搞定 |
| 头身接缝比例 | ❌ 要靠猜 | ✅ 天然对齐 |

**原因**：角色卡要做 **2.5D 分层 + 遮挡补全 + 伪深度绘制序**，这些都要求**全身处在同一张图、同一投影尺度**里。
如果拿到「头部高清特写 + 全身低清」两张不同尺度的图，头部与身体的**接缝比例与层级归属会变成猜测** → **反而引入误差**。

> ⭐ **结论：相机拉近，让角色填满画面 —— 一张全身图同时提升头部和身体。**
> 只有一种例外：**游戏相机拉不到那么近** → 那就拍两张（全身尽量近 + 一张头部特写），
> 我把头部特写当**细节参考**、全身图当**结构基准**，由我做对齐。**可接受，但次优。**

### 截图要求（逐条照做）

| # | 要求 | 说明 |
|---|---|---|
| 1 | **姿势与现有两张完全一致** | 双手叉腰站立。**不要换动作/表情** —— 配对数据要求「只变视角，不变姿势」 |
| 2 | **视角：正视 + 正后各一张** | 正对镜头，**不要斜视、不要鱼眼/广角畸变** |
| 3 | ⭐ **构图：角色填满画面** | 头顶到脚底几乎顶满。**拉近相机**，不是事后裁剪放大 |
| 4 | **背景：能选纯色就选纯色** | 换装/图鉴界面常有纯色板。**不行也没关系**，我来抠 |
| 5 | **关掉后期特效** | 景深(DOF) / 运动模糊 / 胶片颗粒 / 锐化 —— 会让颜色与轮廓失真 |
| 6 | **避开 UI** | HUD、角色名、按钮、准星、伤害数字。截完检查一遍 |
| 7 | **格式 PNG** | 不要 JPG（压缩伪影会被学成"细节"） |
| 8 | **分辨率拉到最高** | 游戏设置里先调满 |

### 关于「不是白底，要自己去底」

- ✅ **抠图由我自动做**，不用你操心（现成分割模型 + 边缘细化）。
- ⭐ 但**背景越干净，抠得越准**。抠图边缘的误差会变成**角色轮廓上的假信息** —— 所以能选纯色背景就选。
- 极端情况：背景太杂（有景深模糊、粒子、光晕）→ 抠图会在轮廓上留毛刺 → 这种我会退回给你重截。

### 原图放在哪

```
data/characters/<角色名>/raw/      ← ⭐ 原始截图直接丢这里，不要预处理
```

> **不要自己裁切/压缩/去底** —— 原图信息越多越好，所有处理我来做。
> 处理后的规范图会出现在 `images/`，原图保留在 `raw/` 做追溯。
