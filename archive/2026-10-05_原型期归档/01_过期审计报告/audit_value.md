| 问题 | 判断 |
|---|---|
| **这个项目现在有产品价值吗？** | **没有。** 没有权重、没有训练过、没有任何"模型侧"证据。全部价值在**设计文档 + CPU 骨架 + 一条已被实测证伪的立论**。 |

## 1. 差异化评估表

**证据档位定义**：
- 🟢 **已实测**（本项目有真数据，且是对该主张的直接检验）
- 🔵 **装置层自证**（装置正确、有已知答案/负对照，但**随机权重 / 非真实分布 / 合成数据**）
- ⚪ **纯设计意图**（推理自洽，无任何本项目证据）

| # | 声称的创新点 | 证据档位 | 竞品对照（联网核实） | 判断 |
|---|---|---|---|---|
| 1 | **32× 混合 latent（语义8ch + 细节32ch）** | ⚪ 设计意图 + 🔵 装置（合成数据上分离监督净收益 8.17×） | **不是空白。** **DA-VAE**（arXiv 2603.22125, CVPR 2026）做的是**逐字相同**的结构：base latent + 额外 D 个 detail 通道拼接、共用一个 decoder。**SVG**（arXiv 2510.15301, ICLR 2026）= 冻结 DINOv3 语义 + 轻量残差 encoder 补细节，**沿通道维 concat** —— 与 KP 的"语义通道 + 细节通道拼接"是同一句话 | **换名字的已有方案。** 真正的差别只剩"语义通道对齐 DINOv3"（SVG 也做了）和"32× 而非 16×"。**不能当创新点卖。** |
| 2 | **3:1 非 softmax 混合注意力** | 🟢 **已实测，且自我反驳** | SANA-Video 2.0 的 75%线性+25%softmax 消融确实存在（设计稿引对了）；但 Sigmoid/Softpick 本身不是新算子 | **诚实但尴尬。** 自建装置测出「长提示收益不获支持、量化友好性获支持」，**且被证实的那半边恰好是没有判据的那半边**。这是**项目最有价值的单条实测**，但它证明的是"设计稿 §4.3 的立论 L310 是错的"。**作为差异化主张：不成立。** |
| 3 | **Matryoshka 分辨率** | ⚪ 设计意图（骨架可跑，未验收） | 原始 Matryoshka Diffusion（arXiv 2310.15111, ICLR 2024）是**像素域多分辨率联合去噪 + NestedUNet**，机制与 KP「高分辨率跑更浅的层」**完全不同**。设计稿引用的 PostDiff 数字（FID 18.42→15.69 / FLOPs −60%）我核实到出自 **PostDiff（arXiv 2508.06160, ICCV 2025）Table 2，测的是 SD v1.5 (DreamShaper-v7)，且是 training-free 的 post-hoc 混合分辨率去噪 + 模块缓存** | **引证错位。** 用一个 UNet 上的免训练后处理技巧，去论证「DiT + 无位置编码 + Matryoshka 训练」兼容，**是范畴错误**。设计稿 §A4 诚实地标了"不是我们的架构"，但 `MEMORY.md` 里那行数字没有这个限定。 |
| 4 | **角色卡 2.5D 分层** | ⚪ 设计意图（语义层是启发式占位） | See-through（arXiv 2602.03749, SIGGRAPH 2026）确实存在，但：① 它建在 **SDXL 的 LayerDiff 3D + 微调 Marigold** 上；② 自举自 **9,102 个商业 Live2D 模型**；③ 实测局限明确：**复杂褶边 / 手或道具大幅遮挡面部 / 极端透视 / 全身场景 / Q版 / 半透明材质**易崩 | **先例存在但比设计稿引用的弱。** 且 See-through 处理的是**单张动漫插画**，不是「正反 3D 视图 → 分层卡」—— 这条路径**确实无直接先例**（设计稿没说错）。但它继承 See-through 的全部失败模式。 |
| 5 | **双向能力包体系（∥/Δ/SVD-Pack）** | 🔵 装置层自证（谱检查双判据子空间 PASS cos=1.000 / 正交 FAIL cos=0.000；E⁻¹∘E KL≈0） | 底层机制全部有先例：块对角 LoRA（RaLoRA）、零空间约束（LoRA-X）、旁路适配（IP-Adapter/PuLID）、可插拔模块化 LoRA（CharCom, arXiv 2510.10135 用 rank-4 身份 adapter 在冻结骨干上组合） | **是真工程贡献，但价值依赖下游。** 这是一套**正确的组合**，不是新原理。它的价值 = "如果底模够好" × "你确实需要挂很多能力"。**底模不存在 ⇒ 价值 = 0。** |
| 6 | **可逆擦除（E = Σαᵢuᵢvᵢᵀ + 账本 + E⁻¹ 闭式恢复）** | 🔵 装置层自证（KL≈0） | 擦除本身是成熟方向（2505.17013 引导式回避 / 安全微调近正交 ΔW / LoX 安全子空间 k≈6 / CURE 22s 闭式擦除）。**"把可逆性做成显式算子 + 写进 model card"是产品创新，不是技术创新** | **最有商业想象力、最不解决当前问题的一条。** 它的对象是**一个还不存在的模型的可分发权重**。合规叙事得很好，但**一个没有权重、没有数据合规路径的项目，审计账本是空的**。 |
| 7 | **NVFP4 原生 + SM120 + 8GB** | 🔵 装置层 + ⚠️ **G1 测的不是这件事** | **NVIDIA arXiv 2509.25149 真的做过 NVFP4 从零预训练**（12B 混合 Mamba-Transformer / 10T tokens / 稳定期 loss 差 <1%）。但那是 **12B + 10T token + 四件套配方**的规模，不是 0.6B。**关键：论文的四件套是 RHT（Wgrad）+ 2D block scaling + 梯度随机舍入 + 选择性高精度（~16% linear 留 BF16）**，且论文说**四者缺一不可** | **⚠️ 证据档位错配 —— 这是全案最隐蔽的问题。** 「NVFP4 原生预训练」的成立条件是**梯度也被量化 + 随机舍入 + RHT + 2D scaling**。KP 的做法是 **adapter 式 QAD（只训 0.33% 参数）**，而 G1 测的是**预训练权重上的 fake-quant 前向偏移（`d_quant/d_ref`）**。这**完全没有测到**"从零在 4-bit 里训练会不会收敛"。另注：4/6 那篇（Cook et al.）报告 **plain NVFP4 在所有测试的预训练里都发散**，加修正才稳。 |
| 8 | **"显存第一因是 token 数"** | ⚪ 设计推理 | 已被 Sana/DC-AE（32× → 1024 token @1024²）**实证为可行的工程选择** | **这条是对的，且是全案最扎实的一块地基。** 但它不是差异化 —— 它是**抄了 Sana 最正确的那一条**，然后加了一个新 latent 结构。且它有个未被承认的推论：**一旦 token 数压到 1024，NVFP4 就从"第一因"降级为"二级放大器"** —— 而"二级放大器"恰好是全案最高风险的项。**优先级排错了。** |

### 1.1 差异化结论

**「比 SDXL/Flux/Z-Image/HunyuanImage 强在哪」的诚实答案：目前一处都没有可证伪的优势主张。**

- 唯一被实测支撑的技术判断（G3 的因果反转）**是负面的** —— 它推翻了自己的立论。
- 三个"创新点"（混合 latent / Matryoshka / 角色卡 2.5D）经核实**都是已有工作的重命名或变体**（DA-VAE / MDM / See-through）。
- 真正的差异化只有两个，且都不是模型能力：**① 可逆擦除账本**（合规产品功能）、**② 8GB + 中文 + 角色卡 + 审计四合一**（**但四者任意单点都已被更强的东西占了**）。

### 1.2 对照表缺了谁（这是 §1 最重要的发现）

二次元赛道 2026 年的真实格局（联网核实）：

| 模型 | 底座 | 数据 | 状态 |
|---|---|---|---|
| **Illustrious-XL v2.0** | SDXL | **2000 万+ Danbooru 动漫图**（截至 2024-08） | **二次元事实标准**，LoRA 生态最深 |
| **NoobAI-XL** | Illustrious | 同上 + 继续优化 | 二次元最强开源之一 |
| Z-Image-Turbo | 自研 S3-DiT 6B | 未知 | Apache 2.0 / 8 步 / 中英双语 / FP8 ~6GB / 开源榜首 |
| FLUX.2 [klein] 4B | 自研 | 未知 | Apache 2.0 / ~8.4GB 实测 |

社区共识（多来源一致）：**纯二次元/插画，SDXL + Illustrious/NoobAI 仍是更好的选择**；Flux 在二次元上"要跟模型的本能对抗"，且二次元 LoRA 生态几乎不存在。

⇒ **设计稿 §8 的对照组里没有 Illustrious/NoobAI。** 这意味着 KP 从未面对「我们要用 0.6B 从零训的模型，去打一个用 2000 万张精心标注动漫图微调出来的 SDXL」这个真实命题。**这是整份设计稿最大的方法论漏洞，不是遗漏，是框架错误。**

## 2. 可行性评估：各验证门会不会卡死项目

### 2.1 排序：真正的"生死门"只有三道

| 门 | 性质 | **会不会卡死** | 理由 |
|---|---|---|---|
| 🔴 **G2 通道分离** | 结构性 | **会。且是唯一「理论上就可能不成立」的** | 见 §2.2 专项分析。**它挂了，"写实是内生旋钮"、"LoRA 只做长尾"、三层控制栈 90/9/1 全部塌掉**，退路是"改单通道 latent + 风格外挂" = 回到 SDXL 生态 + IP-Adapter = 现有方案。也就是说 **G2 不过，KP 就退化成"我们重新发明了 SDXL 的做法，但花了从零预训练的钱"。** |
| 🔴 **A1 / G1 NVFP4 原生预训练** | 结构性（但退路便宜） | **会卡住"NVFP4 原生"这个招牌，但不卡项目** | 退路是回 FP8，方案仍成立，只是**第一条硬约束作废**、8GB 目标的算力账要重算。**这是"不过也能出活"的门。** 但注意：**当前 G1 的证据测不到这件事**（§1 表 #7），所以现在"初步通过"这三个字**不构成任何保证**。 |

| 🟠 **G3.5 L1 条件轴真实性** | 结构性 | **不会卡死** | 全轴不过的退路是"L1 降级为方向性微调 + 风格走 Style-Pack"，方案仍成立（只是失去"零成本 90% 主路径"）。**但这是静默降级 —— 不会有人注意到主路径塌了。** |
| 🟠 **G6 Micro-budget 预训练** | 配方性 | **会超预算**（见 §3） | 不是"不可能"，是"$1890 这个前提不成立 ⇒ 真实预算高 1-2 个数量级"。 |

| 🟡 G4 Matryoshka | 配方性 | **不会** | 关掉即可。**而且引证要修正**（§1 表 #3）。 |
| 🟡 G5 角色卡 | 配方性 | **不会** | 退回 LoRA。**但它寄生了许可问题**（数据线是 NC 的）。 |
| 🟡 G7 少步蒸馏 | 配方性 | **不会** | 保持 8-12 步。社区先例充分。 |

### 2.2 ⚠️ G2 专项：32× 混合 latent 的通道分离，技术可行性分析

**结论：技术上是「可能但不被保证」，且现有文献的先验是偏悲观的。KP 目前对它的乐观建立在一个尚未做过的实验上。**

**先看文献实际说了什么（这很关键，设计稿没有引用这一组）**：

1. **DA-VAE（arXiv 2603.22125, CVPR 2026）—— 直接的负面证据。**
   它做的和 KP 几乎一样（base latent + detail 通道），论文原文明确报告：
   > *"Naively adding more channels to the existing latent makes diffusion training difficult. When the VAE encoder is trained only with a reconstruction loss, the extra detail channels z_d tend to **absorb noisy residuals** rather than forming a meaningful semantic structure."*
   **它必须加一个显式的 latent alignment loss（把 z_d 投影回 base latent 空间做 L2）才能让细节通道"可被 diffusion 建模"。**
   ⇒ **含义：detail 通道的天然倾向是变成噪声残差，不是变成"有意义的语义"。** 这正是 KP `MEMORY.md` 里自己担心的"主干把两通道都塞满"的 VAE 版本。

2. **SVG（arXiv 2510.15301, ICLR 2026）—— 第二个负面证据。**
   冻结 DINOv3 + 残差 encoder 沿通道拼接，**同样必须做 batch-statistics 级的 distribution alignment**，理由是 *"防止 Residual Encoder 的输出破坏 DINO 原有的语义分布"*。
   ⇒ **含义：两个分支会互相污染；先例是靠显式对齐约束把它们拉住，不是靠让它们自然分工。**

3. **Send-VAE（arXiv 2601.05823, Kolors）—— 第三个警示。**
   明确报告：把 VAE latent 直接对齐 VFM（DINOv2/CLIP）特征会造成 **semantic collapse，丢失细粒度属性**；并给出关键相关性 —— **低层属性的线性可分性 vs 下游 FID，Pearson 相关 −0.9572**。
   ⇒ **含义：这不是"语义通道对齐 DINOv3 就赚 REPA 收益"这么简单。VAE 端的语义对齐和生成端的需求是冲突的**，Send-VAE 整篇论文就是在解这个矛盾。**KP 把 REPA/RAE 的收益"免费内置"的表述过于乐观。**

4. **⚠️ 一个方向性的张力（这是我的技术判断，未在任何论文里找到直接对应，需实测）**：
   - 现有工作为了让新 latent **可被 diffusion 建模**，做的都是**对齐**（align z_d 到 z，align residual 到 DINO）。
   - KP 为了让能力**可控**，要的是**分离**（正交 + 互信息惩罚 + 反向扰动）。
   - **这两个目标可能是相反的**：对齐让 diffusion 好训但牺牲可控性；分离给可控性但让 latent 难训。
   - **如果这个张力是真的，那么 G2 的正确答案可能不是"通过"，而是"找到一个对齐/分离的折中点"—— 而那意味着设计要改。**
   - 我**没有找到文献直接验证这个张力**，标为**不确定**，**必须靠实验判**。

**对"真图上语义 8ch / 细节 32ch 能不能真的分开"的判断：**

- **理论上有通道容量**（40ch × 32×32 = 40960 个数/张，比 SD 的 4×128×128 = 65536 少，但 32ch 细节通道的容量远超 DC-AE 的 32ch 同规格）。所以**不是容量不够的问题**。
- **但「容量够」≠「学得出来」。** 一个训到收敛的自编码器，其通道分组由**训练目标的诱导偏置**决定，而不是由你写进 config 的通道数决定。DA-VAE 的观察（细节通道倾向吸收噪声残差）说明**纯重建损失会把通道推向"高频残差"这个平凡解**，而**语义**需要一个更强的、DA-VAE 用对齐损失、KP 用交叉扰动+MI 惩罚 —— **两者的力度是否够、会不会在 1024² 真实图上够，目前完全未知。**
- ⚠️ **且 KP 的 G2 现在是「合成数据上」的结论**（自检 §19：oracle 0.0000 PASS / leaky 0.592 FAIL / 有监督 0.0654 PASS）。**合成数据可以人为构造出可分的通道结构；真实照片+线稿的动漫图上，DINOv3 语义与高频细节的实际可分性要低得多。设计稿 §9.2 G2 行自己也写了"⚠️ 真图结论待接入真实 VAE 编码器（P1/P2 之后）"。**

**⇒ 我的判断：G2 不是"最重要的门"，G2 是"排期错误的门"。**
它被标为"结构性"，却**被排在它所 gate 的 P1/P2 之后**。以现在的顺序，你要先做完 VAE 训练 + 数据管线定稿 + 换主干，才知道这个项目的地基有没有。**这是本项目风险控制上最严重的一处设计缺陷。**（详见 §5.3 加码 #1）

| 二次元语料 | 自渲染 + NOVA-Human 10.2k VRM | **Illustrious 用 2000 万+ 张**；Danbooru 全库约 **490 万** | **2-3 个数量级** |
| 许可 | NOVA/Live2D **仅研究用** | 可分发权重需要商用授权数据 | 🔴 **当前无解** |
| caption 语言 | 中文为主 + 10-20% 英 | 社区实际主流是 **Danbooru 标签串**（Illustrious 对 booru tag 响应远好于自然语言） | ⚠️ **这是一个未经验证的产品假设**：KP 主张"输入从标签串变自然语言句子"，但二次元用户和他们的 LoRA 生态全在标签串上。P1.8 已把它绑成不可逆死线，**但没人证明过二次元用户想要句子**。 |

### 3.2 算力（重算 G6）

Micro-Budget 原文核实（CVPR 2025, arXiv 2407.15811）：
- **8 × H100 × 2.6 天**（≈499 H100·h），$1,890
- **37M 图**（真实 + 合成混合）
- 配方：**256×256 预训练 280K 步 → 256 finetune 55K 步 → 512 预训练 → 512 finetune**
- 模型：**含 MoE 的 sparse transformer**
- 结果：**COCO 零样本 FID 12.7**（COCO 256/512 域）

**四个不匹配，逐条：**

| # | Micro-Budget 的条件 | KP 的条件 | 后果 |
|---|---|---|---|
| 1 | 有 MoE（论文明确把 MoE 列为关键改进之一） | **KP 无 MoE** | 同参数下表达力更低 → 要么更大、要么更多步 |
| 2 | 目标 256/512 | **目标 1024²** | 4× 像素面积/张 |
| 3 | 37M 图（COCO + 合成，许可干净） | **二次元数据被许可阻断**，实际可用量远小 | 数据是唯一的真瓶颈 |
| 4 | FID 在 COCO 上有公开可比基线 | **二次元没有公开 FID 基准**，"FID 12.7"这个目标**在 KP 的域里不可测量** | G6 的判据"零样本 FID 进入可接受区间"**无法执行** |

**另外：$1,890 是 2024 年的 H100 租价，且不含数据管线、不含失败重跑。**

**我的重估（诚实标注为估算，非实测）**：
- 若照 KP 路线（无 MoE / 1024² / 40ch 混合 latent / 双域 / 中文），一次能看的预训练 ≈ **5,000–20,000 H100·h ≈ $12k–50k**。
- G2/G3.5 若不通过，大概率要**重跑**（不是微调能救的）⇒ **乘 2-3 倍**。
- **真实预训练预算量级：$30k–100k，不是 $1,890。** 且**这一笔钱随时可能因为 G2 结果作废。**

### 3.3 人力与时间

- 已完成：~9,605 行 Python / 44 文件 / CPU 骨架 / 73 项自检 —— **这个产出速度是真实的、值得认可的**。
- 但剩余工作：**混合 VAE 训练 + DINOv3 对齐 + 真实预训练 + 少步蒸馏 + CharaBridge + TypographyPack + G2/G3.5/G4/G5/G7 七组消融 + 数据渲染产线**。
- 我的估算：**1-2 人年**（不含数据产线），**12-24 个月**出可交付模型 —— **前提是一切顺利。**

### 3.4 ⛔ 不可逆死线（过了发现方向错，损失多少）

| 死线 | 何时过 | 损失 | 严重度 |
|---|---|---|---|
| **① 数据管线定稿**（中文 caption 配比、双域配比、tag 与自然语言的比例） | P1.8 / P2 同批 | 配比错了要**从头重训**，不是重训一个 LoRA | 🔴 高。**但这是全案最便宜的一道防线**（已有 `audit_captions.py` 守门），设计上是对的 |
| **② G2 真图判决** | 名义上在 P1/P2 之后 | **整个主线（L1 / 90-9-1 / 写实内生旋钮）作废**，退路 = 现有方案 + 更贵的路径 | 🔴 **最高。当前排期让这道防线形同虚设。** |
| **③ P2 换主干 + 全量预训练** | G6 | **$30k-100k + 3-6 个月**。架构从此被沉没成本锁死 | 🔴 **这是唯一真正花钱的死线。** |
| **④ 中文 caption 配比** | 与 ③ 同一批 | 二次元中文这个产品定位可能要重开（且未证明用户要句子） | 🟠 中高 |
| **⑤ 架构定稿（40ch / 3:1 / adaLN 8 段）** | 现在 | 现在改成本最低；G6 后改要重训 | 🟡 **现在是最后的便宜窗口。** |
| G3.5 L1 条件轴 | G3.5 | 静默降级到 L3，**没人会注意到** | 🟠 中（隐蔽） |
| 可逆擦除账本 | 设计期 | **现在砍掉零成本** | 🟢 低（现在就该砍） |

**⇒ 最重要的观察：项目当前把大量精力放在"装置层自证"（73 项自检、谱检查、bit-exact），这些是有价值的工程纪律；但**投入产出比最高的动作（把 G2 前移、在真实 VAE 上判一次）在路线图上不存在**。**

## 4. 结论

### 4.1 这个项目**现在**（commit `32449ae`）的价值是什么？

**分四层说清，不要混：**

| 层 | 价值 | 说明 |
|---|---|---|
| **产品/模型** | **0** | 没有权重、没有训练过、没有任何模型侧证据 |
| **设计文档** | **中上（同类个人项目里优秀）** | 有验证门、有退路、判据可执行、**装置层自证方法论是真的有效**。它比绝大多数"从零设计架构"的文档严谨得多。 |
| **可复现骨架** | **中** | 73 项自检 + 不变量审计确实立住了一批东西（bit-exact、可关断、谱检查、可逆算子）。但 `audit_invariants` 已查出 **7 个死旋钮 + 5 处写死魔数**（含 `QuantCfg` 全部 8 字段零执行点），**说明"自检全绿"与"旋钮真的活着"是两件事** —— 这是自检体系的盲区。 |
| **⭐ 单条最高价值资产** | **高（且独立于本项目）** | **G3 装置实测**：softmax 因归一化而**平移不变**（判别力恒 2,981×），Sigmoid 的对比度**强烈依赖绝对零点**（2,927× → 1×，塌 2,875×）；同时 Sigmoid 激活离群比低 2.85× ⇒ **NVFP4 量化友好性成立**。这是一个**诚实推翻自己立论**的发现，它证明了两件事：① 这套装置层方法论能产出真结论；② 设计稿 §4.3 的核心论证方向是错的。**这条结论可以独立发表/复用，是全部资产里最值钱的东西。** |

**⇒ 现在值不值得投？** 值不值得投的是"**下一个两周**"，不是"**下一个两年**"。

### 4.2 终局价值？值得投多少资源？

**终局价值判断：架构思想会被吸收，模型本身大概率不会赢。**

- **需求是真的**：8GB 段确实有大量用户；中文 + 二次元 + 角色一致性 + 可审计，这个四合一切口**目前没有单一模型占全**。
- **但窗口已经关了**：**2025-11 Z-Image-Turbo** —— 6B / Apache 2.0 / 8 步 / **原生中英双语文字渲染** / FP8 ~6GB / 开源榜首 / 支持 in-context 参考图（**这一条直接对标 CharaBridge**）。
- **8GB 显存这一格已经被占满**：Z-Image-Turbo FP8 ~6GB、FLUX.2 klein 4B 实测 ~8.4GB、Illustrious/NoobAI 6-8GB。**KP 要在 2026 年之后作为一个无生态、无权重的后来者挤进去。**
- **二次元这一格被占得更死**：Illustrious/NoobAI 用 **2000 万张** 精心标注的动漫图 + 最深的 LoRA 生态。**KP 打算用什么打？用 Micro-Budget 的 $1890 打 2000 万图训练出来的 SDXL 生态？** 这个问题设计稿没有回答。

**⇒ 资源建议：**
- **不该按现路线投 $30k-100k 的预训练。**
- **该投接下来 $5k-10k / 4-6 周** 做三件解耦验证（§4.3）。**验证通过再谈预训练；不通过就止损，损失可控。**

### 4.3 如果我是投资人 / 如果这是别人给我提的方案，我要求补什么才继续投？

**五个硬性要求，全部是"补证据"而不是"补愿景"：**

| # | 要求 | 为什么这是硬门槛 | 判定标准 |
|---|---|---|---|
| **R1** | **把 G2 前移**：在**真实 VAE + 真实动漫图**上，用 **Send-VAE 的低层属性线性可分性探针**（不是自定义的交叉扰动指标）+ **DA-VAE 式的"无对齐损失"负对照**，各跑一次 | 这是唯一"理论上可能不成立"的假设，现在被排在它 gate 的东西**之后**。任何投资人都会先问这个 | 语义 8ch 在细节 32ch 存在时的属性可分性，与反向，是否都显著高于随机。**若不显著 ⇒ 直接停** |
| **R2** | **把 Illustrious-XL / NoobAI-XL 加进 §8 对比表**，并给出 KP 在二次元上必须赢的具体指标线 | 现在的对照组是通用模型，不是这个赛道的真实对手。**这是框架错误，不是数据缺失** | 一张表：角色一致性、Danbooru tag 遵循、纯插画风格保真、显存、LoRA 生态可用性。**KP 至少要有一项明显赢** |
| **R3** | **商用数据许可方案**（不是"研究用"） | NOVA/Live2D 逐模型授权禁止 AI 训练与商用 ⇒ **权重不可分发 ⇒ 商业模式不成立**。这是**当下就是红的**风险 | 一份能落地的、可分发权重的数据来源清单 + 成本估算。**若无 ⇒ 整个终局价值归零** |
| **R4** | **二次元产品假设验证**：用户真的要"中文自然语言句子"而不是 Danbooru 标签串吗？ | P1.8 把它绑成了不可逆死线，但**从未验证需求**。社区主流（Illustrious/NoobAI/Pony）全在标签串生态上 | 一个可用的替代方案：**双模式**（自然语言 ∥ 标签串作为内部条件轴），或者先证明需求 |
| **R5** | **真实预算表 + 退出判据**：从零预训练 $30k-100k 量级（G6 的 $1890 前提已失效）；并预先写死"什么情况下停" | 目前没有退出判据。且 G2/G3.5 失败都要**重训**，不是微调 | 一张表：门 → 成本 → 通过线 → **不过怎么办**。**且 G2 的"不过怎么办"要真的写成"回到 SDXL 生态 + IP-Adapter"，并承认那意味着项目失败** |

### 4.4 最该砍掉的 3 件事

| 砍 | 理由 |
|---|---|
| 🗑️ **1. 可逆擦除账本（E / E⁻¹ / 账本元数据）** | **它解决的问题，项目还没有。** 它的价值锚点是"可分发权重的合规叙事"，而 R3 显示**权重根本不可分发**。现在砍掉**零成本**（现在不动，等做完模型再补是零成本；现在做，是要在 model card 格式、训练流程里插一套尚未有对象的东西）。**保留谱检查**（那是 L3 的承重墙），**砍掉擦除叙事**。 |
| 🗑️ **2. TypographyPack + 独立 Layout Planner（<0.6B + 100M-1B）** | 要**再训两个模型**，抢同一套数据管线和同一个 8GB 预算。而 **Z-Image 和 Qwen-Image 已经把中英双语文字渲染做进底座且是 Apache 2.0** —— 这是**最不差异化、总成本最高**的一块。且 KP 自己已实证：Sana 32× DC-AE 出「心夏北极星」是乱码。**从零建一套排版系统，去追一个别人已经免费给你的能力。** |
| 🗑️ **3. KP-M / KP-L 多档 + "KP-L 3B 仅作 teacher"** | **次序是反的。** 用一个还没训出来的 0.6B 去评判，还没资格要求一个 3B teacher。而 **Z-Image-Turbo（6B Apache 2.0）和 Sana-1.5 已经是现成的、许可干净的 teacher**。**先只做 KP-S 一个尺寸，直到有第二个尺寸的实测理由。** |

### 4.5 最该加码的 3 件事

| 加 | 理由 |
|---|---|
| ➕ **1. 把 G2 从"门"改成"前移的在线探针"，并按 Send-VAE 的方法重做判据** | 唯一"理论上可能不成立"的假设，却是全案排期最靠后的。**成本从"6 个月后发现"降到"3 周后发现"** —— 这一条改动**单独就能把项目风险敞口缩小一个数量级**。具体：Send-VAE（arXiv 2601.05823）的**低层属性线性可分性探针**是现成的、被验证过与 FID 强相关的工具，比自定义的交叉扰动指标更可信；**必须带 DA-VAE 式的"去掉对齐损失"负对照**，因为那是已知的失败模式。 |
| ➕ **2. 建一个二次元专用基准 + 商用数据资产（这两件事绑在一起做）** | 项目的全部差异化都建立在"主打二次元"上，而**这是唯一一格既有真实需求（8GB + 中文 + 角色）又有已被占据的强敌（Illustrious / Z-Image）的市场**。没有基准就无法判断 R2；没有数据许可，**终局价值直接归零**。这两件事是**当前唯一真正的关键路径**，其余都是可选项。 |
| ➕ **3. 用 DA-VAE 式"热启动"把架构验证与从零预训练解耦** | **DA-VAE（arXiv 2603.22125）在结构上和 KP 的 32× 混合 latent 几乎相同，但它是 plug-in：5 H100·天 LoRA 微调就让 SD3.5-medium 在 1024² 只用 32×32 token，FID 10.91 vs 原生 64×64 的 12.04。** ⇒ **可以在几周内、在已有 checkpoint 上，验证"KP 的 32× 混合 latent + 角色卡 + 8GB 显存"这套架构到底行不行**，而**不用先赌 $30k+ 的从零预训练**。这不否认 KP 的从零目标 —— 它把"架构是否成立"和"预训练能否收敛"两个问题**解耦**了。这是能想到的最便宜的判据。⚠️ 代价：这会让"无底模"这个身份主张在验证阶段不成立。**我认为这个代价是值得的 —— 因为现在最大的风险不是"没有底模"，是"结构可能不成立"。** |
