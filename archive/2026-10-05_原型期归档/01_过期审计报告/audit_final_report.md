### 1.5 🔴 `python -O` 下 73/73 全绿，但**71 项断言实际已失效**（本轮新发现，已复现）

这是本轮**最需要立刻修**的一条，因为它摧毁的是整个项目的验收基线。

**机制**：`kp/selftest.py` 的骨架是
```python
def check(name, fn):            # selftest.py:61-69
    try:
        detail = fn() or ""     # ← fn 内部靠 assert 判定
        RESULTS.append((name, True, detail))
    except Exception as e:      # ← 靠捕获 AssertionError 判失败
```
而文件里有 **171 处裸 `assert`**、只有 **3 处 `raise`**。
Python 的 `-O` 会把 `assert` 语句**整体移除** ⇒ `fn()` 变成"只算不判"，返回空串 ⇒ **被记为 True**。

**实测（我独立复现）**：
```
python    -m kp.selftest  →  73/73 通过
python -O -m kp.selftest  →  73/73 通过    ← 数字一样，但什么都不证明
```

**决定性最小证明**：
```
[无 -O] __debug__=True    assert 守护的检查(传-1)  ->  ❌ AssertionError
[有 -O] __debug__=False   assert 守护的检查(传-1)  ->  ✅ 报通过     ← 失效
                          raise 守护的检查(传-1)  ->  ❌ AssertionError  ← 仍有效
```

**影响**：任何带 `-O` 的 CI / `PYTHONOPTIMIZE=1` / 打包器，`73/73` 这条验收基线**静默失效且不报错**。
这与项目记忆里"静默失效"（LoRA 在 4-bit 下不出错但风格不变）是**同一类病**，只是这次发生在验收工具自己身上。

**修法（零成本）**：`kp/paths.py` 或 `kp/__init__.py` 入口加
```python
if not __debug__:
    raise RuntimeError("selftest 不可在 -O 下运行：assert 会被移除，验收基线失效")
```
更彻底的做法是把 `check()` 改成 raise-based 门函数。

### 1.6 🔴 3:1 混合注意力实际是 1:3.43，且断言容差带是围绕**实际行为**设计的

**实测**（我用 `build_attn_plan` 独立复算，与代码审查员一致）：
```
KP-S (L=24): softmax 1 / sigmoid 5 / linear 18  → 1:3.60
KP-M (L=32): softmax 1 / sigmoid 7 / linear 24  → 1:3.43
设计目标     : 1:3 = 0.3333
```

**根因是结构性的，不是笔误**：第 0 层被 softmax 锚点占用后，剩余槽位是 `L−1`。而
```
L=24 → (24-1) mod 4 = 3  ✗    L=32 → (32-1) mod 4 = 3  ✗
L=25 → (25-1) mod 4 = 0  ✓ 整除 → 恰好 1:3.00
L=33 → (33-1) mod 4 = 0  ✓ 整除 → 恰好 1:3.00
```
⇒ **只有 `L ≡ 1 (mod 4)` 时 3:1 才能整除**，而 KP-S=24、KP-M=32 都 ≡ 0 ⇒ 必然偏差。

**断言方向问题**：`selftest.py:1259` 写 `assert 0.2 <= ratio <= 0.35`，实测 `0.2917` 贴近上沿。
⇒ **这条容差带是围绕"实际发生的 1:3.43"设计的，不是围绕设计目标 1:3**。
这正是项目记忆里**教训 #5**（断言要检验设计想表达的不变量，不是代码当前的行为）的教科书案例。

**修法**：若 3:1 是硬约束 ⇒ `layers` 取 `4k+1`（KP-S=25 / KP-M=33），断言改窄带；
若锚点优先 ⇒ 显式加 `n_sigmoid` 覆盖字段算准数量，断言「sigmoid 层数 == 期望整数」。
**当前这条比例断言应降级为"报数"，因为它无法区分"符合设计"和"偏离但落在宽容带内"。**

### 1.7 🔴 40ch 混合 latent 在主干里**只是通道拼接**，不是结构分离

**位置**：`kp/latent/hybrid.py:141`（split_channels）+ `kp/models/dit.py:331`（patch_embed）

```python
def split_channels(x):        # hybrid.py:141
    sc = LATENT.semantic_ch
    return x[:, :sc], x[:, sc:]        # ← 纯切片，无任何算子
```
主干侧：`self.patch_embed = _gl(latent_ch, d)`，其中 `latent_ch = 40`
⇒ **是一个 40→1152 的稠密矩阵，40 个通道在同一组权重下线性混合。**
后续 24/32 层 block **完全不感知通道身份**。

代码里唯一让两块"分开"的机制是 `channel_mi_penalty`（只存在于 `separation.py` 的训练/验收装置）与 `swap_channels`（交叉扰动探针）——**都在 `kp/latent/` 与 `probe/` 域，DiT 前向路径零感知**。

**与设计稿的偏差**：设计稿要求"语义/细节通道分离"，且 `hybrid.py` 自述"**必须显式监督，否则主干会把两个通道都塞满信息**"。
代码把"显式监督"实现为**一个可微惩罚项**（训练期），但**没有任何机制阻止推理时 `patch_embed` 把两块混在一起**。
⇒ **"分离"在代码里是训练目标，不是结构保证。**

**这条与 §3.3 的 `cross_r2=0.988` 遥相呼应**：既然 `patch_embed` 是混合的、惩罚只在训练期，
那么"两通道冗余拷贝"就是**当前架构的必然结果**，而不是训练不足。

**修法**：若设计意图是结构保证 ⇒ `patch_embed` 拆成 `_gl(8,d) + _gl(32,d)` 后相加；
若设计意图就是"训练期软约束" ⇒ **把 `hybrid.py` docstring 里读起来像结构保证的措辞改成软约束**，
并补一条断言：训练后 `patch_embed` 在两块上的 Frobenius 能量比有下界。

## 3. 🟡 逻辑裂缝（3 处）

### 3.1 L310 立论已被推翻，但主文档的 3:1 仍靠它站着

主文档 §4.3 已在 v1.16 加了实测表格并**诚实标注** L310 未获支持 ✅。但：
- 3:1 混合注意力在 §0 摘要、§4.3 标题、§8 对比表里**仍以"去 softmax 防长提示稀释"作为卖点**
- 附录 A 的 `attn.ratio` 仍写 `"3 linear : 1 Sigmoid/Softpick"` 无条件说明

**实测结论**：Sigmoid 摊薄指数 α 0.88–1.00 vs softmax 0.16–0.89 ⇒ **Sigmoid 摊薄不轻反重**；判别力对绝对零点塌 2,875×。
⇒ **建议**：3:1 的立论重心正式移到 L311（量化友好性，实测离群比低 2.85×），并给 Sigmoid 加零点/温度控制 `σ(k(x−x₀))`。**不改结构，但改理由。**

### 3.2 L1 的 90% 覆盖率是**从未检验的前置假设**

`补充08` 已经写得非常清楚（「不是信赖，更准确是**从未检验**」）。但 `MEMORY.md`、`ONBOARDING.md`、主文档里 **90% 仍以既定事实的口吻出现**。

**实质风险**：一旦 G3.5 不过，L1 从"零成本覆盖 90% 调用量"静默降级为"方向性微调"，**没有任何指标会报警**。
⇒ 建议：所有出现 90% 的地方统一加限定「**（未验证 · G3.5 把关 · 不过则默认归 L3）**」。

### 3.3 ⭐ G2 真图实测的**判据盲区**（本轮新发现，⚠️ 后经复核实为**部分误判，见 §3.3b**）

`out/g2_real_vae.json`（19:06 生成，651s，5 臂）**已经跑出来了**——`HANDOFF.md §4.1` 说它"没验证过"，实际上是**已跑通且有结论**：

| 臂 | worst_dep | 判定 |
|---|---|---|
| A 冻结随机编码器（对照） | 0.0253 | PASS（但无图像语义，**不能当真图结论**） |
| B joint w_inv=1（主实验） | **0.0498** | **PASS** |
| C joint 负对照 w_inv=0 | 0.2215 | FAIL ⇒ **监督净收益 4.45×** ✅ |
| D 去掉信息锚 w_anchor=0 | 0.0353 | PASS（⚠️ 比 B 更好，见下） |
| **E 结构/纹理代理监督** | **0.3369** | **❌ FAIL** |

**盲点（成立的部分）**：交叉扰动判据**只测「分支运行时会不会偷看另一侧」**，
**不测「两块 latent 的内容是不是同一份信息的冗余拷贝」**。
若两分支各自不看对方、但每块都塞着全部信息 ⇒ **假分离**，而现有判据完全测不到。
**这个盲点是真的，且是 `MEMORY.md` 里担心的「主干把两通道都塞满」的 VAE 版本。**

⚠️ **同时 Arm D 去掉信息锚反而更好**（0.0353 < 0.0498）这件事本身需要解释：
可能是 anchor 项在拖后腿，也可能是 B 过约束而牺牲了信息量。**目前无法区分 ⇒ 不应据此改配方。**

### 3.3b ✅ 更正记录：关于 `cross_r2 = 0.988`，我**两次口径搞反了**（过程留档）

**这一节是本轮最重要的自我修正记录**，请连着读：

⚠️ 而这正是 `MEMORY.md` **通用教训 #1** 的一次完整复现：
> 「口径不全不下全局结论」——**用户/前人给出的实测观察往往正确，先重测自己的口径，不要辩解。**
> 我这次是**反过来**：先质疑前人的数字，做完发现自己错了。**教训升级为：质疑任何既有数字之前，先确认自己复现的是同一个口径。**

⇒ 教训 ④「跨块内容冗余度**可以**测，但必须用 `real_separation._r2` 的位置级口径」——
`separation.py::cross_predictability`（我中途写的、基于相关性的版本）**仍然无分辨力**，
但那是因为它测的是**块间绝对相关**，而正确的量法是**逐位置可预测性**。**方向没错，口径错了。**

### 3.3c ⭐ 仍然成立的新发现：判据盲区是真的，但**工具早就有了**

- **盲区（成立）**：交叉扰动只测「分支运行时会不会偷看另一侧」，**不测「两块 latent 的内容是不是冗余拷贝」**。假分离（各不看对方，但每块都塞满信息）会漏过。
- ⚠️ **但这不是"没有工具"**：`real_separation.py` 的 `block_cross_r2()` **已经算这个量**（且口径正确）。
  ⇒ **真正缺的是把 `block_cross_r2` 纳入 G2 的总判定**，而不是发明新指标。
- ⇒ **下一步应该是**：在 `separation.py` 的 `evaluate()` / `run_g2` 里引入
  `block_cross_r2`（**位置级口径**），设门线；并用 `_Oracle`（应低）/`_Leaky`（应高）做双向尺子校验。
  ⚠️ 本轮**未完成**（我先前的实现口径错了，已标注为待办）。

## 5. 项目价值判断

### 5.1 现在（今天这个 commit）值多少？

| 层 | 价值 |
|---|---|
| 产品/模型 | **0** —— 没有权重、没训练过 |
| 设计文档 | **中上**（同类个人项目里优秀） |
| 可复现骨架 | **中** —— 但"自检全绿 ≠ 旋钮活着"，7 个死旋钮是证据 |
| **⭐ 单条最高价值资产** | **G3 装置实测**（softmax 平移不变 vs Sigmoid 零点敏感，离群比低 2.85×）——**可独立复用，是全部资产里最值钱的** |

⇒ **值不值得投的是"下一个两周"，不是"下一个两年"。**

### 5.2 终局价值：需求真实，但窗口已关

**需求是真的**：8GB + 中文 + 角色一致性 + 可审计，这四合一切口没有单一模型占全。

**但格局已经变了**（联网核实）：
- **Z-Image-Turbo**（2025-11，6B，Apache 2.0，8 步，FP8 ~6GB，**原生中英双语**）已占"小模型+低显存+中文"
- **二次元赛道的真正对手不在对比表里**：**Illustrious-XL / NoobAI-XL**（2000 万+ Danbooru 图，LoRA 生态最深，社区共识纯二次元仍优于 Flux/Z-Image）。**拿通用模型当二次元项目的对照组，是设计稿最大的方法论错误。**
- ⚠️ **"混合 latent 创新点"已被 DA-VAE（arXiv 2603.22125, CVPR 2026）与 SVG（arXiv 2510.15301, ICLR 2026）占据**——两者都是"基础 latent + detail 通道沿通道拼接 + 显式对齐损失"，与 KP 几乎逐句相同
- ⚠️ **Matryoshka 引证错位**：引用的 PostDiff 数字（FID 18.42→15.69）出自 **SD v1.5 UNet + training-free 后处理**，不是 DiT 训练时 Matryoshka
- ⚠️ **G1 测的不是它声称测的东西**：NVIDIA 的 NVFP4 从零预训练（arXiv 2509.25149）证明的前提是 **RHT + 梯度随机舍入 + 2D scaling + ~16% linear 留 BF16 四件套缺一不可**；KP 做的是 adapter 式 QAD（只训 0.33%），G1 测的是 fake-quant 前向偏移。**"NVFP4 原生预训练能不能收敛"目前零证据。**

**G2 的排期是本项目最严重的风险控制缺陷**：它被标为"结构性门"（不过则 L1 全废、90/9/1 塌掉），却被排在**它所 gate 的 P1/P2 之后**。等于要先花 6 个月和几万美元，才知道地基有没有。

### 5.3 建议

**该投的**：$5k–10k / 4–6 周，做三件解耦验证：
1. **把 G2 前移**：在真实 VAE + 真实图上判一次，并**补 `cross_r2` 反向判据**（本轮发现）；用 Send-VAE（arXiv 2601.05823）的低层属性线性可分性探针（已被验证与 FID 相关 −0.9572），带 DA-VAE 式"去掉对齐损失"负对照
2. **加一个二次元专用基准**（Illustrious/NoobAI 进对比表，定出必须赢的指标线）
3. **商用数据许可方案**——NOVA/LiveD 逐模型授权禁止 AI 训练与商用 ⇒ **权重不可分发 ⇒ 商业模式不成立，这是当下就是红的风险**

**该砍的**（现在砍零成本）：可逆擦除账本（它解决的是一个还不存在的模型的分发合规问题）、TypographyPack + Layout Planner（Z-Image/Qwen-Image 已免费提供中英双语文字，且要再训两个模型抢同一预算）、KP-M/KP-L 多档（次序反了：Z-Image/Sana 已是现成干净 teacher）。

**核心判断**：**不要按现路线直接投 G6 预训练。先花 4–6 周把地基验了。** 这一步单独就能把风险敞口缩小一个数量级。
