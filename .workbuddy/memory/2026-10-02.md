**任务**：用户（模型设计方向）要求设计一个全新的文生图模型架构，非 SDXL/Flux 修补。仅做调研与规划，不实现。

**用户约束与目标**

- 痛点核心：LoRA 训练要极简易——提供角色的 3D 正视图 + 背视图就能训好；当前 WAI(SDXL) 能做到但**会与底模打架**；低数据训练必须可行。
- 明确不管：画风（归底模）。
- 用户自称非专业，但技术判断准确（主动指出 UNet 过时、SM120 最低 8GB 等）。

**设计核心（供后续继续推进时复用）**
- 架构名 POCKET-DiT（Precision-Optimized Compact Kernel-Efficient Transformer），中文名「囊萤」。
- **第一性原理：显存的第一因是 token 数，不是参数量。** 动作优先级 = latent 压缩率 > 注意力复杂度 > 权重位宽 > 参数量。NVFP4 是二级放大器。
- 五个模块：①蒸馏文本塔 ~220M（多层特征聚合，**不缓存 embedding**）②**混合 Latent** 32× 压缩（语义 8ch 对齐 DINOv3 + 细节 32ch 走 DC-AE 式重建，1024² 仅 1024 token）——创新点1，同时解决低数据与身份/画风解耦 ③单流 DiT 主干 0.6B/1.5B，3:1 线性:softmax 混合注意力 + QK-Norm + adaLN-Single + Mix-FFN 无位置编码 ④**CharaBridge** 多视角身份+几何双分支，gated cross-attn 注入第 4/10/16 层，可关断 bit-exact——创新点2 ⑤解码器分块 + 2 步 refiner。
- 创新点3：Matryoshka 式可伸缩深度（不同分辨率跑不同深度）。
- 创新点4：FP4 下 LoRA —— 主干冻结 NVFP4 + BF16 适配器 + **LoftQ 式初始化**（DiT 上是空白，原创空间）；**LoRA 注入点必须绕过量化器**（否则复现 FLUX 的静默失效 bug）。
- 不打架的四条机制：M1 通道分离 / M2 正交注入（门控初始化为 0）/ M3 Latent 解耦 / M4 可关断 bit-exact。
- 对偶视角损失（Antipodal Pair Loss）：置换不变性 + 对偶一致性 + 虚拟视角插值辅助监督 → 直接对着用户「正视图+背视图」场景。
- 显存目标：推理 ~2.5GB @1024²；LoRA 训练 ~4–5GB（8GB 卡可训）。
- 路线：P0 验证 NVFP4 假设（最高优先级，几天可验证）→ P1 换 Latent → P2 换主干 → P3 CharaBridge → P4 少步蒸馏。

**关键技术事实（已联网核实）**
- NVFP4 = E2M1 + 每 16 元素一个 FP8 E4M3 block scale + per-tensor FP32 scale，≈4.5 bit。
- **SM120 消费卡没有 tcgen05 / TMEM**，共享内存上限 99 KiB（SM100 是 228 KiB），FP4 只能走 per-warp OMMA/QMMA。不要自己写 kernel，用 CUTLASS sm120 或 TransformerEngine。
- NVFP4 QAT 四件套：敏感层保精度 / 权重 2D 16×16 block scaling / RHT 只加到 Wgrad / 随机舍入只加到梯度。
- NVIDIA FLUX.1 数据：FP4 PTQ 掉点（IR 1.118→1.096），FP4 QAT 不掉点（1.119）。
- Z-Image-Turbo：6B S3-DiT 单流 + Qwen3-4B 文本塔 + 8 步 + Decoupled-DMD，16GB/FP8 6GB，Apache 2.0。
- Sana：Linear DiT + DC-AE 32× → 1024² 仅 1024 token。
- 敏感度排序：MLP up/down 最敏感，attention projection 较不敏感，最后几层最敏感。

## 补充设计 01（同日追加）：底模策略 + 注意力稀释

**用户追加问题**：① 底模该定什么？他不想走 SDXL / Flux 两大方向，但愿意结合一点 Flux；问底模选择有无限制。② SDXL 提示词一多注意力就涣散、开始乱画，希望这是优化空间之一。用户自称「小白」，要求解释这两个问题。

**关键结论 —— 底模**：本案**不设底模，只设教师**。理由：架构全自研（换 VAE / 换文本塔 / 换主干），**一个权重都继承不了**，继承权重在数学上不成立；这反而是好事——不受任何底模架构约束。选择标准变为「哪个教师能蒸馏出最强 student + 许可证允许分发」。
- 教师选型：主教师 **Z-Image-Turbo**（6B, Apache 2.0）+ FLUX.1[dev] 仅离线对照 + **DINOv3** 语义锚定（跨教师通用的公共语言，使教师可替换）+ Qwen3-4B 文本教师（蒸馏到 220M）。少步蒸馏不要链式抄袭 Z-Image-Turbo 的 8 步。
- 三条限制：**许可证**（硬墙；坑：FLUX.2[klein] 4B 是 Apache 2.0 但 9B 是 Non-Commercial）、**Latent 兼容性**、**算力**（教师只需离线跑一次）。
- 从 Flux 借：rectified flow + **浅层前 4–6 block 保留 double-stream**。不借 12B 规模 / T5-XXL / 全栈双流。

**关键结论 —— 注意力稀释**：病根是 **softmax 把所有 token 的概率归一化到总和为 1 → token 互相抢概率质量**，提示词越长有效词份额越小。SDXL 三重叠加：① 两个 CLIP 各 77 token（可用 75）硬上限 + UI chunking 跨块注意力断裂且训练时没见过；② softmax 稀释；③ CLIP 是 bag-of-concepts，对空间关系无感。
- 硬数据 **T2I-CompBench**：SDXL-base 平均 42.5（**Spatial 仅 21.3**，Color 却有 58.8）；FLUX.1 平均 53.2（Spatial 28.6）；OmniGen2 55.3（Spatial 39.3）；最优 Bagel+R3-Refiner 58.8。→ 精确对应用户「颜色管得住、位置管不住」。
- **POCKET-DiT 解法（v1.1 修订）**：把 softmax 换成 **Sigmoid / Softpick 注意力**（非归一化，互不抢占）；新增 **16 个 layout token 两段式路由**（4×4 粗网格 + 2D 位置编码）；文本 KV 按角色分组；小 LLM 提示词编译器；后训练用 GORS 式奖励筛选。
- **⭐ 重大发现**：Sigmoid / Softpick 注意力能做到接近零 attention sink 率并**显著减少激活离群值 → 让低比特量化更鲁棒**。而 attention sink 正是 NVFP4 最怕的 outlier 来源之一。**一个改动同时解决长提示稀释 + FP4 精度两个问题。**
- 代价：必须从零训练（无所谓）；需自写 Triton kernel；过度平坦损失 sharp attention → 保留第 0 层一次 softmax。
- 新增验收指标：T2I-CompBench Spatial > 35，平均 > 55，长提示（>150 token）一致性不退化。

## 补充设计 02（同日追加）：能力总线 + 文字渲染

**用户追加问题**：① 想留一个可插拔接口给「不限全年龄」内容——但**重点不是那类内容，是可扩展性**（以后能套更多画风、更多未来选项）；② 不理解「专家模型」和「小模型」怎么连在一起，听说有「不用重训」的专家模型式解法；③ 希望模型能自己写文字、自己排文本框（像同人志嵌字），但觉得新模型「太大量了」。用户自称小白，要求解释。
- 边界处理：明确不生成/不参与制作那类内容的图像与训练数据，但把问题**当纯工程问题回答**——架构上它就是能力总线里的一行，与「画风包」结构同类，天然被覆盖，**不需要为它额外做设计**。用户接受。

**核心结论 —— 「专家模型」的两个歧义（这是用户困惑的根源）**
- **LoRA 专家 / 能力包**（Mixture of LoRA Experts、Adapter Bank）= 挂在冻结主干上的低秩小模块 → ✅ 这才是用户要的。
- **稀疏专家 MoE** = 主干内部 FFN 拆分，每个 token 走 1–2 个 → ❌ 不是这个。**关键反直觉点：MoE 省算力（FLOPs）不省显存**，全专家权重都要驻留，对 8GB 卡是负担，且必须随预训练设计。
- 比喻：手机（小主干，常在）+ App（专家包，按需加载）。「不用重训」= 手机不出厂，装 App 就行。

**⭐ 核心判据（本案最值钱的一条）——「可插拔」的分界线**
- 低秩扰动 ΔW=AB 只能做 rank-r 子空间内改动。
- **同一支撑集内**（概率质量重分配）→ 能装包：画风 ✅ / 角色身份 ✅ / 领域倾向 ✅（rank 要大）/ 构图偏好 ✅。
- **支撑集外扩**（底模几乎不产生这种输出）→ 必须进预训练：**文字渲染 ❌** / 手部解剖 ❌ / 纯空间关系推理 ❌（→ 走主干设计）/ 新条件模态 ⚠️（需新增分支）。
- 一句话：**低秩适配能改「怎么画」，不能改「看得见什么」。**

**能力总线（Capability Bus）设计**
- 结构：冻结主干 ← 门控总线（g 初始 0）← 能力包 {ΔW, g, 元数据}。
- **bit-exact 不变量**：全部门控=0 时输出与裸模型逐位一致 → 接口本身零风险，挂 100 个包不影响裸模型。
- **四个正交作用维度**：Layer-scope / **Channel-scope（语义 8ch vs 细节 32ch，把 CharaBridge 机制升级为全局）** / Time-scope / Space-scope(ROI)。
- 包体积实算（1.5B、24 层、d=1536）：仅 attention rank16 ≈4.7M/9MB；**全层 rank16 ≈13.6M/27MB**；rank32 ≈27M/55MB。100 个包 = 5.5GB 磁盘，但显存只需按需挂 3–4 个（~200MB）→ **选择变多，显存不变**。
- 冲突仲裁升级：降 lr / Dropout（被动）→ 门控归一化 → **正交化投影（NP-LoRA 式：SVD 找 A 包主方向，把 B 包更新投影到其零空间）**。⚠️ 硬证据：**LoRA 专家「朴素平均/均衡共享」会掉点**（2025 多项消融），不要用简单 ΣαₖΔWₖ。
- **强制规定：注入点必须绕过 NVFP4 量化器**（复现 FLUX 4bit 路径 LoRA 静默失效 diffusers #9291/#10989 的坑）。

**⭐ 文字渲染的核心障碍（本轮最重要的技术发现）——32× 压缩与文字互斥**
- 主干 32× 压缩 → 1024² 仅 1024 token；**40px 汉字只占 1.25 个 latent 格，24px 可读下限只占 0.75 格** → 汉字还不到一个格子大，**字在编码阶段被物理性丢弃**。
- 这是**信息问题不是容量问题**：任何 rank 的 ΔW 都无法从不含该字的表征里造出该字。**这就是上面那条判据的物理来源。**
- 降回 8×？→ 1024² 变 **16384 token**，注意力 O(N²)，8GB 直接爆。**「文字好」与「显存小」在同一 latent 里互斥。**
- 解法：**主干一动不能动，文字走独立低压缩 ROI 分支（TypographyPack）**。
- TypographyPack：Layout Planner 出框 → 裁 ROI（<10% 画面）→ 4× 压缩编码 → 字形灰度图（字体光栅化）+ 位置图 + 字体 embedding + 颜色 → **AttnX 式 cross-attn 注入（α/β 控融合强度）** → 字符级 CTC 监督。参数量 <0.6B。**同类方案 AnyText2 demo 8GB 可跑**（中文 +3.3%、英文 +9.3%、推理快 19.8%）。仍是可插拔包。
- 三条路线：T0 确定性排版（字体引擎渲染后合成，正确率 100% 但不参与光影融合，**真实漫画行业就这么干**；ComfyUI 已有 Illustrious Comic Lettering 节点）／**T1 字形条件分支（推荐）**／T2 端到端预训练（Qwen-Image 路线：低压缩 VAE + 课程学习「先无字后有字」，暂不做）。
- AnyText2 论文总结的注入机制取舍：「prompt 里条件 embedding」→ 泛化不到未见字符；「latent 里辅助像素」→ 预渲染字形与 caption 融合不足；正解是两者组合、用 WriteNet 把文字生成与图像生成解耦。
- **经验法则**：能装的包只改权重（LoRA）；必须加的包可以带结构（分支）——只要主干冻结、门控可关断。

**⭐ 事实校正：文字能力天花板不是参数量**
- 中文单字渲染字典覆盖率 ChineseWord↑：SDXL(2.6B) 基本不可用 / Seedream 3.0 33.1 / GPT Image 1[High] 36.1 / Qwen-Image(20B MMDiT) 56.6–58.3 / HunyuanImage 3.0(80B) 58.5 / **LongCat-Image(6B) 90.7**。
- **6B 碾压 20B 与 80B**（1.6× / 1.55×）→ 天花板是 ①字形条件 ②数据配方 ③课程学习。⚠️ ChineseWord 衡量字典**覆盖广度**非逐字准确率。
- 直接回答用户「新模型能写字但太大量了」的顾虑：**不需要 20B，需要正确的配方。**

**Layout Planner（"自己会文本框"）**
- 版式规划 = **符号推理 + 几何输出**，与像素生成是两个任务，**不要指望 DiT 做**（任务错配）。
- 规模 100M–1B 小模型（甚至微调小 LM）。输出 JSON：`{canvas, panels[], items[{type, poly, tail_to, text, font, size, align, emphasis}]}`，一个字像素都不碰。
- 数据两条腿：① Manga109Story **21,142 页 / 109 卷**（panel 坐标 + 文字标注 + 对话-说话人配对 + 阅读顺序；⚠️ 需确认许可）② **合成白拿——字体光栅化确定性、成本≈0**（中文 6763 常用字 × 数千字体 × 无限背景）→ **全案唯一一种零成本无限扩增的训练数据**，正是用户第一轮说的「更聪明的数据供给方式」。
- 可抄经验：MangaDiffusion（FID 143.5 vs SD3.5-Large 197.8）用 inter-panel attention + **局部掩码（训练时把对话框区域从 attention 与 loss 里 mask 掉）** → 印证「文字与画面必须解耦训练」。

## 补充设计 03（同日追加）：LoRA 的两个天花板 + 三层控制栈 + 一处重要更正

**用户追加观察**（自称「这是我的理解」，实际完全正确）：① LoRA **泛用性极差**——哪个底模训的只能哪个底模跑（他说"没必要搞成兼容的样子"，但通用性太差）；② LoRA **功能性极其有限**——给二次元模型打一个 LoRA 做不出接近写实的提升，**提升上限太低**。并要求「总体再想想还有什么可优化的，你来择优选择，不必急于回答也不要过度思考」。

**根因（两条是同一个病，且与「文字渲染」同病）**
- **LoRA 是加法**：只能放大/削弱底模已有的东西，不能创造没有的。外部原话："LoRA adapters are additive only: they cannot subtract from the base model's knowledge. If your base model is bad at a task, LoRA will not fix it."；"adapter weights are tied to the exact shapes of the frozen layers"。
- 三个现象一个根因：二次元→写实（支撑集外扩）／SDXL→写字（支撑集外扩）／换底模即失效（**ΔW 定义在 W₀ 的坐标系里**）。
- **泛用性差是数学必然不是工程缺陷**（ΔW=BA 描述的是"相对这个 W₀ 往哪偏"，W₀ 变则坐标系变）。继续在"让 LoRA 更通用"上用力是错方向。

**⭐ 主攻方向：三层控制栈（让 LoRA 只做长尾）**
- **L1 主干内生条件轴**（覆盖约 90% 需求，**成本为零**，推理时一个数值）：风格/写实度/光照/色调/笔触。
- **L2 外置条件编码器**（约 9%）：身份/参考图 → 特征空间条件 token。**必须外置**——权重扰动会"覆盖"底模先验（打架的物理原因），并联通路物理上不可能覆盖；且条件向量与主干版本耦合远弱于 ΔW。
- **L3 子空间约束 LoRA**（约 1%，27MB/包）：只剩底模真没见过的。
- 核心：**不要在"让 LoRA 更强"上用力，而要让 LoRA"不需要做那些事"。**

**L1 可行性的两个先例**：PARASOL（CVPRW 2024，内容 + 细粒度风格 embedding 联合条件化，改写 CFG 解耦控制，三元组用内容/风格检索构造）；Stylistic Attribute Control in LDM（arXiv:2605.02583，从**合成数据集**学**解耦的风格编辑方向**：描边/局部对比/水彩化/几何图案，**连续可调**）。⚠️ 风格必须在**预训练阶段**建模，做不了事后补——**这正是我们自研从零开始的优势**。

**⭐ L3 的免费升级：SVD 子空间约束（LoRA-X, ICLR 2025）**
- `W₀ = UΣVᵀ`；`ΔW = Ũ·ΔΣ·Ṽᵀ`（Ũ/Ṽ 为 W₀ 冻结奇异向量，只训 ΔΣ）。适配器语义从"往哪偏"变成"底模已会的东西里哪几样该加强/削弱"→ **跨模型成立**。
- 迁移 = 闭式投影，**零训练瞬时完成**；BlueFire 风格上 **HPSv2 比从零训还高 3.6%**，DINOv2>0.85，比 X-Adapter **快 4.6×**（3.7s vs 17.1s）；**越深的层子空间越相似**。
- 同类 **Cross-LoRA（arXiv:2508.05232）** data-free/training-free，商品级 GPU **20 分钟**，相对收益最高 +5.26%。
- **对我们的意义（零成本）**：我们控制主干版本演进 → 让每个包从第一天起就训在主干自己的子空间里 → 泛用性只需做到"**跨我们自己的 v1→v2→v3 可迁移**"。

**⭐⭐ 数据钥匙（新的白拿数据）：shader 配对**
- L1 需要**内容完全对齐、只有风格不同**的图对，网上爬不到（真实世界不存在"同一张脸同一姿势的写实版和赛璐璐版"）。
- 但渲染器可免费生产：**同一 3D 场景 × 不同着色器 → 几何/光照/相机/姿态完全一致、只有渲染风格不同的完美配对**。风格轴：PBR 写实／赛璐璐／平涂／水彩／厚涂／线稿。
- 把 §7.1 的 Engine-Synthetic Triplet 从「角色轴」扩展为「角色 × 风格」双轴：**一条 3D 资产生产线同时养活角色、几何、风格三条需求**。与 §4.7.8 的字形数据同一思想——**让渲染器生产数据，而不是去爬别人的图**。

**⚠️ 全案第二个隐藏关键假设（新发现，必做）：通道分离会「退化」**
- §4.2 的「语义 8ch 管结构 / 细节 32ch 管画风」**只切通道不加监督，主干一定会偷懒**——重建最简单的办法是两个通道都塞满信息。于是通道分离名存实亡，画风解耦失败，**整个 L1 是空谈**。
- 必须加显式监督：① 交叉扰动测试（替换/打乱细节通道，要求语义通道仍能独立支撑结构重建）② 反向扰动（破坏语义通道，要求细节通道不补位）③ 通道互信息惩罚。

**新优化点：分辨率维度 Matryoshka（免费午餐）**
- §4.4 只做了深度维度伸缩，**没做分辨率维度**。
- PostDiff（ICCV 2025, arXiv 2508.06160）混合分辨率去噪：早期低分辨率、后期全分辨率。**FID 18.42 → 15.69（改善），FLOPs −60%**；结论「**降低每步成本比减少步数更有效**」；意外发现低分辨率早期步骤还**增强低频成分**；U-Net/Transformer、大/小模型、LDM/LCM 全部有效。LowDiff（arXiv:2509.19042）吞吐 **+50%**，ImageNet-256 FID 4.00。
- 对我们：1024 token 的前几步只跑 **256 token**（注意力便宜约 16×）。⚠️ 需位置编码自适应（我们 Mix-FFN 无位置编码 + QK-Norm 天然占便宜）+ 噪声调度对齐，**必须一开始就留好**。

**❗ 重要更正（推翻我自己在 v1.0 写的判断）**
- 原文：「从零预训练一个 T2I 底模需要千万级算力，不是个人能承担的」——**已被推翻**。
- Sony AI **Micro-Budget Diffusion（arXiv 2407.15811）**：**1.16B 稀疏 Transformer + 3700 万张图 → 总花费 $1,890，零样本 COCO FID 12.7**（8×H100, 2.6 天）。配方：**256→512 渐进分辨率 + 75% patch masking（在 patch-mixer 之后丢 patch）** 的四阶段；关键发现 **patch-mixer 显著降低 masking 的性能退化**。佐证：HDM（2025）在**消费级 4× RTX 5090** 上训出有竞争力的 T2I。
- 我们条件更好：0.6B/1.5B（比 1.16B 小）、1024 token、引擎合成数据。**「逐层替换」仍是稳妥起点，但「从零训练」不再是需要放弃的选项。**

**一个未检验假设（先测不改）：文本侧 token 预算**
- 图像压到 1024 token，但**从未优化文本侧**。若文本塔输出 200+ token 变长序列 → 占总序列约 16%，且在最贵的注意力上消耗。
- 候选解：文本塔输出**固定长度压缩**（64 语义槽，Perceiver/Q-Former 式）。⚠️ 代价：牺牲细粒度属性绑定，**直接撞在「长提示涣散」上，可能与 Sigmoid 注意力改造互相抵消**。
- 建议：P0/P1 阶段加消融（变长 200 token vs 固定 64 槽 在 T2I-CompBench 上的差），**先测不改**。

P1 子空间约束（零成本）／P1 通道分离显式监督（必做）／P1 分辨率维度 Matryoshka（免费午餐）→ P2 风格条件轴 + shader 配对数据（真正解决"功能性有限"）／P2 文本槽位消融 → P3 Micro-budget 配方落地。

## 第 5 轮：身份载体与双向包体系（补充 04，2026-10-02 晚）

**用户新诉求**
1. 想要一种**比 LoRA 更好（或互补）的「炼丹」方式**：给角色**完全正面 + 完全背面**两张 3D 图，就能"训练"出这个角色，理论上信息量接近一个 3D 模型；**不一定要替代 LoRA，可能互补**。
2. 想要一个**拓展包**让模型既能画写实又能画二次元，后期可像拓展一样更改。
3. 问**要不要支持 ComfyUI**，支持成本是否过高、是否必要。
4. 补充：模型**以二次元 / 日系画风为主**（暂不影响架构讨论）。

**三条关键调研发现（本轮最值钱）**
- ⭐ **「打架」的物理机理找到了**：MIT CSAIL（arXiv 2410.21228）发现 LoRA 会产生 **intruder dimensions（入侵维度）**——**近似正交于底模权重奇异向量的全新高排名分量**，全量微调不会产生。后果是"成为预训练分布的更差模型"。**不是覆盖，是侵入**。→ 直接推出设计律：**ΔW 可以入侵底模，旁路与条件不能；能力越"域外"越不能住在 ΔW 里**。
- ⭐ **身份可以是外置适配器**：腾讯混元 **InstantCharacter**（arXiv 2504.12395）单图驱动、stacked transformer encoder、1000 万级数据集分 **paired（多视角）+ unpaired（文本-图像）** 两路，**可与风格 LoRA 同时加载**。局限：动物角色不稳定；`nb_token=1024` 拼接身份 token（**我们不能照抄**）。
- ⭐ **二次元的正确表征是 2.5D 分层，不是 3D 网格**：See-through（SIGGRAPH 2026, arXiv 2602.03749）拆 **19 类语义 RGBA 层 + 遮挡补全 + 伪深度绘制序**，数据引擎自 **9,102 个 Live2D 模型**自举。论文原话：全 3D 建模管线对二次元"不实用且美学不兼容"。

**本轮确定的架构条目（15–22）**
- ⑮ **身份载体（Character Carrier）升为一等公民**：新数据类型**「角色卡」**，约 **1–5MB**（19 层 × 1024 token × 32ch × fp16 ≈ 1.25MB + 深度/元数据），**不依赖底模坐标系 → 跨版本可用**。三段式：① 训一次 **Character Fitter** ② 换角色 = Fitter 前向一次（**秒级**，峰值 ~1.2GB）③ 可选精修。
- ⑯ **双向包体系二分**：**并联包 ∥-Pack**（旁路/条件编码器，100M–1B，**物理上不可能打架**，负责跨域能力如写实、文字）/ **叠加包 Δ-Pack**（ΔW，27MB，**必须锁在底模 SVD 子空间**，只做同域长尾）。**LoRA 仍是第三列最优，只是作用域必须被限制。**
- ⑰ **「禁止入侵维度」硬约束**：Δ-Pack 必须建在 `W₀` 自身 SVD 子空间；训练后做**谱检查**——发现与 `W₀` 全部奇异向量 cos < 0.1 的高排名分量即判不合格。
- ⑱ **叠加包规格升级**：**块对角分解**（RaLoRA 式，**有效秩 r → n_l×r，参数量不变**）+ **rsLoRA `α/√r` 缩放** + 按 **GID** 分层 + **`W_o` 优先分配预算**（Transformer 里 `W_o` 的 GID 始终最高）。依据：ICLR 2026 GID Alignment（GID 30–1000，差 100×；块对角实测超 DoRA/AdaLoRA）、BD-LoRA（arXiv 2510.23346）、arXiv 2405.09673（全量微调更新秩为 LoRA 的 10–100×）。
- ⑲ **身份 token 走 cross-attention，不拼主序列**：预算 **256 token**（非 InstantCharacter 的 1024）。理由：我们全图只有 1024 个图像 token，拼接会让**序列翻倍、注意力成本 ×4**。收益：序列不膨胀 / 与文本 token 完全隔离（不二次稀释）/ g=0 时 bit-exact。
- ⑳ **主干双域预训练 + domain 条件向量**（默认 anime）→ 让「写实」成为**内生旋钮**而非外挂。**必须在预训练阶段就定**：纯二次元主干的写实先验几乎为零，事后外扩远难于混合域主干。退路：事后加「域包」必须是**并联包**（体量大两个数量级，需重训）。
- ㉑ **ComfyUI 不作为路线依赖**。真实成本在**架构特征**不在节点：三块硬骨头 = **40ch 混合 latent** / **非 softmax 注意力** / **能力总线门控**。主交付 = **diffusers 兼容 `ModelMixin` + 单文件 safetensors + 30 行推理脚本 + Gradio**；预留四接口（同构单文件权重 / latent 打包解包纯函数 / **attention 可替换** / 统一 `load_adapter()`）。最终由 **Comfy-Org 官方化**（FLUX.2 / HiDream / Lumina「within days of release」，ERNIE-Image 开源当天即有官方模板）。⚠️ **NVFP4 单文件在 ComfyUI 的可用性未查到确证 → 并入 P0 实测**。
- ㉒ **TypographyPack 与角色卡共用同一套分层表示**（19 类语义层 + 文本框层）。

**新发现的数据线（可直接用，但许可证高风险）**
- **NOVA-Human**（NOVA-3D, arXiv 2405.12505）：**10.2k 个 VRM 二次元角色**，**16 随机视角 + 4 固定正交视角（front/back/left/right）**，共 **163.2k 图**，512²，A-pose，**仅漫反射光照**，带精确相机参数。
- **See-through 数据引擎**：自 **9,102 个 Live2D 模型**自举 19 类语义层标注（代码开源）。
- ⚠️ **许可证高风险**：VRoid Hub 逐模型独立授权，多数禁止 AI 训练/商用 → **只能研究用，绝不能进可分发权重**；商用资产线必须自建或购买。
- 技巧：**标准正交视图由我们自己用渲染器生产**，不指望用户提供（业界痛点是「AI 不会画标准三视图」）。

**「完全正 + 完全反」为什么对二次元是强约束**（回答用户直觉）：① 二次元设定图天然**轴对称**，完全正/反正好落在对称面上，左右一半信息免费补全；② 二次元**几何靠轮廓线不靠光影**，信息几乎全在"轮廓线 + 色块边界"，两视图并集覆盖绝大部分形状（写实相反，信息大量在材质/光照里）；③ 正/反**来自同一张设定图，严格一致**（写实的正/反几乎不可能是同一人同一姿势）。→ **用户直觉正确。**

**更激进选项**：arXiv 2511.03156（Samsung AI）用 **Hypernetwork 直接预测 LoRA 权重**，靠**输出正则化**稳定（等价自动早停）+ **HM-CFG** 混合底模构图能力与身份保真度。**我们的变体**：让 hypernet 预测**角色卡的条件编码**（而非主干权重）→ 连"解算"都省掉，**给图出角色、零优化**。

## 补充 05 · 可逆擦除与能力谱系（v1.5）

**问题（纯工程接口讨论）**：架构能否像「二次元↔写实」那样，预留一个可插拔的能力接口。用户明确要求不生成任何相关内容，且不要重复边界声明。

**核心结论：技术可行，且是整套能力谱系里最便宜的一类，比跨域便宜一个数量级。**
- 对称性：**加能力 = 减能力取反**。现代概念擦除已被证明是 **闭式 / 低秩 / 秒级**。
- 关键数字：安全子空间**有效秩 k≈6**（LoX，α≈1.25 外推即可改行为）；**CURE（NeurIPS 2025）闭式光谱投影 22 秒**；MACE（CVPR 2024）闭式 cross-attention 精修可扩到 100 概念且多 LoRA 互不干扰；GLoCE 门控低秩（可开关）。
- 机理：arXiv 2505.17013 证明擦除**多数是「引导式回避」而非销毁**，被擦概念可被「向去噪轨迹重新注入噪声」捞回；安全微调学的是**近正交于 W 的 ΔW，列空间对齐 W 的零空间**（是滤波器，不是重学）；不安全激活塌缩到单一方向（首奇异值 ~62% vs 12%）。

**判据补全（important，v1.3 那版有缺口）**：原判据「支撑集内=低秩可做 / 支撑集外=不可做」漏了**「支撑集内、但被人为推出去」**这一类。完整判据 = **两问**：① 底模见过吗？② 被人为抑制过吗？

**架构贡献：可逆擦除账本（§4.7.10）**。把合规抑制实现为**显式低秩算子 `E = Σαᵢuᵢvᵢᵀ`** 并记录 {基, 有效秩, 作用层, 强度, 保留集边界}；则 **`Pack_recover ≡ E⁻¹`**。因为我们自己在数据阶段做过滤 → 我们**知道**擦了什么（社区做不到）。同时改善擦除本身（generality/specificity 可测量、α 连续可调、作用层按 SSB 选在深度 ~2/3）。门控默认 0 + bit-exact ⇒ **接口成本严格为零**。

**成本三档**：秒级·闭式（恢复被抑制的能力）｜小时级（长尾内容分布，Δ-Pack）｜天级（跨域：写实/文字，∥-Pack）。**工程含义：先做①②，覆盖绝大部分需求，完全不动主干。**

**CA-LoRA 教训**：LoRA 是低秩的，而压缩/抑制造成的损失**常非低秩** → 恢复包内允许 `σ(XD)U` 轻量非线性并放宽 rank 预算。

**数据供给升级为「四旋钮」**：视角 / 着色器 / **分层可见性** / 姿态，四者正交 → **配对样本组合式扩增**。现成证据：**SynBody（ICCV 2023）的 SMPL-XL 分层参数化人体**（Base Body / Hair / Garments / Accessories；1.2M 图 / 10k 模型 / 1,187 动作；**CC BY-NC-SA 4.0，仅研究用**）；**UnrealPose（arXiv 2601.00991, 2026）** UE5 管线开源、100 万帧。

**部署三层责任**：模型层（干净底座+门控+账本）/ 包层（能力）/ 部署层（策略）。依据：**训练期对齐在工程上不可靠**——无害数据（GSM8K）微调 2 epoch 即可把拒绝率从 ~0% 打到 50%+；0.2% 权重复位即可把有害率 33.25% → 1.74%。

## 补记 3 · 功耗天花板翻案（用户反驳 → 推翻 v1.2/v1.9 的核心结论）

**用户原话（关键）**：「在考甜甜圈的时候，我确实跑到过 109 瓦的数据，而是因为你激活的不够标准，不符合华硕的预期……这台机上线就是 115 瓦。」

**结论：用户完全正确，v1.2/v1.9 的「功耗天花板 ≈80W、115W 不可达」是错的。**

### 三方对账（权威证据）

| 来源 | 数值 |
|---|---|
| 本机 `nvidia-smi -q -d POWER` | **Max Power Limit = 115.00 W**，Default 55 W，Min 5 W |
| NVIDIA 官网规格表 | RTX 5050 Laptop GPU：**GPU 35 – 100 W** |
| Notebookcheck / MSI 规格书 | **115W Maximum Graphics Power with Dynamic Boost**（基频 100W + DB） |
| ASUS 官方 FAQ（1047107） | 「**Dynamic Boost 支持系统动态地将电源从 CPU 转移到 GPU……该值越高，可从 CPU 转移到 GPU 的功耗越大**」 |

**激活条件（NVIDIA / ASUS 口径）**：Dynamic Boost 只在 **接电源 + GPU 负载足够高 + Performance/Turbo 模式** 时激活；Windows 上依赖设备管理器里的 **「NVIDIA Platform Controllers and Framework」** 组件。本机 Armoury Crate 全套已安装。

### 新实测（`tools/power_ceiling_probe.py`，5 种负载形态 × 各 18 秒）

| 负载形态 | 稳态 | 峰值 | SM 峰值 | 温峰 | 降频标志 |
|---|---|---|---|---|---|
| bf16 大 GEMM（纯 tensor core） | 79.7 W | 80.9 W | 2842 MHz | 78 °C | **`0x0`** |
| **FP4 block-scaled GEMM** | **113.0 W** | **113.8 W** | 2797 MHz | 82 °C | **`0x0`** |
| D2D 大拷贝（纯显存带宽） | 68.4 W | 68.5 W | 2842 MHz | 70 °C | **`0x0`** |
| fp32 大 elementwise（SM ALU） | 66.9 W | 69.7 W | 2850 MHz | 68 °C | **`0x0`** |
| 三流并发 mix（GEMM+拷贝+ALU） | 79.8 W | 81.2 W | 2835 MHz | 79 °C | **`0x0`** |

日志 `power_ceiling_log.csv` 中 FP4 段连续 19 秒采样稳定 **108.14 → 113.80 W**。

### 根因（我的错误）

**测量口径错误**：v1.2 的 80W 是 **bf16** 阶段的功耗，我把它当成了整卡上限。**功耗是「负载形态」的函数**，不是固定的墙。

### ⭐ 方法论（新永久规范）

1. **功耗必须按负载形态分别测**，不能用一个负载的功耗代表整卡上限。
2. 测功耗上限**必须同时读 `clocks_event_reasons.active`**——这是判定「是否被限住」的**唯一权威信号**（NVIDIA 口径：只有 SW Power Cap 为 `Active` 才算功率受限；满载接近上限 + 温度正常 + 时钟不降 = 健康充足的 GPU）。
3. 本次 5 种负载全部 `0x0`，SM 时钟 2790–2850 MHz（**高于官标 boost 2662**），温度最高 82 °C ⇒ **卡完好无损地吃到了 113.8 W，没有任何东西在拦它。**

### 为什么 FurMark 109W 而 bf16 只有 80W

FurMark 是 **「power virus」**——用光栅/纹理/ROP 这些**能效极差**的单元烧电，只烧瓦数、不产生 AI 算力。
而 **FP4 用 113 W 打出 120.5 TFLOPS（1.07 TFLOPS/W），bf16 用 80 W 打出 25.8 TFLOPS（0.32 TFLOPS/W）——FP4 每瓦算力是 bf16 的 3.3 倍。**

### 对项目的影响（结论不变，证据更强）

- ✅ **修正口径后的收益递减**：**FP4** 45.7→113.0 W（×2.47）而算力 99.2→120.5（**仅 ×1.21**），静音档已拿到满血 **82.3%**；**bf16** 45.7→79.7 W（×1.74）而算力 ×1.23，已拿到 **81.0%**。
- 🎯 **「瓶颈是 20 SM 而非功耗」现在有了硬证据**：FP4 在 113 W 下**已逼近 20 SM 的 tensor 理论峰值**（20×1024 MAC×2×2.797 GHz ≈ 114.6 TFLOPS，实测 120.5 已在该量级）→ **再给瓦数也买不到 FLOPS**。
- ✅ **设计主线的 FP4 路径正是把功耗打满的那条**，这是好消息。
- 📊 H100×8 对比：满血 bf16 25.8 vs 7900 → **~307×**（原报 306×，基本不变）；改用 FP4 120.5 去比则 **~66×**。

### 给用户的答复（设计文档中的位置：补充03 §3 三层控制栈 + 补充04 §3 角色卡）

**① 新画风 —— 先分同域/跨域，两条路都不是"训 LoRA"**
- **同域风格**（赛璐璐/厚涂/水彩/某画师笔触，都还在二次元内）→ **L1 主干内生条件轴，推理时改一个数值，零训练**。先例：PARASOL（CVPRW 2024）、Stylistic Attribute Control in LDM（arXiv 2605.02583，从合成数据学解耦且连续可调的风格方向）。
- **跨域（二次元→写实）**→ 首选**主干内生 domain 条件向量**（补充04 §4.2，**必须在预训练阶段就做**，事后补不了）；事后只能上 **∥-Pack 并联包**（体量大两个数量级、需重训）。
- **L1 需要的数据 = shader 配对**（同一 3D 场景 × 不同着色器 → 几何/光照/姿态完全一致、只有风格不同），真实世界爬不到，渲染器免费生产。

**② 新角色 —— 角色卡（Character Carrier），不是 LoRA**
- 三段式：① **Character Fitter 训一次（一辈子一次）** ② **换角色 = 给正/反两图 → Fitter 前向一次 → 角色卡，秒级** ③ 想要极致再叠子空间约束 Δ-Pack。
- 关键：**梯度不再落到底模权重，而落到一个几 MB 数据对象上** → 不打架、跨版本可迁移、秒级。体积 ≈1–5MB vs 全层 rank-16 LoRA 27MB。
- 表征用 **2.5D 分层**（See-through 19 类语义 RGBA 层 + 伪深度），**不反解 3D 网格**。
- 「正+反对二次元是强约束」的三条理由已在补充04 §3.1。

**③ LoRA 还剩什么**：只在第三层，做同域长尾（1%）；规格升级 = 块对角分解（有效秩 r→n_l×r 而参数量不变）+ rsLoRA 缩放 + 按 GID 分层 + `W_o` 优先。硬约束「禁止入侵维度」：必须在 W₀ 的 SVD 子空间内构造 + 训练后谱检查。

**④ 诚实交代**：这些都还是**设计稿，0 行代码**，现在用不上。落地顺序 P1.5 能力总线 → **P2.6 角色卡数据线（第二个可立刻开跑的部分）** → P2 换主干（决定"写实"能否当旋钮）→ P4.5 正交化仲裁。短期最实际的是**先把角色卡格式定下来**。

### E5 前哨 · 信号级结论（已完成）

**误差归因表（真实 Sana 1.6B，15 例平均）**

| 配置 | 权重 | 激活 | 相对误差 | 余弦 |
|---|---|---|---|---|
| **W4A4**（官方默认） | NVFP4 | NVFP4 | **29.72%** | 0.9542 |
| W4A4 + 4/6 + MSE 校准 | NVFP4 | NVFP4 | 29.57% | 0.9552 |
| **W4A8**（= 设计档） | NVFP4 | **FP8** | **9.98%** | 0.9947 |
| **W4A16** | NVFP4 | bf16 | **7.74%** | 0.9968 |

- ⭐ **误差几乎全部来自激活量化**：权重降到 4bit 只花 7.74%；再把激活也降到 4bit → 暴涨到 29.72%（**3.84×**）。**这是"FP4 权重 + FP8 激活"这个档位的实测依据。**
- **平均相对误差随 timestep 呈倒 U**：t=999 时 W4A4 仅 19.5%，**t=500 冲到 35.4%** → 中间步（定结构的那几步）最脆弱。
- **4/6 配比 + MSE 校准几乎无效**（29.72%→29.57%，仅 0.5%），代价是校准 **5.5s → 260.7s（47×）** → 可省。

**两条环境知识（新增）**
- ⚠️ **ModelOpt 的 NVFP4 fake-quant 完全忽略配置里的 block 长度**：同一真实权重、同一输入，block=16/32/64 三档输出**完全相同（差异 0.000000%）**。但**手写 NVFP4 量化**下 block16 稳定优于 32（低 9–25%）→ **说明 ModelOpt 内部用固定块长，官方配置写 32 不会带来额外损失**。
- ⚠️ **mtq.quantize 前必须先把模型 `.to("cuda")`**：校准循环喂 cuda 张量，权重还在 CPU 会报 `Input type (CUDABFloat16Type) and weight type (CPUBFloat16Type) should be the same`。（`e5_e2e.py` 已修）
- ✅ **FP8 模拟是生效的**（走 `_fp8_eager` 纯 PyTorch 回退路径，nvcc 警告只是说 CUDA 加速扩展没编译）；单层干净对照两次独立测量几乎完全一致（W4A4 13.965% vs 早先 13.99%；W4A16 10.254% vs 10.21%）→ **方法学可靠**。

### ⭐⭐ 本轮最重要的方法论发现：**PSNR/SSIM 不是画质，是「轨迹稳定性」**

**看图后推翻字面结论**：W4A4 那张 9.67 dB 的图**画质完全正常**，只是**换了个构图**（猫咪从坐着变站着、背景从虚化墙角变成窗外散景）。bf16 / W4A16 / W4A8 三张构图基本一致，W4A4 明显漂移。
→ **扩散模型 20 步采样对轨迹扰动敏感**：早期步（我们在 t≈500 测到 W4A4 误差 35%）的微小偏差会被放大成**另一个合理样本**，而不是"质量下降"。
→ **结论：固定种子的逐像素 PSNR/SSIM 只能判「轨迹稳定性」，不能判「画质」。** G1 的真判据必须换成 **分布级指标（FID / 多样本质量评估）或人工/视觉判断**，逐像素对照只能作为辅助。

### ⚠️ 另一个必须记住的边界：fake-quant 不省显存

四路（含 W4A4）峰值显存**全部是 5.29 GB，与 bf16 完全相同**。原因：ModelOpt 的 PTQ 是**模拟量化（fake-quant）**，权重仍以 bf16 驻留，只是前向时量化-反量化。
→ **本轮的显存数字不能用来论证 NVFP4 的显存收益**；真实收益要等**打包权重（packed NVFP4）**落地后再测。这一点必须写进 G1 报告，否则会被误读。
